# 청크 메타데이터 형식 (WBS M2-1-3)

> 청크와 문서에 붙는 정보, DB 표, 열람 권한, 버전 전환, 검색 결과 형식.
> A(DB)·C(검색)·D(AI 판단·정보 보호)가 같이 지키는 약속이라 바꿀 때는 같이 정한다.
> 청크를 나누는 규칙은 [청크_규칙.md](청크_규칙.md). 코드: [`chunker.py`](chunker.py)

## 1. 한눈에

- 설계서 7.3의 최소 항목을 **문서 단위**(가이드·가이드 버전 표)와 **청크 단위**(청크 표)로 나눠 채운다.
- 검색 때 거르는 값(열람 등급·분류·문서 종류·활성 여부)은 청크 표에도 복사한다. 벡터 검색 한 번에 권한 필터를 걸기 위해서다.
- **외부 전송 정책은 열람 등급으로 추론하지 않는다.** 등록할 때 명시한 값만 쓰고, 없으면 `unconfirmed`(허용 안 함)다.
- 팀·긴급도·시나리오·FAQ 칸에는 DB 코드 표(`teams`·`urgency_levels`·`scenarios`·`faqs`)에 있는 값만 들어간다.

| 설계서 7.3 최소 항목 | 필드 |
|---|---|
| 문서·Chunk ID | `doc_no` · `chunk_id` · `unit_id` |
| 문서 버전·활성 여부 | `version` · `is_active` (`status`) |
| 카테고리·제목·소제목 | `category` · `title` · `heading_path` · `subheadings` |
| 열람 범위·보안 등급 | `access_level` · `audience` |
| 외부 전송 정책 | `external_send` |
| 페이지·슬라이드·절 위치 | `page_start` · `page_end` · `section_no` |
| 본문·Embedding | `text` · `body` · `guide_chunk_embeddings.embedding` |

## 2. 문서 정보 `document_record(doc, source_path, registration)`

키는 `.md` 머리말·`manifest.json`과 같다. `registration`은 등록 입력(`manifest.json` 한 행 또는 `POST /guides` 본문)이다. 외부 전송 정책과 검색 대상 여부는 문서 내용이 아니라 **등록 때 정하는 값**이라 여기서만 받는다.

| 필드 | 예 | 설명 |
|---|---|---|
| `doc_no` | `IT-SW-002` | 문서 번호 |
| `title` · `category` · `doc_type` | `SW 라이선스 신청·인증 가이드` · `SW` · `guide` | 분류는 7개 + 공통 `STD`. 종류는 `guide`(가이드)·`manual`(매뉴얼)·`standard`·`policy` |
| `version` · `effective_date` | `v2.0` · `2026-10-16` | 활성 여부는 적재 뒤 활성화 함수가 정한다 (7장) |
| `access_level` · `audience` | `사내 일반`/`사내 제한` · `전 임직원` | 열람 등급 (4장) |
| `external_send` | `allow` · `deny` · `unconfirmed` | 외부 모델 전송 정책 (3장) |
| `rag_target` | `True` | 검색 대상 여부 (등록 입력. `IT-AI-001`은 false) |
| `owner` · `pair` | `서비스데스크` · `IT-SW-002-M` | 관리 부서 · 짝 문서 |
| `scenarios` · `faqs` · `keywords` | `['SW-02']` · `['FAQ-023']` · `[…]` | DB `scenarios`·`faqs`와 연결. `keywords`는 동의어·화면 메시지 |
| `source_path` · `source_format` | 원문 위치 · `md` | |
| `parse_mode` · `parse_coverage` | `layout`/`safe` · `1.0` | 파싱 품질 (보수 모드 문서는 구조가 약하다) |
| `parser_version` · `chunker_version` | `1.0` · `1.0` | 어떤 규칙으로 만든 청크인지 |

## 3. 외부 전송 정책

설계서 7장 "외부 전송 정책이 없거나 불명확한 정보는 전송하지 않는다"와 IT-STD-002 "외부 모델 전송 허용 여부는 열람 등급과 따로 정합니다"를 따른다.

- 열람 등급에서 자동으로 정하지 않는다. 등록 입력에 명시된 값만 쓰고, 없거나 모르는 값이면 `unconfirmed`다.
- `unconfirmed`는 허용으로 보지 않는다.
- 정리본 57종의 값은 정보 보호 담당(D)이 승인한 뒤 `manifest.json`에 넣는다. **승인 전에는 모두 `unconfirmed`라서 외부 모델 답변 경로가 막힌다.**

| 문서 종류 | 제안 값 (D 승인 대기) | 이유 |
|---|---|---|
| 임직원용 가이드 27 · 공통 기준 2 | `allow` | 임직원에게 그대로 보여 주는 안내문이고 개인정보가 없다 |
| 담당자용 매뉴얼 27 | `deny` | 담당자 실명·내부 처리 절차가 들어 있다 |
| AI 응대 정책 1 (`IT-AI-001`) | `deny` | 검색 대상이 아니다 (`rag_target=false`) |

매뉴얼의 담당자 실명은 가상 데이터라 마스킹하지 않는다. 열람은 4장 권한으로, 외부 전송은 `deny`로 막는다. 실제 문서를 업로드할 때는 이 결정을 그대로 쓰지 않고 다시 정한다.

## 4. 열람 권한

| 열람 등급 | 볼 수 있는 사람 (DB `user_roles`) |
|---|---|
| 사내 일반 | 활성 상태 사용자 전원 |
| 사내 제한 | `IT 운영 담당자` · `관리자` (`일반 임직원`은 못 본다) |

열람 권한이 없는 청크는 검색 결과·답변·출처 어디에도 나오지 않는다. 검색 단계에서 거른다 (8장).

## 6. DB 표 (A의 Alembic 마이그레이션 기준)

설계서 8.1의 Guide · Guide 버전·정책 정보 · GuideChunk를 따르고, 임베딩은 모델 비교(M3-2-1) 동안 모델별로 따로 둔다.

```sql
create table guides (
    doc_no    text primary key,                 -- IT-SW-002
    title     text not null,
    category  text not null,                    -- ACC·ACS·NET·SW·HW·SYS·SEC·STD (STD는 categories 표에 없음 → FK 안 검)
    doc_type  text not null,                    -- guide · manual · standard · policy
    pair      text,
    owner     text
);

create table guide_versions (
    id               bigserial primary key,
    doc_no           text not null references guides (doc_no),
    version          text not null,
    effective_date   date,
    status           text not null default 'loading' check (status in ('loading', 'ready', 'failed')),
    is_active        boolean not null default false,       -- 활성화 함수만 바꾼다
    access_level     text not null,
    audience         text,
    external_send    text not null default 'unconfirmed' check (external_send in ('allow', 'deny', 'unconfirmed')),
    rag_target       boolean not null default true,
    scenarios        text[] not null default '{}',
    faqs             text[] not null default '{}',
    keywords         text[] not null default '{}',
    source_path      text not null,
    source_format    text not null,
    parse_mode       text,
    parse_coverage   real,
    parser_version   text not null,
    chunker_version  text not null,
    loaded_at        timestamp not null default now(),
    unique (doc_no, version),
    check (not is_active or (status = 'ready' and rag_target))
);
create unique index guide_versions_one_active on guide_versions (doc_no) where is_active;

create table guide_chunks (
    chunk_id          text primary key,
    version_id        bigint not null references guide_versions (id) on delete cascade,
    unit_id           text not null,
    seq               integer not null,
    chunk_type        text not null,
    section_no        text,
    heading_path      text[] not null,
    subheadings       text[] not null default '{}',
    part              integer not null default 1,
    parts             integer not null default 1,
    page_start        integer,
    page_end          integer,
    body              text not null,
    text              text not null,
    char_count        integer not null,
    props             jsonb not null default '{}',
    scenario_ids      text[] not null default '{}',
    faq_ids           text[] not null default '{}',
    handling          text,
    team              text references teams (name),
    escalation_teams  text[] not null default '{}',
    urgency           text references urgency_levels (code),
    images            text[] not null default '{}',
    -- 필터용 복사 (category·doc_type 원본 guides, access_level·is_active 원본 guide_versions)
    category          text not null,
    doc_type          text not null,
    access_level      text not null,
    is_active         boolean not null default false,
    content_hash      text not null,
    embed_hash        text not null,
    unique (version_id, seq),
    check (part between 1 and parts)
);
create index on guide_chunks (unit_id);
create index on guide_chunks (content_hash);

create table guide_chunk_embeddings (
    chunk_id    text not null references guide_chunks (chunk_id) on delete cascade,
    model       text not null,                 -- '이름@리비전' 예: kure-v1@<HF commit>
    embed_hash  text not null,                 -- 만들 때의 guide_chunks.embed_hash
    embedding   vector(1024) not null,         -- KURE-v1·BGE-M3 둘 다 1024차원
    created_at  timestamp not null default now(),
    primary key (chunk_id, model)
);
-- 모델마다 부분 HNSW 인덱스. 차원이 같아도 서로 다른 모델의 벡터를 섞어 검색하지 않는다
-- create index on guide_chunk_embeddings using hnsw (embedding vector_cosine_ops) where model = 'kure-v1@…';
```

## 7. 적재·버전 전환 (M2-2-1 적재 스크립트 · A 활성화 함수)

**준비 → 검증 → 짧은 트랜잭션으로 교체**. 준비나 검증에서 실패하면 DB에 손대지 않는다.

1. **준비** (DB 밖): 파싱 → 청크 → 선택 모델로 임베딩한다. 이미 있는 청크 중 `embed_hash`와 `model`이 같은 것은 기존 벡터를 다시 쓴다.
2. **검증**: 아래를 모두 통과해야 다음 단계로 간다.
   - 파서 경고 0건, `validate(chunks) == []` (조각 번호, 3.x 항목 4,500자 이하)
   - 정리본이면 문서별 청크·항목·단위 수가 [`chunk_baseline.json`](chunk_baseline.json)과 같음. 새 문서는 담당자 확인
   - 모든 청크에 선택 모델의 임베딩이 있고 `embedding.embed_hash = chunk.embed_hash`
   - `rag_target=false` 문서는 적재 대상에서 뺀다
3. **교체**
   - 새 버전: `status='loading', is_active=false`로 넣는다. 활성화 함수(A)가 한 트랜잭션에서 이전 버전과 그 청크를 `false`로, 새 버전과 그 청크를 `true`·`status='ready'`로 바꾼다.
   - 같은 버전을 다시 적재 (파서·청커 수정 뒤): 한 트랜잭션에서 그 버전의 청크를 `chunk_id`로 upsert하고, 이번 결과에 없는 `chunk_id`는 지우고, 임베딩을 넣는다.

`is_active`는 활성화 함수 하나만 바꾼다. 청크 표의 복사본도 같은 트랜잭션에서 바꾼다. 새 버전을 등록하거나 문서를 비활성화하면 이전 문서가 검색에 쓰이지 않는다 (설계서 7장).

## 8. 검색 결과 형식 (M3-1-1, C → D)

검색 API는 아래 순서로 처리한다.

1. **벡터 검색**: 선택 모델 하나의 임베딩으로, 청크 복사본(`is_active`, 사용자 권한에 맞는 `access_level`, 필요하면 `category`)으로 걸러 k × 3개 청크를 뽑는다. 분류로 거를 때도 공통 기준 `STD`는 함께 넣는다.
2. **원본 재확인**: `guide_versions`·`guides`와 조인해 활성·열람 등급을 다시 확인한다. 어긋나는 것은 버린다.
3. **단위 복원**: `item`·`faq`·`preface`는 같은 `unit_id`의 조각을 모두 `part` 순서로 붙인다 (지금 항목은 최대 3조각). `chapter`는 맞은 조각과 그 앞뒤 조각만 붙인다 (장은 최대 7조각, 6,557자라 통째로 넣지 않는다).
4. **중복 묶기**: `content_hash`와 `external_send`가 둘 다 같은 단위만 하나로 묶는다. 대표는 문의 분류와 같은 문서 → 공통 문서(IT-STD) → 점수 순으로 고른다. 나머지 출처는 `also_in`에 남긴다.
5. **개수 맞추기**: 단위가 k개보다 적으면 k × 6개로 한 번 더 뽑고, 그래도 모자라면 있는 만큼 돌려준다.

결과 하나 = 단위 하나:

```json
{
  "unit_id": "IT-SW-003@v2.0§item:3.1",
  "chunk_type": "item",
  "doc_no": "IT-SW-003", "title": "업무용 SW 실행·오류 대응 가이드", "version": "v2.0",
  "section_no": "3.1", "heading_path": ["3. 증상별 조치 방법", "3.1 프로그램이 멈추거나 바로 꺼질 때 (기본 조치)"],
  "page_start": null, "page_end": null,
  "text": "조각을 part 순서로 붙인 글",
  "chunks": [{"chunk_id": "IT-SW-003@v2.0#004", "part": 1, "score": null},
             {"chunk_id": "IT-SW-003@v2.0#005", "part": 2, "score": 0.71},
             {"chunk_id": "IT-SW-003@v2.0#006", "part": 3, "score": null}],
  "matched_chunk_ids": ["IT-SW-003@v2.0#005"],
  "unit_score": 0.71,
  "score_type": "cosine:kure-v1@…",
  "scenario_ids": ["SW-03"], "handling": "사용자 직접 조치", "team": "서비스데스크", "escalation_teams": [], "urgency": "",
  "access_level": "사내 일반",
  "external_send": "allow",
  "also_in": []
}
```

- `unit_score`는 그 단위에서 실제로 맞은 조각 점수 중 가장 높은 값이다. 붙이기만 한 조각의 `score`는 `null`이다.
- `access_level`·`external_send`는 원본 표와 조인한 값이다 (청크 복사본이 아님).
- D는 외부 모델을 부르기 직전에 `external_send`를 다시 확인한다. `allow`가 아닌 단위는 입력에서 뺀다. 근거가 남지 않으면 담당자 처리 경로로 보낸다 (설계서 7장).
- 답변의 출처는 `title` · `version` · `section_no` · `page_start`~`page_end`로 보여 준다 (설계서 7.5).

## 9. 나중에 정할 것

- 매뉴얼의 처리 방식(`props['처리 방식']`: `티켓`, `즉시 처리 후 필요 시 티켓` …)을 DB `handling_types`(티켓/즉시 처리)에 맞춰 정리할지 (D의 처리 방향 판단 방식에 따라)
- 가이드 처리 구분과 평가셋 `expected_action`(`ANSWER`·`ESCALATE` …)의 대응 (M2-2-2 평가 도구에서)
- 10.21 이후: BM25·`keywords` 같이 쓰기, 이미지를 문서 버전의 자산 ID로 관리하기
