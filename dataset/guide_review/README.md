# 가이드 검증 결과 (WBS D1~D6)

가이드 56종(`dataset/guides`의 검색 대상)을 DB에 넣기(M2-2-1) 전에 확인한 결과와, 검색 평가에 쓸 질문 228개입니다 (이 중 56개는 반말·무례 말투 묶음).

| 파일 | 내용 |
|---|---|
| `{분류}_검증시트.md` | 문서마다 자동 대조 결과와 검색 단위(항목 3.x · 장 · FAQ) 목록, 단위마다 확인 표시 |
| `{분류}_질문.csv` | 문서마다 검색 질문 3개 이상과 정답 단위 (`IT-ACC-001/item:3.2` 형식) |

분류는 ACC · ACS · HW · SW · NET · SYS · SEC · STD 8개입니다. 만드는 도구와 명령은 [`backend/app/rag/review/README.md`](../../backend/app/rag/review/README.md)에 있습니다.

## 왜 필요한가

- **적재 전 확인**: 틀린 파싱·잘못 나뉜 단위·틀린 열람 등급이 DB에 들어가면 검색과 권한 필터가 그 값을 그대로 씁니다. WBS는 가이드 검증(D1~D6)을 적재(M2-2-1)의 선행 작업으로 둡니다.
- **검색 시험지**: 질문은 평가 도구(M2-2-2)에서 검색 적중률(Hit@k · MRR)을 잴 때 씁니다. 평가셋(`dataset/data/eval_inquiries.csv`, 50건)은 실제 문의 말투로 AI 전체를 채점하고, 이 질문들은 **문서·단위마다 빠짐없이** 검색을 시험합니다. 임베딩 모델 비교(M3-2-1)에도 같은 질문을 씁니다.

WBS 완료 기준(문서마다): ① 파싱 결과 = 원문 ② 분류·열람 권한 확인 ③ 검색 질문 3개와 정답 근거.

질문 작성 규칙: 직원·담당자가 실제로 칠 법한 말투(반말 묶음은 욕설·비하 없이 반말·명령조·줄임말), 문서 제목·본문 문장을 그대로 옮기지 않음, 평가셋 문장 금지, 오류 메시지 원문은 허용. `작성자` 칸에 누가 썼는지, `메모` 칸에 고친 이유가 있습니다.

### AI 1차 검수와 사람 검수 (2026-10-22~23)

사람이 228개를 다 보기 전에 AI가 문제 후보를 골랐습니다. 쓴 쪽과 엇갈려 봤습니다: Claude가 쓴 116개는 Codex가, Codex가 쓴 112개는 Claude 세션이 봤습니다. 후보 53개와 통과 표본 20개(고정 시드)를 사람이 결정했습니다.

- **후보 A 17개**: 문서에 근거가 없는 질문, 다른 단위와 정답이 겹치는 질문, 답(처리 절차)이 질문에 들어 있던 질문, 문서체 말투. 사람이 질문을 고치거나(`사람 검수 반영`) 정답을 추가했습니다. 다른 문서에 정답이 있는 3건은 `다른 문서 정답: <이유>`로 표시했습니다.
- **후보 B 36개 (쉬움)**: 단위 제목이나 예시 문장(문의이력의 실제 문장)을 거의 그대로 쓴 질문. 틀린 질문이 아니라 쉬운 시험이라 고치지 않고 `난이도: 쉬움`을 붙여 따로 집계합니다.
- **통과 표본 20개**: 19개 적절, 1개는 질문을 정답(접수 시 확인 질문)에 맞게 고침. AI가 놓친 비율 약 5%라 검수 범위를 넓히지 않았습니다.

## 이어서 작업할 때

**언제 고쳐야 하나**: 개발 기간에 우리가 가이드(`dataset/guides`)를 고칠 때만이다. 운영 중 관리자가 올리는 가이드는 적재 스크립트의 자동 검사(파서 경고·청크 검증·문의 유형 코드)를 거치고, 내용은 올리는 사람이 책임진다. 이 폴더는 우리 평가용 시험지라 업로드마다 고치는 대상이 아니다.

**자동 알림**: `tests/test_guide_questions.py`가 질문 파일마다 `check`와 같은 검사를 한다. 가이드를 고쳐 정답 단위가 사라지거나 문서마다 3개가 안 되면 `pytest`가 실패한다. 실패하면 해당 csv의 정답 단위를 검증 시트의 단위 칸에 맞춰 고친다.

- **질문 추가**: 언제든 됩니다. 같은 문서 번호로 줄을 추가하고(`번호` 4, 5 …) `check`로 오류 0 · 경고 0을 확인합니다. 단, 평가 결과를 비교할 때는 같은 시점의 질문 파일을 써야 합니다 (평가 도구가 커밋을 함께 기록).
- **가이드가 바뀌면**: 시트를 다시 만들어야 하는데 `--force`는 확인 표시와 `문제` 칸을 지웁니다. 바뀐 문서만 `--name`을 따로 줘서 새로 만든 뒤 비교하고, 기존 시트의 해당 문서 부분만 바꿉니다. 질문의 정답 단위가 사라졌으면 `check`가 오류로 알려 줍니다.
- 평가셋 문장은 질문에 쓰지 않습니다 (`dataset/README.md`).
