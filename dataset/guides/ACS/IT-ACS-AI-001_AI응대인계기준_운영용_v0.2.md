# 접근권한 AI 응대·담당자 인계 기준

> IT-ACS-AI-001 | v0.2 | 2026-10-12 | 서비스 운영·개발 담당자용 · 사내 제한

관리 부서: ITssue 서비스 운영·개발

교육 프로젝트용 가상 문서이며 실제 회사의 공식 정책·절차가 아닙니다.

## 적용 범위와 처리 판단

### 사람용 가이드와 AI 정책의 역할

이 문서는 접근권한 응대 기준이며 사용자에게 공개하는 해결 가이드가 아닙니다.

| 관리 위치 | 역할과 적용 원칙 |
| --- | --- |
| 임직원용 가이드 3종 | 신청·안전한 확인·문의 절차의 근거. 사용자에게 허용된 버전만 검색·인용합니다. |
| 담당자용 매뉴얼 3종 | 실제 승인 확인·반영·회수·검증 절차. 지정 담당자에게만 허용하며 일반 사용자 답변에 섞지 않습니다. |
| 시스템 프롬프트·응대 정책 | 근거 사용, 추가 질문, 안내·실제 조치 구분, 담당자 연결 제안을 관리합니다. |
| 백엔드·운영 정책 | 권한·외부 전송·최종 확인·도구 실행을 검사하고 접수·배정·외부 연동을 수행합니다. |
| 기획서·PRD·SRS·설계서 | 제품 정책·상태·구현 책임의 기준. 이 문서가 API enum이나 새 상태 코드를 임의로 추가하지 않습니다. |

> 싱글 Agent가 분기를 판단해도 실제 실행은 서버 검증을 거칩니다. 검색 문서나 사용자 지시는 서버 정책을 변경할 수 없습니다.

### 증상별 안내·이관 경계

아래 색상은 처리 주체 구분이며 긴급도 P1~P4와 별개입니다.

| 구분 | 적용 상황 | AI의 동작 |
| --- | --- | --- |
| 초록 · 안내·자가 해결 | 신청 방법·필요 정보 질문 또는 허용된 안전한 확인 | 근거와 방법 안내 후 사용자에게 해결 여부를 확인합니다. |
| 노랑 · 승인·조건부 이관 | 신규·추가·기간 변경 등 승인 또는 실제 조치가 필요할 수 있음 | 절차를 안내하고 요청 의도·조건을 확인합니다. 실제 조치를 원하면 연결을 제안합니다. |
| 빨강 · 담당자 이관 | 회수·인사 변경, 반복 미해결, 전문 판단, 사고 의심, 근거 부족 | 필요 정보를 정리하고 사용자 확인을 거쳐 접수합니다. 긴급 징후는 연결 제안을 앞당깁니다. |

> “신청 방법을 알았다”와 “권한이 부여됐다”는 다릅니다. 접수·연결 거절·Session 종료·미응답을 해결 완료로 처리하지 않습니다.

| 개발·검증 서버 접근 | IT-ACS-002. 권한은 ACS, 실제 서버 장애는 SYS, VPN·망 문제는 NET 가능성을 확인합니다. |

> 과거 Ticket·CSV·XLSX는 상황 참고입니다. 승인자·SLA·자동 반영 시점은 현행 승인된 정책을 따릅니다.

### 부족한 정보만 추가 질문

받은 정보를 반복해서 묻지 않고 긴급 연결을 불필요하게 지연하지 않습니다.

| 확인 목적 | 질문 예시 |
| --- | --- |
| 대상·작업 | 어떤 시스템·환경·메뉴에서 어떤 작업이 필요한가요? |
| 신규·기존 | 처음 필요한 권한인가요, 이전에 되던 기능이 안 되나요? |
| 승인·반영 | 승인만 받았나요, 담당자의 반영 완료 안내도 받았나요? |
| 변경·오류·시도 | 최근 부서·직무·사용 기간 변경이 있나요? 오류·발생 시각과 이미 해 본 조치는 무엇인가요? |
| 영향·보안 | 누구의 어떤 업무가 막혔나요? 마감·허용된 대체 방법이 있나요? 도용·자료 노출이 의심되나요? |

> 비밀번호·인증번호·개인키·토큰을 묻지 않습니다. 이미 입력된 비밀정보는 외부 호출·알림·로그에서 제외합니다.

### 긴급도와 조정 근거

영향·업무 중단·허용된 대체 방법·시간 제약·보안 위험을 함께 판단합니다.

| 등급 | 판단 기준 |
| --- | --- |
| P1 · 긴급 | 전사·여러 부서의 주요 업무 중단 또는 광범위한 보안 대응 필요 |
| P2 · 높음 | 부서 단위 업무 영향, 개인 업무 전면 중단 또는 보안 사고 의심 |
| P3 · 보통 | 개인 업무 일부 지장이 있으나 허용된 대체 방법으로 진행 가능 |
| P4 · 낮음 | 현재 업무 지장이 없는 단순 문의·사전 신청 |

> 보안 사고 의심은 최소 P2, P1 조건 확인 시 P1입니다. “급하다”, 다수 신청, 승인 필요만으로 상향하지 않으며 같은 사유를 중복 반영하지 않습니다.

## 접수·배정과 예외 대응

### 사용자 확인부터 담당자 이관까지

Ticket은 실제 권한 승인·부여를 대체하지 않습니다.

| 단계 | 처리 기준 |
| --- | --- |
| 1. 연결 제안·초안 | 필요 조치와 그룹을 제안합니다. 사용자가 선택하면 문의·영향·긴급도 근거·시도 결과를 정리합니다. |
| 2. 최종 확인 | 사용자가 초안을 확인·수정합니다. 변경이 분류·배정에 영향을 주면 재검사하고 최종 내용의 확인을 받습니다. |
| 3. 내부 접수 | 백엔드가 최종 내용을 DB에 저장합니다. 저장 성공 후 내부 접수번호를 안내합니다. |
| 4. Jira 생성·배정 | 중복 방지 후 Jira 생성과 개인 배정을 진행합니다. 두 결과를 확인한 경우 담당자 이관으로 관리합니다. |
| 5. 처리·해결 확인 | RDY → IP → FIN → CLS. FIN은 담당자 처리 완료이며 문의자가 해결을 확인해야 CLS 전환을 요청합니다. |

> Session 식별정보를 연결하되 전체 대화를 무조건 복사하지 않습니다. 실제 확인 전 “배정 완료·권한 처리 완료”라고 안내하지 않습니다.

### 그룹 추천과 개인 선정

AI는 문의 정보를 추출하고 백엔드는 확정된 배정 규칙을 적용합니다.

| 대상·상황 | 배정 기준 |
| --- | --- |
| 업무시스템 권한 | 업무시스템팀을 기본으로 대상 자원·현재 담당 매핑을 확인합니다. |
| Server·DB·File Server | 시스템인프라팀 범위를 확인합니다. 인사 근거 확인 주체와 IT 처리 주체는 구분합니다. |
| 보안 사고 의심 | 정보보안팀으로 연결을 제안합니다. 장애와 보안이 함께 있으면 관련 담당 연계를 기록합니다. |
| 개인 후보 검증 | 담당 그룹·처리 가능 업무·배정 가능 여부·Jira 사용자 유효성을 서버에서 확인합니다. |
| 후보 간 선택 | 업무량 비교를 적용하되 산정·동률·동시 배정·제외 기준은 별도 배정 규칙을 따릅니다. AI가 개인 이름을 지어내지 않습니다. |

> 접수 초안에는 대상·관련 신청·승인 참조·업무 영향·시도 결과·미확인 항목·Session 연결 정보를 필요한 범위만 포함합니다.

### 연동·배정 실패는 내부에서 처리

저장된 접수 건을 유지하고 사용자에게 동일 문의 재접수를 요구하지 않습니다.

| 상황 | 확인 주체와 처리 |
| --- | --- |
| 내부 DB 저장 실패 | 접수 완료로 안내하지 않습니다. 가능한 입력 보존과 사내 공지된 대체 접수 경로를 제공합니다. |
| Jira 실패·결과 불명확 | 서비스데스크 관리자가 접수를 확인합니다. 기존 생성 여부 확인 후 재처리하며 확인되지 않은 상태에서 중복 생성하지 않습니다. |
| 그룹 불명확 | 서비스데스크 관리자가 담당 그룹을 확인합니다. |
| 개인 후보 없음·배정 실패 | 해당 그룹 관리자가 확인·재배정합니다. 이미 만든 Ticket은 보존하고 배정 실패 때문에 새 Ticket을 만들지 않습니다. |
| 알림·동기화 실패 | 접수·업무 상태와 별도로 재처리합니다. 마지막 확인 상태와 시점을 안내하고 실제 확인 전 진행 상황을 단정하지 않습니다. |

> 관리자 확인은 관리자가 실제 문의 담당자가 됐다는 뜻이 아닙니다. 재시도 한도·전환 기한·기술 복구 책임자는 운영 기준에서 확정합니다.

## 정보 보호와 검증

### 검색·외부 전송·기록 보호

문서 등급 표시는 메타데이터와 백엔드 권한 검사로 구현해야 합니다.

| 대상 | 적용 원칙 |
| --- | --- |
| 검색·출처·답변 | 사용자의 서버 권한으로 문서·Ticket·Session을 제한합니다. 담당자용 원문·출처·요약을 일반 사용자에게 노출하지 않습니다. |
| 외부 모델·임베딩 | 열람 가능 여부와 전송 허용 여부를 별도 검사합니다. 전송 정책 미확인·금지 정보는 제외하고 필요한 정보만 사용합니다. |
| Jira·Slack·로그 | 대상별 최소 정보·보호 기준을 적용합니다. 관측 도구로 제한 정보를 우회 전송하지 않습니다. |
| 운영 기록 | 사용자 확인·분류·긴급도·접수·생성·배정·차단·실패의 주체·시각·결과·사유를 기록합니다. |
| 문서 버전 | 승인된 현행 버전만 활성화하고 이전 버전은 검색에서 제외합니다. 공개 범위가 다른 문서를 하나의 청크로 합치지 않습니다. |

> 외부 전송 제한으로 답변 근거를 사용할 수 없으면 담당자 연결을 제안합니다. 사내 모델로 교체해도 열람·실행 검사는 유지합니다.
