## 1. 개요

#### 목적

IT-ACS-001로 들어오는 시스템·공유폴더 권한 요청(신규·추가, 일괄 신청, 승인 후 접근 불가, 축소·회수)을 승인 확인 → 반영 → 검증 순서로 같은 기준으로 처리한다.

#### 담당 범위

| 항목 | 내용 |
| --- | --- |
| 1차 처리 | 서비스데스크(L1): 신청 경로·승인 상태 안내, 계정 상태 확인 |
| 2차 이관 | 업무시스템팀(L2): 권한 반영·회수·검증 / 시스템인프라팀: 파일서버·공유 드라이브 측 설정 |
| 배정 기준 | ACS-01: 전자결재·권한 담당 (서준호, 신유나). 재배정은 업무시스템팀장이 승인 |
| 관련 시스템 | 권한관리 시스템, 그룹웨어 IT 요청·전자결재, 인사 시스템 |

## 2. 접수·분류 기준

임직원용 가이드의 항목별 기본값입니다. 긴급도 기준은 IT-STD-001 IT 서비스 운영 기준을 따릅니다.

| 번호 | 문의 유형 | 증상·요청 | 기본 긴급도 | 1차 처리 | 처리 방식 | 이관 대상 |
| --- | --- | --- | --- | --- | --- | --- |
| 3.1 | ACS-01 | 신규·추가 권한 반영 | P4 | 업무시스템팀 | 티켓 | 없음 |
| 3.2 | ACS-01 | 신규 입사자 일괄 신청 | P4 | 업무시스템팀 | 티켓 | 시스템인프라팀 (공유 드라이브 계정) |
| 3.3 | ACS-01 | 승인 후 접근 불가·기존 기능 막힘 | P4 | 서비스데스크 | 티켓 | 업무시스템팀 |
| 3.4 | ACS-01 | 정책에 따른 축소·회수, 임시·고권한 요청 | P4 | 업무시스템팀 | 티켓 | 정보보안팀 (보안 의심 시) |

#### 처리 방식

- 즉시 처리: 안내만으로 끝낸 건. 티켓 없이 상담 기록만 남긴다.
- 티켓: 담당자 조치가 필요한 건. 담당 팀에 배정하고 상태를 RDY → WIP → FIN → CLS 로 관리한다. FIN은 담당자 처리 완료, CLS는 문의자가 해결을 확인한 최종 종료다.

#### 긴급도 조정 조건

- ACS-01은 기본 P4다. 마감 등 당일 업무가 막히면 P3로 올린다 (INQ-2026-00153).
- "급하다", 다수 신청, 승인 필요만으로는 올리지 않는다.
- 무단 접근·자료 노출 의심은 최소 P2로 보고 정보보안팀에 넘긴다 (MAN-00 공통 규칙 6).

## 3. 증상별 처리 절차

### 3.1 신규·추가 권한 반영

**문의 유형** ACS-01 · **기본 긴급도** P4 · **1차 처리** 업무시스템팀 · **처리 방식** 티켓 · **이관 대상** 없음

**접수 시 확인 질문**

- 대상자·시스템·메뉴(폴더)·필요한 작업·기간은?
- 팀장 승인이 끝났나요? (신청번호)
- 처음 필요한 권한인가요, 쓰던 기능이 막힌 건가요?

**판단 기준**

- 승인 기록에서 승인자 적격성과 대상자·자원·기능·기간을 대조한다. 맞지 않으면 반영을 보류하고 보완을 요청한다.
- 기존 접근 장애면 3.3으로 전환한다. 동료 계정의 권한 전체를 복제하지 않는다.
- 업무 시스템은 업무시스템팀, File Server·공유폴더 중 서버 측 설정은 시스템인프라팀 범위를 확인한다.


#### 처리 절차

1. 전자결재 승인을 확인한다 (INQ-2026-00269, 00310).
2. 대상 계정과 현재 역할·그룹·직접 부여 권한을 조회한다.
3. 승인된 역할·그룹·기능만 반영한다.
4. 승인 내역과 실제 유효 권한을 대조해 과도한 권한이 없는지 확인한다.
5. 사용자에게 승인된 기능의 정상 동작 확인을 요청하고 FIN 처리한다.

#### 작업 기록 양식

| 기록 항목 | 적을 내용 |
| --- | --- |
| 요청·승인 연결 | 기존 신청번호, 승인 기록 참조, 요청자·대상자 |
| 변경 대상 | 시스템·메뉴·폴더, 현재 권한, 요청 권한, 적용 기간 |
| 결과와 증빙 | 변경 전후 설정, 수행 시각·처리자, 승인 대조 결과, 검증 결과 |
| 남은 작업 | 미완료 항목·사유·담당자·다음 안내 일정, 사용자 확인 결과 |

#### 처리 후 안내 문구

> 신청하신 권한을 반영했습니다. 본인 계정으로 신청한 메뉴를 사용해 보시고, 신청하지 않은 자료가 보이면 알려 주세요.

**재발 방지**

- 인사발령 시 권한 자동 갱신 요청 (문의이력)

**이관 시 전달 정보**

- 신청번호와 승인 기록
- 대상자·자원·기능·기간


### 3.2 신규 입사자 일괄 신청

**문의 유형** ACS-01 · **기본 긴급도** P4 · **1차 처리** 업무시스템팀 · **처리 방식** 티켓 · **이관 대상** 시스템인프라팀 (공유 드라이브 계정)

**접수 시 확인 질문**

- 대상자별 사번·입사일·계정 보유 여부는?
- 사람마다 필요한 자원·역할은?
- 팀장 승인이 있나요?

**판단 기준**

- 대상자별로 승인과 처리 결과를 구분한다. 계정 생성과 접근권한 부여 결과를 나누어 기록한다.
- 계정이 없으면 계정 생성부터 확인한다.


#### 처리 절차

1. 입사자 명단과 인사 정보를 대조한다 (INQ-2026-00092, 00112, 00342).
2. 계정을 만들고 필요한 권한을 부여한다.
3. 임시 비밀번호는 본인의 등록 휴대폰 문자로만 보낸다 (IT-ACC-002-M). 명단·메일·메신저로 보내지 않는다.
4. 대상자별 처리 결과를 기록하고 FIN 처리한다.

#### 처리 후 안내 문구

> 신규 입사자 계정과 권한을 만들었습니다. 각자 등록 휴대폰으로 받은 임시 비밀번호로 처음 로그인한 뒤 새 비밀번호로 바꿔 주세요.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 대상자 목록
- 자원별 처리 결과


### 3.3 승인 후 접근 불가·기존 기능 막힘

**문의 유형** ACS-01 · **기본 긴급도** P4 · **1차 처리** 서비스데스크 · **처리 방식** 티켓 · **이관 대상** 업무시스템팀

**접수 시 확인 질문**

- 승인만 받았나요, 반영 완료 안내도 받았나요?
- 오류 문구와 처음 실패한 시각, 마지막 정상 시각은?
- 최근 직무·기간 변경이 있었나요?
- 다른 사람도 같은가요?

**판단 기준**

- 원인을 확인하기 전에 권한을 넓히거나 전체를 다시 설정하지 않는다.
- 여러 명이 동시에 안 되면 시스템 장애로 보고 연계한다.
- 승인하지 않은 자료 노출·도용 의심은 정보보안팀에 바로 넘긴다.
- 직무 변경 후 권한 미갱신이면 팀장 승인 확인 후 역할별로 바꾼다 (INQ-2026-00366).


#### 처리 절차

1. 신청·계정·환경을 대조한다 (다른 환경에 접속했다면 정확한 경로를 안내한다).
2. 그룹·역할·직접 권한·상속·만료를 확인하고 기존 승인 범위 안에서 고친다.
3. 인증·세션·VPN 조건을 확인한다. 이미 한 사용자 조치를 반복시키지 않는다.
4. 서비스 상태와 최근 변경을 확인하고 필요하면 시스템·네트워크 담당과 연계한다.
5. 사용자 확인 후 FIN 처리한다.

#### 처리 후 안내 문구

> 권한 그룹을 다시 지정해 정상으로 접근할 수 있습니다. 같은 증상이 다시 나오면 기존 신청번호로 알려 주세요.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 신청번호
- 오류·시각·영향
- 확인 결과


### 3.4 정책에 따른 축소·회수, 임시·고권한 요청

**문의 유형** ACS-01 · **기본 긴급도** P4 · **1차 처리** 업무시스템팀 · **처리 방식** 티켓 · **이관 대상** 정보보안팀 (보안 의심 시)

**접수 시 확인 질문**

- 정책 근거(공지·승인 문서번호)와 적용 범위·일시는?
- 임시 권한이면 시작·종료 시점과 회수 담당은?
- 고권한·타 부서·민감자료 요청인가요?

**판단 기준**

- 고권한·타 부서·민감자료는 자원 소유자의 추가 승인을 확인한다. 승인 경로가 없으면 부여하지 않는다.
- 임시 권한은 자동 만료를 쓸 수 있는지 확인하고, 없으면 회수 작업을 따로 등록한다.
- 회수한 권한의 복원은 승인 없이 하지 않는다.


#### 처리 절차

1. 근거·범위·일시를 대조한다.
2. 필요한 업무의 영향과 대체 방안을 확인한다.
3. 축소·회수 또는 부여를 반영하고 결과를 기록한다.
4. 일부 실패는 성공·실패 항목을 나누어 후속 조치를 남긴다.

#### 처리 후 안내 문구

> 보안 정책에 따라 권한을 조정했습니다. 업무에 필요한 기능이 정상인지 확인해 주세요.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 근거 문서
- 대상·범위
- 실패 항목


## 4. 대형 장애 대응

- 인사 발령 자동 반영이 여러 사람에게 한꺼번에 되지 않으면 개별 처리를 멈추고 대표 티켓 1건으로 묶어 업무시스템팀장에게 알린다.
- 권한관리 시스템·디렉터리 동기화 장애면 시스템인프라팀과 연계하고, 복구 후 반영 결과를 대상자별로 확인한다.
- 여러 사람이 동시에 같은 시스템에 접근하지 못하면 권한이 아니라 시스템 장애로 보고 IT-SYS-003-M을 따른다.
- 복구 후 연결된 티켓을 한꺼번에 종료하고(해결 방법: "MI-YYYY-NN 대형 장애 복구로 일괄 해결") 장애 보고서를 남긴다.

## 5. 처리 기록 기준

티켓을 종료(FIN)할 때 아래 항목을 남깁니다.

| 항목 | 적는 내용 |
| --- | --- |
| 요청·승인 연결 | 기존 신청번호, 승인 기록 참조, 요청자·대상자 |
| 변경 대상 | 시스템·메뉴·폴더, 현재 권한, 요청 권한, 적용 기간 |
| 결과와 증빙 | 변경 전후 설정, 수행 시각·처리자, 승인 대조 결과, 검증 결과 |
| 남은 작업 | 미완료 항목·사유·담당자·다음 안내 일정, 사용자 확인 결과 |
| 가이드 반영 | 임직원용 가이드에 추가·수정이 필요한지 (필요 / 불필요) |
