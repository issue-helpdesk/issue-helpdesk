# 사내 시스템 접근권한 처리 매뉴얼

> IT-ACS-001-OPS | v0.1 | 2026-10-12 | IT 담당자용 · 사내 제한

관리 부서: 업무시스템팀 · 시스템인프라팀

교육 프로젝트용 가상 문서이며 실제 회사의 공식 정책·절차가 아닙니다.

## 접수와 승인 확인

### 담당 범위와 착수 조건

대상 시스템의 실제 작업 권한을 가진 담당자만 변경을 수행합니다.

| 확인 항목 | 처리 기준 |
| --- | --- |
| 업무 시스템 / 공유폴더 | ERP·전자결재 등은 업무시스템팀, File Server·공유폴더는 시스템인프라팀 범위를 확인합니다. |
| 요청자와 권한 대상자 | 본인 요청인지 대리·일괄 신청인지 구분하고 대상자 식별정보·재직 상태·업무 관계를 확인합니다. |
| 신규 / 변경 / 기존 장애 | 신규 기능 필요와 기존 접근 장애를 구분합니다. 기존 신청이 있으면 연결하고 중복 작업을 막습니다. |
| 승인 근거 | 확인 가능한 승인 기록에서 승인자 적격성, 대상자·자원·기능·기간을 대조합니다. |
| 미확인·범위 불일치 | 승인 확인 전 변경을 보류하고 요청자 또는 자원 소유자에게 보완을 요청합니다. |

> 접수·담당자 배정은 권한 승인이 아닙니다. ITssue 관리자 역할만으로 실제 자원 변경 권한이 생기지 않습니다.

### 작업 기록 양식

확인되지 않은 값은 확인 필요로 남기고 사실처럼 채우지 않습니다.

| 기록 항목 | 기재 내용 |
| --- | --- |
| 요청·승인 연결 | 기존 신청번호, 승인 기록 참조, 요청자·대상자 |
| 변경 대상 | 시스템·메뉴·폴더, 현재 권한, 요청 권한, 적용 기간 |
| 작업 계획 | 적용할 역할·그룹·범위, 작업자, 적용 일시, 영향·복구 방법 |
| 결과와 증빙 | 변경 전후 설정, 수행 시각·처리자, 승인 대조 결과, 검증 결과 |
| 남은 작업 | 미완료 항목·사유·담당자·다음 안내 일정, 사용자 확인 결과 |

> 비밀번호·인증번호·키를 기록하지 않습니다. 설정 캡처와 승인 자료는 열람이 제한된 위치에 보관하고 참조만 남깁니다.

## 권한 반영과 검증

### 신규·추가·변경 처리

승인된 자원·기능·기간만 반영합니다.

**변경 전 대조**

대상 계정과 환경을 다시 확인하고 현재 역할·그룹·직접 부여·상속 권한을 조회합니다. 동료 계정의 전체 권한을 복제하지 않습니다.

**승인 범위 적용**

자원별 승인된 관리 절차로 필요한 역할·그룹·기능만 반영합니다. 변경 요청에 기존 권한 회수가 포함되면 별도로 확인합니다.

**결과 검증·사용 확인**

승인 내역과 실제 유효 권한을 대조하고 과도한 권한이 없는지 확인합니다. 사용자에게 승인된 기능의 정상 동작 확인을 요청합니다.

> 관리 콘솔 메뉴·API·명령은 해당 자원의 운영 절차를 따릅니다. 실제 제품이 미정인 상태에서 범용 명령으로 대체하지 않습니다.

### 일괄·임시·고권한 요청

일괄 신청도 대상자별 승인과 처리 결과를 구분합니다.

| 상황 | 담당자 처리 |
| --- | --- |
| 신규 입사자 일괄 신청 | 대상자별 계정 유무·자원·역할·승인을 대조합니다. 계정 생성과 접근권한 부여 결과를 분리 기록합니다. |
| 임시 권한·기간 연장 | 승인된 시작·종료 시점과 회수 담당을 확인합니다. 자동 만료 지원 여부를 확인하고 미지원이면 회수 작업을 등록합니다. |
| 고권한·타 부서·민감자료 | 자원 소유자와 추가 승인 필요 여부를 확인합니다. 승인 경로가 정해지지 않았으면 부여하지 않습니다. |
| 정책에 따른 축소·회수 | 확인된 정책 근거·적용 범위·일시를 대조합니다. 필요한 업무의 영향과 대체 방안을 확인하고 결과를 기록합니다. |

> 승인된 일정·범위를 임의로 확대하지 않습니다. 최대 사용 기간과 고정 처리 시간을 이 문서에서 새로 정하지 않습니다.

## 장애·예외 처리와 완료

### 승인 후에도 접근이 안 되는 경우

원인을 확인하기 전 권한 확대나 전체 재설정을 하지 않습니다.

| 점검 순서 | 확인 및 다음 조치 |
| --- | --- |
| 1. 신청·계정·환경 | 승인과 실제 반영, 대상 계정·자원·기간을 대조합니다. 다른 환경에 접속했다면 정확한 경로를 안내합니다. |
| 2. 유효 권한 | 그룹·역할·직접 권한·상속·제외 조건·만료를 확인합니다. 수정은 기존 승인 범위 안에서 수행합니다. |
| 3. 인증·세션·접속 조건 | 본인 계정과 로그인 상태, 필요한 VPN 조건을 확인합니다. 이미 수행한 사용자 조치를 반복시키지 않습니다. |
| 4. 서비스 장애 여부 | 다수 영향·최근 시스템 변경·서비스 상태를 확인하고 필요하면 시스템·네트워크 담당과 연계합니다. |
| 5. 보안 의심 | 승인하지 않은 자료 노출·도용은 정보보안팀에 즉시 연결하고 불필요한 추가 열람을 중단시킵니다. |

> 오류·발생 시각·마지막 정상 시각·업무 영향·마감과 확인 결과를 남깁니다. 사용자에게 권한 우회나 계정 대여를 요구하지 않습니다.

### 실패·부분 처리와 완료 기준

처리 실패를 정상 완료로 기록하지 않습니다.

**실패하면 범위부터 확인**

중복 실행 전에 실제 반영 여부를 조회합니다. 일부 반영은 성공·실패 항목을 분리하고 과도한 권한 노출 여부를 먼저 확인합니다.

**복구·후속 조치**

변경 전 상태와 승인 범위를 비교하여 허용된 복구 절차를 적용합니다. 회수한 권한의 복원은 보안 영향을 확인하고 승인 없이 수행하지 않습니다.

**완료 기록과 안내**

승인 대조·설정 검증·사용자 확인 결과를 기록합니다. 미완료 항목에는 담당자와 다음 안내 일정을 남기고 전체 완료로 안내하지 않습니다.
