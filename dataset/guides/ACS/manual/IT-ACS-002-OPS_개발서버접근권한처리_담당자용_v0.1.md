# 개발·검증 서버 접근권한 처리 매뉴얼

> IT-ACS-002-OPS | v0.1 | 2026-10-12 | IT 담당자용 · 사내 제한

관리 부서: 시스템인프라팀

교육 프로젝트용 가상 문서이며 실제 회사의 공식 정책·절차가 아닙니다.

## 자원과 승인 확인

### 신청 범위와 작업 주체 확인

서버·DB의 실제 관리 권한을 가진 담당자가 처리합니다.

| 확인 항목 | 처리 기준 |
| --- | --- |
| 자원 소유·환경 | 사내/고객사, 개발/검증/운영, 서버/DB, 프로젝트와 소유 조직을 대조합니다. |
| 대상 계정·업무 관계 | 대상자의 계정·소속·재직 상태와 해당 프로젝트의 업무 필요성을 확인합니다. |
| 승인·필요 작업 | 조회·실행·배포 등 승인된 역할·작업 범위·기간을 확인 가능한 승인 기록과 대조합니다. |
| 접속 수단 | 허용된 VPN·접속 경로·인증 수단·자원별 계정 등록 필요 여부를 확인합니다. |
| 일반 범위 밖 요청 | 운영·고객사·관리자 권한은 별도 승인 경로를 확인합니다. 경로 불명확 시 작업을 보류합니다. |

> 신청자에게 개인키·비밀번호·토큰을 요구하지 않습니다. 공개키 제출도 회사가 승인한 전달 경로와 대상자 확인을 거칩니다.

### 서버 권한 작업 기록 양식

호스트·네트워크 정보는 보호된 기록 위치에서만 관리합니다.

| 항목 | 기재 내용 |
| --- | --- |
| 요청·승인 | 신청번호, 대상자, 승인 기록 참조, 자원 소유자 |
| 환경·권한 | 환경·자원 식별자, 현재 역할·그룹과 승인된 변경 범위 |
| 기간·회수 | 승인 시작·종료 시점, 자동 만료 지원 여부, 회수 담당·확인 방법 |
| 적용·검증 | 작업자·시각, 변경 전후 상태, 접속·기능·과도 권한 검증 결과 |
| 예외·남은 작업 | 실패 범위·사유, 복구 결과, 연계 담당, 사용자 확인 결과 |

> 사용자에게는 접속에 필요한 최소한의 승인된 정보만 안내합니다. 관리자용 상세 설정·다른 계정 목록은 전달하지 않습니다.

## 등록·변경·만료 처리

### 신규 접근권한 반영

승인 확인 → 자원별 적용 → 접속·기능 검증 순서로 처리합니다.

**현재 상태와 변경 계획**

기존 계정·역할·인증 등록 상태를 조회합니다. 승인된 역할, 필요한 인증 등록, 적용·회수 일정과 복구 방법을 확인합니다.

**승인된 설정 적용**

자원별 운영 절차로 계정 등록·역할·그룹·인증 수단을 필요한 범위만 적용합니다. 일반 신청을 관리자 권한 부여로 대체하지 않습니다.

**유효 권한 검증**

승인 환경에서 접속과 허용 기능을 확인하고 과도한 권한이 없는지 대조합니다. 사용자 확인과 담당자 설정 확인을 모두 기록합니다.

> SSH·DB 제품과 접근제어 방식이 미정이므로 특정 계정 생성 명령, 포트, sudo 정책을 확정 절차로 제시하지 않습니다.

### 변경·연장·종료 관리

프로젝트 일정 변경은 기존 권한의 자동 연장을 의미하지 않습니다.

| 상황 | 처리 절차 |
| --- | --- |
| 역할·작업 범위 변경 | 현재·요청 권한의 차이를 확인하고 추가 승인 범위만 적용합니다. 불필요해진 기존 권한도 별도 확인합니다. |
| 기간 연장 | 승인 기록과 새 종료 시점을 대조하고 만료 설정·회수 예정 작업을 함께 갱신합니다. |
| 기간 종료·프로젝트 종료 | 승인된 회수 시점에 자원별 접근·인증 수단을 회수하고 실제 유효 접근이 남았는지 확인합니다. |
| 일부 회수 실패 | 미회수 자원·노출 범위·영향을 기록하고 담당자에게 후속 조치를 요청합니다. 침해 위험은 정보보안팀과 연계합니다. |

> 자동 만료가 없으면 회수 담당과 확인 작업을 명시합니다. 회수 완료 확인 전 전체 종료로 기록하지 않습니다.

## 접속 장애 진단과 결과 기록

### 접속 실패의 원인 구분

같은 오류에도 여러 원인이 있을 수 있으므로 확인 결과로 판단합니다.

| 증상 | 확인할 내용과 연계 |
| --- | --- |
| 인증 실패·접근 거부 | 계정·인증 등록·승인 역할·기간·자원 정책을 확인합니다. 권한 추가로 무조건 해결하지 않습니다. |
| 시간 초과·연결 거부 | VPN·경로·접속 대상·서비스 상태를 점검합니다. 네트워크팀 또는 서버 운영 담당과 연계합니다. |
| 접속은 되나 작업 실패 | 역할 범위와 서버·DB 상태를 구분합니다. 배포 실패·디스크 부족은 별도 운영 장애 절차로 처리합니다. |
| 다수 사용자 동시 영향 | 영향 범위·업무 중단·변경 이력을 수집하고 장애 담당과 연계합니다. 개인 권한 신청을 반복 생성하지 않습니다. |
| 무단 접근·키 노출 의심 | 추가 사용을 중단시키고 정보보안팀에 확인을 요청합니다. 증거는 승인된 보호 경로로 보존합니다. |

> 사용자에게 방화벽 해제·개인키 전송·서버 재시작을 요구하지 않습니다. 허용되지 않은 조치를 “대체 방법”으로 제시하지 않습니다.

### 실패 복구와 완료 확인

재실행 전에 실제 적용 여부와 보안 영향을 확인합니다.

**적용 결과 불명확**

관리 기록과 현재 설정을 조회해 반영 여부를 확인합니다. 계정·인증 정보의 중복 등록을 피하고 실패한 항목만 재처리합니다.

**복구와 작업 연계**

자원별 운영 절차와 승인 범위 안에서 복구합니다. 회수 복원·고권한 확대가 필요하면 별도 승인을 확인하고 후속 담당을 기록합니다.

**완료 조건**

허용된 환경·기능·기간이 승인과 일치하고 사용자 접속 확인이 끝났는지 확인합니다. 회수 건은 담당자가 잔존 접근을 확인합니다.
