# 퇴사·부서이동 권한 변경 처리 매뉴얼

> IT-ACS-003-OPS | v0.1 | 2026-10-12 | IT 담당자용 · 사내 제한

관리 부서: 업무시스템팀 · 자원별 담당

교육 프로젝트용 가상 문서이며 실제 회사의 공식 정책·절차가 아닙니다.

## 인사 근거와 작업 목록

### 착수 전 확인과 역할

인사 확인 주체와 실제 권한 처리 주체를 구분합니다.

| 확인 항목 | 처리 기준 |
| --- | --- |
| 인사 근거 | 인사 담당 부서가 확인한 대상자·변경 종류·적용 일시·변경 또는 취소 이력을 확인합니다. |
| 대상자와 자원 | 사번·계정·기존/새 부서·직무, 실제 사용 시스템·공유폴더·개발환경을 조회합니다. |
| 승인과 예외 | 유지·추가·자료 이관의 범위·기간·승인 근거를 확인합니다. 발령 기록만으로 모든 신규 권한을 부여하지 않습니다. |
| 처리 역할 | 인사는 사실·일시 확인, 자원 소유자는 업무 범위·인계 승인 확인, 자원 담당자는 반영·회수 검증을 수행합니다. |
| 부족한 근거 | 제3자의 주장만으로 차단·복원하지 않습니다. 실제 침해 의심은 인사 확인과 별도로 정보보안팀에 즉시 연결합니다. |

> 고정 퇴사 처리 시각·메일 전달 기간·휴직 정책은 임의로 정하지 않습니다. 확인된 인사 일시와 자원별 운영 기준을 따릅니다.

### 자원별 변경 작업표

다음 양식에 실제 대상 자원과 담당자를 한 줄씩 기록합니다.

| 항목 | 기재 내용 |
| --- | --- |
| 공통 식별 | 신청번호, 인사 기록 참조, 대상자, 적용 일시 |
| 자원과 현재 상태 | SSO·업무시스템·공유폴더·메일·개발환경 등 실제 자원, 현재 계정·권한 |
| 회수 / 유지 / 추가 / 인계 | 수행 작업, 승인 범위·기간, 담당자, 예정 시각 |
| 반영과 검증 | 실행 시각·처리자, 변경 전후 상태, 잔존 접근·인수자 사용 확인 |
| 미완료 관리 | 미완료 자원·사유·영향·담당자·다음 안내 일정 |

> SSO 비활성화만으로 개별 계정·세션·토큰·공유폴더 권한까지 모두 회수됐다고 판단하지 않습니다.

## 이동·퇴사 처리

### 부서이동: 기존 권한과 새 권한을 함께 처리

유지할 권한도 사유·기간·승인을 확인합니다.

**변경 전 자원별 분류**

기존 접근을 회수·유지 검토 대상으로, 새 업무 기능을 추가 대상으로 나눕니다. 겸무·인수인계는 승인된 예외 범위를 확인합니다.

**승인된 일정에 적용**

자원별 승인 범위에 따라 회수·추가를 처리합니다. 예정 순서가 업무 중단이나 과도 권한을 만들지 않는지 확인하고 조정이 필요하면 승인 주체와 협의합니다.

**새 기능과 회수 결과 검증**

사용자는 새 기능을 확인하고, 담당자는 기존 권한의 잔존 여부를 확인합니다. 일부 성공만으로 전체 변경을 완료 처리하지 않습니다.

> 새 부서 동료의 권한을 통째로 복제하지 않습니다. 기간 한정 유지 권한에는 종료 시 회수 확인 작업을 연결합니다.

### 퇴사: 접근 회수와 자료 인계를 분리

회수와 보존·인계 요구가 충돌하면 인사·자원 소유자에게 판단을 요청합니다.

**적용 시점과 인계 확인**

확인된 인사 일시, 자원별 회수 계획, 승인된 인수자·자료·보존 요구를 대조합니다. 자료 삭제를 기본값으로 하지 않습니다.

**자원별 접근 회수**

승인된 운영 절차로 계정 비활성화·역할 회수·인증 수단 정리를 수행합니다. 잔존 세션·토큰·개별 계정은 해당 자원의 지원 기능과 정책에 따라 처리합니다.

**회수·인계 검증**

담당자가 잔존 접근을 확인하고 지정 인수자가 승인 자료 사용을 확인합니다. 퇴사자 계정을 공유하거나 대신 로그인해 검증하지 않습니다.

> 일반 메일 자동 전달·계정 대여·외부 반출로 인계를 대체하지 않습니다. 메일·소유권·보존 처리는 별도 승인 범위를 확인합니다.

## 예외·누락 점검과 완료

### 일정 변경·미반영·회수 실패

같은 인사 변경 건과 연결하여 후속 작업을 관리합니다.

| 상황 | 처리 절차 |
| --- | --- |
| 일정 변경·취소 | 확인된 인사 기록으로 기존 예약·작업 목록을 대조합니다. 이미 반영된 권한은 자동 복원하지 말고 재승인 필요 여부를 확인합니다. |
| 휴직·복직·겸무 | 해당 인사 정책과 자원별 승인 범위를 확인합니다. 퇴사와 동일한 일괄 회수 또는 전체 복원을 가정하지 않습니다. |
| 새 폴더·메뉴 미노출 | 인사 반영·승인·계정·대상·실제 권한을 대조합니다. 장애가 원인이면 해당 기술 담당과 연계합니다. |
| 일부 회수 실패 | 실제 잔존 범위·위험·담당자를 기록하고 후속 조치를 요청합니다. 임의로 권한을 다시 열거나 실패 건을 누락하지 않습니다. |
| 퇴사 후 사용·정보 노출 | 정보보안팀에 즉시 연결합니다. 추가 열람·시험 로그인을 중단하고 이미 확보된 기록만 보호하여 전달합니다. |

> 회수 재시도 전 현재 상태를 확인합니다. 부분 처리·복구 실패는 전체 완료와 구분하여 관리합니다.
