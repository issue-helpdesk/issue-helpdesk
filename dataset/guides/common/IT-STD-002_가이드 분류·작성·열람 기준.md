## 1. 개요

**목적**

- 7개 분류 담당자가 따로 쓴 가이드를 하나의 체계로 정리한 기준과 결과를 남깁니다.
- 앞으로 가이드를 새로 쓰거나 고칠 때 같은 기준을 따르게 합니다.

**적용 대상**

- dataset/guides 의 모든 문서
- 가이드 작성·관리 담당자, 관리자, ITssue 운영·개발

**근거**

- docs 01 기획서 · 02 PRD · 03 SRS · 04 시스템 설계서 · 05 가상 기업 환경정의서
- dataset (taxonomy·FAQ·문의이력·MAN-00~07)


> ※ **기준이 서로 다르면 docs 01~05를 먼저 따르고, 그다음 데이터셋(FAQ·taxonomy)을 따릅니다. 팀원 문서끼리 다르면 데이터셋과 맞는 쪽을 씁니다.**

| PC에 설치한 메일 프로그램 오류 | SW-06 (IT-SW-003 3.7) | 메일 수신·용량·반송·메일 서버는 SYS (IT-SYS-004) |
| 메신저·화상회의 | SYS-10 (IT-SYS-005) | VPN 중에만 느리면 NET-02, 사무실 전체가 느리면 NET-04 |
| 프린터·복합기 | HW (IT-HW-003) |  |
| 공유 드라이브 "액세스 거부" | 팀 전체: SYS-13 (IT-SYS-006 3.1) | 혼자만: ACS-01 (IT-ACS-001 3.4), 부서 이동 뒤: ACS-02 (IT-ACS-003 3.2) |
| 개발 서버 SSH 실패 | 팀 전체·배포 중단: SYS-15 (IT-SYS-008 3.1) | 혼자만·권한: ACS-01 (IT-ACS-002 3.4) |
| 관리자 권한이 필요하다는 설치 | SW-01 (IT-SW-001) | 접근권한(ACS)이 아님. 관리자 권한은 주지 않음 |
| 부서 이동·퇴사 문의 | ACS-02 (IT-ACS-003) | "부서 이동", "퇴사", "발령"이 있으면 ACS-02, 새로 필요한 권한이면 ACS-01 |

| --- | --- | --- |

| 생성형 AI 사용 기준 | IT-SEC-004 3.4 | IT-SW-001 (원본 1장 6) 삭제, 대상 SW 표에서 참조), 미승인 도구 검토는 IT-SW-001 3.5 절차 |
| 통합 로그인 화면 반복·로딩 | IT-ACC-001 3.3 | IT-SW-003 3.8은 일반 사이트 화면 깨짐만 다룸 |
| 메일 | 서비스: IT-SYS-004 / PC 메일 프로그램: IT-SW-003 3.7 / 전사 장애: IT-SYS-003 3.3 | IT-SW-003 3.7 신규 작성 (원본에 없어 SYS-004의 참조가 빈 곳을 가리켰음) |

| 공유 드라이브 "액세스 거부" | 팀 전체: IT-SYS-006 3.1 / 개인: IT-ACS-001 3.4 / 부서 이동: IT-ACS-003 3.2 | 서로 참조를 항목 번호까지 연결 |

## 4. 열람 등급

| 등급 | 볼 수 있는 사람 | 대상 문서 |
| --- | --- | --- |
| 사내 일반 | 전 임직원 (ITssue 일반 임직원·IT 운영 담당자·관리자 모두) | 임직원용 가이드, 공통 기준 |
| 사내 제한 | IT 운영 담당자·관리자 (IT운영·보안 조직) | 담당자용 매뉴얼, AI 응대 정책 |

#### 사내 제한으로 두는 내용

- 담당자 실명과 배정 기준, 팀장 재배정 승인
- 본인 확인 수준(L1~L3)과 사회공학 대응 문구
- 관리 콘솔·내부 도구 절차 (잠금 해제, 원격 격리, 권한 반영·회수, 라이선스 할당 등)
- 긴급도 조정 조건과 판단 기준, 처리 후 안내 문구, 이관 시 전달 정보
- 팀별 내선 번호(1030·1040·1050·1060)와 내부 연락처

> ※ **애매하면 사내 일반으로 둡니다. 임직원이 알아야 할 절차·기준은 사내 일반 가이드에 쓰고, 담당자만 하는 작업만 매뉴얼로 나눕니다. SW 분류도 같은 이유로 담당자용 매뉴얼 3종(IT-SW-001-M~003-M)을 새로 만들었습니다.**

#### 등급 표시와 적용

| 위치 | 표시 |
| --- | --- |
| 표지 | "사내 일반 · 전 임직원" (남색) / "사내 제한 · IT 운영 담당자·관리자" (주황) 배지 |
| 쪽 꼬리말 | © 가상 ICT 기업 · 문서 번호 · 열람 등급 |

| 파일 속성 | docx·pptx·pdf의 주제(Subject)·범주에 열람 등급 |
| .md 머리말 | access_level, audience 항목 |

> ★ **표시만으로 접근이 막히지 않습니다**
>
> RAG 등록 때 열람 등급을 문서 메타데이터로 넣고, 검색·답변·출처에서 백엔드가 사용자 권한으로 거릅니다 (설계서 7.3·7.4). 외부 모델 전송 허용 여부는 열람 등급과 따로 정합니다.

## 5. 작성 기준

#### 장 구성

| 장 | 임직원용 가이드 | 담당자용 매뉴얼 |
| --- | --- | --- |
| 1 | 개요 (목적 · 적용 대상 · 적용 환경) | 개요 (목적 · 담당 범위) |
| 2 | 먼저 확인할 사항 (증상별 바로가기 포함) | 접수·분류 기준 (항목별 기본값 · 처리 방식 · 긴급도 조정) |
| 3 | 증상별 조치 방법 / 항목별 안내 (3.x) | 증상별 처리 절차 (3.x, 가이드와 같은 번호) |
| 4 | 자주 묻는 질문 | 대형 장애 대응 |
| 5 | 주의사항 | 처리 기록 기준 |
| 6 | 문의처 (공통 표) | 연락처 |
| 부록 | 관련 문서 · 용어 | - |

#### 항목(3.x) 구성

| 종류 | 구성 |
| --- | --- |
| 장애형 가이드 | 이런 경우 → 원인 → 조치 방법 → (그림) → 해결 확인 · 해결되지 않으면 · 문의 시 알려 주실 정보 → 관련 FAQ |
| 신청형 가이드 | 이럴 때 신청합니다 → 신청 방법 → (그림·양식·흐름) → 처리 기간과 결과 확인 · 반려·보완되는 경우 · 문의 시 알려 주실 정보 |
| 담당자용 매뉴얼 | 접수 시 확인 질문 · 판단 기준 → 처리 절차 → 처리 후 안내 문구 → 재발 방지 · 이관 시 전달 정보 |

#### 처리 구분 (항목마다 하나)

| 처리 구분 | 뜻 |
| --- | --- |
| 🟢 사용자 직접 조치 | 안내에 따라 직접 해결합니다. ITssue 챗봇이 절차를 안내합니다. |
| 🟡 신청·승인 후 처리 | 신청서를 내고 팀장 등의 승인을 받은 뒤 담당자가 처리합니다. |
| 🔵 IT 담당자 처리 | 담당자의 확인이나 작업이 필요합니다. ITssue 챗봇으로 접수합니다. |
| 🔴 즉시 신고·이관 | 보안 사고나 여러 사람에게 영향이 있는 장애입니다. 혼자 해결하려 하지 말고 바로 알립니다. |

> ※ **기본 긴급도가 P1인 시나리오(ACC-04, NET-03, SYS-03, SYS-09, SYS-16, SEC-04)와 보안 사고 신고 항목은 "즉시 신고·이관"으로 둡니다.**

#### 통일한 용어와 값

| 항목 | 기준 값 | 원본에서 다르던 것 |
| --- | --- | --- |
| 회사명 | 가상 ICT 기업 | 문서마다 회사 이름 표기가 달랐음 |
| 사내 주소 | *.ict.example, 사내 IT 포털 | portal.ict.example(SW)과 ict.example(그 외)을 함께 씀 → 포털 이름으로 정의 |
| IT 요청 경로 | 그룹웨어 > IT 요청 (= 사내 IT 포털 [IT 요청]) | SW 문서만 사내 IT 포털 > [IT 요청] |
| 연락처 | ITssue 챗봇 기본, IT 헬프데스크 내선 1000 (평일 09:00~18:00), 정보보안팀 내선 1119 | SW 문서는 운영시간 미확정, ACS 문서는 "사내 공지된 연락처"로만 씀 |
| 티켓 상태 | RDY → WIP → FIN → CLS (PRD·SRS·설계서) | 팀원 문서는 RDY → WIP → FIN → CLS |
| 처리 구분 | 사용자 직접 조치 / 신청·승인 후 처리 / IT 담당자 처리 / 즉시 신고·이관 | ACC·SEC는 3색 처리 구분과 처리 주체를 따로, 나머지는 처리 주체만 씀 |
| 부서이동·퇴사 | 발령 다음 날 자동 반영 / 퇴사일 18시 비활성화 / 메일 30일 팀장 전달 (FAQ-004·035) | ACS 문서는 "고정 시각을 보장하지 않음" |
| 담당자용 문서 번호 | IT-{분류}-{번호}-M | ACS만 -OPS |
| 버전·시행일 | 전 문서 v2.0 · 2026-10-16 | v0.1~v1.2, 시행일 2026-03-01 등 제각각 |
| 시연용 표시 문구 | 쓰지 않음 (저장소 README에만 기록) | 표지·쪽 머리·그림 설명·시스템 이름 뒤에 시연용임을 알리는 문구가 있었음 |

#### 쓰지 않는 것

- 시연용·교육용 문서임을 알리는 문구 (그림 속 문구 포함)
- AI 평가용 정답셋(eval_inquiries) 문장과 그 바꿔 쓴 문장, 정답셋에만 있는 키워드
- 비밀번호·인증번호·API 키 같은 비밀정보 예시, 실제 기업 정보
- 근거 데이터에 없는 정책 값 (정해지지 않은 값은 미확정 표시 대신 담당자 확인으로 씀)
