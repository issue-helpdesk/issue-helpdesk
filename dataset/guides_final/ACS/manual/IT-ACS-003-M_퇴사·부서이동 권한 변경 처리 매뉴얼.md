## 1. 개요

#### 목적

IT-ACS-003으로 들어오는 부서이동·퇴사 권한 변경(자동 반영 누락, 유지·추가, 퇴사 회수·인계, 일정 변경)을 인사 근거 확인 → 자원별 반영·회수 → 검증 순서로 처리한다.

#### 담당 범위

| 항목 | 내용 |
| --- | --- |
| 1차 처리 | 서비스데스크(L1): 발령·퇴사 기준 안내(FAQ-004·035), 반영 누락 접수 |
| 2차 이관 | 업무시스템팀(L2): 권한 그룹 갱신·회수·유지, 메일 전달 설정 / 시스템인프라팀: 메일·파일서버 계정 |
| 배정 기준 | ACS-02: 전자결재·권한 담당 (서준호, 신유나). 재배정은 업무시스템팀장이 승인 |
| 처리 역할 | 인사팀은 사실·일시 확인, 자원 소유자는 업무 범위·인계 승인, 자원 담당자는 반영·회수 검증 |

## 2. 접수·분류 기준

임직원용 가이드의 항목별 기본값입니다. 긴급도 기준은 IT-STD-001 IT 서비스 운영 기준을 따릅니다.

| 번호 | 문의 유형 | 증상·요청 | 기본 긴급도 | 1차 처리 | 처리 방식 | 이관 대상 |
| --- | --- | --- | --- | --- | --- | --- |
| 3.1 | ACS-02 | 부서이동 자동 반영 누락 | P4 | 서비스데스크 | 티켓 | 업무시스템팀 |
| 3.2 | ACS-02 | 부서이동 유지·추가 권한 | P4 | 업무시스템팀 | 티켓 | 없음 |
| 3.3 | ACS-02 | 퇴사 계정·권한 회수와 자료 인계 | P4 | 업무시스템팀 | 티켓 | 시스템인프라팀 (메일·파일서버) |
| 3.4 | ACS-02 | 일정 변경·휴직·복직·회수 실패 | P4 | 업무시스템팀 | 티켓 | 정보보안팀 (퇴사 후 사용 의심) |

#### 처리 방식

- 즉시 처리: 안내만으로 끝낸 건. 티켓 없이 상담 기록만 남긴다.
- 티켓: 담당자 조치가 필요한 건. 담당 팀에 배정하고 상태를 RDY → IP → FIN → CLS 로 관리한다. FIN은 담당자 처리 완료, CLS는 문의자가 해결을 확인한 최종 종료다.

#### 긴급도 조정 조건

- ACS-02는 기본 P4다. 마감이 오늘이라 업무가 막히면 P3로 올린다 (INQ-2026-00085).
- 퇴사 후 접속·자료 노출 의심은 보안 사고로 보고 최소 P2로 정보보안팀에 넘긴다.

## 3. 증상별 처리 절차

### 3.1 부서이동 자동 반영 누락

**문의 유형** ACS-02 · **기본 긴급도** P4 · **1차 처리** 서비스데스크 · **처리 방식** 티켓 · **이관 대상** 업무시스템팀

**접수 시 확인 질문**

- 발령일은 언제인가요? 다음 날이 지났나요?
- 보이지 않는 폴더·메뉴는?
- 이전 부서 권한이 아직 보이나요?

**판단 기준**

- 권한은 인사 발령 다음 날 자동 반영된다 (FAQ-004). 그 전이면 기다리도록 안내한다.
- 다음 날이 지났는데 반영되지 않으면 권한 그룹 미갱신으로 보고 직접 처리한다 (INQ-2026-00071, 00074, 00277).
- 이전 권한 그룹이 남아 메뉴가 막히면 권한 그룹을 다시 지정한다 (INQ-2026-00400).


#### 처리 절차

1. 인사 발령 정보를 동기화한다.
2. 새 부서 그룹을 추가하고 이전 부서 권한을 회수한다.
3. 사용자에게 새 기능 확인을 요청하고, 담당자는 이전 권한이 남지 않았는지 확인한다.
4. FIN 처리한다.

#### 처리 후 안내 문구

> 인사 발령 정보를 반영해 새 부서 권한을 추가하고 이전 부서 권한을 회수했습니다. 새 부서 폴더를 사용해 보세요.

**재발 방지**

- 인사발령 시 권한 자동 갱신 점검

**이관 시 전달 정보**

- 발령일
- 대상 자원
- 잔존 권한 확인 결과


### 3.2 부서이동 유지·추가 권한

**문의 유형** ACS-02 · **기본 긴급도** P4 · **1차 처리** 업무시스템팀 · **처리 방식** 티켓 · **이관 대상** 없음

**접수 시 확인 질문**

- 유지가 필요한 권한과 사유·기간은?
- 새 업무에 필요한 추가 권한은?
- 승인 기록이 있나요?

**판단 기준**

- 유지 권한도 사유·기간·승인을 확인한다. 발령 기록만으로 모든 신규 권한을 주지 않는다.
- 새 부서 동료의 권한을 통째로 복제하지 않는다.


#### 처리 절차

1. 자원별로 회수·유지·추가 대상을 나눈다.
2. 승인 범위대로 반영한다.
3. 기간 한정 유지 권한에는 종료 시 회수 작업을 연결한다.
4. 결과를 기록하고 FIN 처리한다.

#### 처리 후 안내 문구

> 인수인계 기간 동안 이전 부서 폴더 조회 권한을 유지했습니다. 기간이 끝나면 자동으로 회수됩니다.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 신청번호
- 유지·추가 권한과 기간


### 3.3 퇴사 계정·권한 회수와 자료 인계

**문의 유형** ACS-02 · **기본 긴급도** P4 · **1차 처리** 업무시스템팀 · **처리 방식** 티켓 · **이관 대상** 시스템인프라팀 (메일·파일서버)

**접수 시 확인 질문**

- 퇴사일은? 인사팀에서 확인됐나요?
- 인수자와 인계 자료는?
- 메일 전달(30일)이 필요한가요?

**판단 기준**

- 퇴사일 18시에 계정이 자동 비활성화된다 (FAQ-035). SSO 비활성화만으로 모든 개별 계정·세션·공유폴더 권한이 회수됐다고 보지 않는다.
- 회수와 보존·인계 요구가 충돌하면 인사·자원 소유자에게 판단을 요청한다.
- 자료 삭제를 기본값으로 하지 않는다.


#### 처리 절차

1. 인사 일시와 자원별 회수 계획, 인수자·자료를 대조한다.
2. 팀장 요청이 있으면 메일을 30일간 팀장에게 전달하도록 설정한다.
3. 퇴사일 18시 비활성화 후 자원별 계정·역할·인증 수단을 회수하고 잔존 접근을 확인한다.
4. 인수자의 자료 사용을 확인하고 결과를 요청한 팀장·인사 담당자에게 알린다.
5. FIN 처리한다.

#### 최종 완료 체크리스트

| 확인 항목 | 완료 판단 |
| --- | --- |
| 인사·승인 일치 | 대상자·적용 일시·변경 범위가 확인된 기록과 같은가? |
| 자원별 회수·유지·추가 | 실제 자원을 모두 점검했고 유지 예외의 범위·기간·회수 담당이 분명한가? |
| 자료·업무 인계 | 지정 인수자의 사용 확인과 보존 요구를 확인했는가? |
| 잔존 접근·미완료 | 잔존 접근 검증 결과가 있고 미완료 항목에 담당·사유·후속 일정이 있는가? |

#### 처리 후 안내 문구

> 퇴사자 계정이 비활성화되고 시스템별 권한 회수를 마쳤습니다. 인계 자료는 지정 인수자가 사용할 수 있습니다.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 퇴사자·퇴사일
- 자원별 회수 결과
- 인계 결과


### 3.4 일정 변경·휴직·복직·회수 실패

**문의 유형** ACS-02 · **기본 긴급도** P4 · **1차 처리** 업무시스템팀 · **처리 방식** 티켓 · **이관 대상** 정보보안팀 (퇴사 후 사용 의심)

**접수 시 확인 질문**

- 변경 전후 일시와 인사 기록은?
- 휴직·복직·겸무 중 무엇인가요?
- 퇴사 후 사용 흔적이 있나요?

**판단 기준**

- 이미 반영된 권한은 자동 복원하지 않고 재승인 필요 여부를 확인한다.
- 휴직·복직·겸무는 퇴사와 같은 일괄 회수나 전체 복원을 가정하지 않는다.
- 퇴사 후 사용·정보 노출은 정보보안팀에 바로 넘긴다 (최소 P2).


#### 처리 절차

1. 기존 예약·작업 목록을 인사 기록과 대조해 고친다.
2. 회수 실패는 잔존 범위·위험·담당자를 기록하고 후속 조치를 요청한다.
3. 결과를 알리고 FIN 처리한다.

#### 처리 후 안내 문구

> 변경된 일정에 맞춰 예약된 권한 변경을 고쳤습니다.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 신청번호
- 변경 전후 일시
- 잔존 범위


## 4. 대형 장애 대응

- 인사 발령 자동 반영이 여러 사람에게 한꺼번에 되지 않으면 개별 처리를 멈추고 대표 티켓 1건으로 묶어 업무시스템팀장에게 알린다.
- 권한관리 시스템·디렉터리 동기화 장애면 시스템인프라팀과 연계하고, 복구 후 반영 결과를 대상자별로 확인한다.
- 여러 사람이 동시에 같은 시스템에 접근하지 못하면 권한이 아니라 시스템 장애로 보고 IT-SYS-003-M을 따른다.
- 복구 후 연결된 티켓을 한꺼번에 종료하고(해결 방법: "MI-YYYY-NN 대형 장애 복구로 일괄 해결") 장애 보고서를 남긴다.

## 5. 처리 기록 기준

티켓을 종료(FIN)할 때 아래 항목을 남깁니다.

| 항목 | 적는 내용 |
| --- | --- |
| 요청·승인 연결 | 기존 신청번호, 승인 기록 참조, 요청자·대상자 |
| 변경 대상 | 시스템·메뉴·폴더, 현재 권한, 요청 권한, 적용 기간 |
| 결과와 증빙 | 변경 전후 설정, 수행 시각·처리자, 승인 대조 결과, 검증 결과 |
| 남은 작업 | 미완료 항목·사유·담당자·다음 안내 일정, 사용자 확인 결과 |
| 가이드 반영 | 임직원용 가이드에 추가·수정이 필요한지 (필요 / 불필요) |
