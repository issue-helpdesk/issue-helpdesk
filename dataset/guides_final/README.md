> 2026-10-19 상태 코드 정정: 담당자 처리 중 표기를 `WIP`로 통일했습니다. 이번 변경은 Markdown·원천 JSON·작성/정규화 스크립트에 반영했습니다. PDF·PPTX·DOCX는 아직 이전 `IP` 표기가 남아 있으므로, 맑은 고딕 글꼴이 있는 환경에서 아래 `build.py` 명령으로 재생성·검수해야 합니다. 재생성 전에는 수정된 Markdown을 기준으로 확인합니다.

`dataset/guides/`에서 7개 분류 담당자가 각자 작성한 가이드를 하나의 체계로 정리했습니다. 팀원 원본은 그대로 두었습니다.
분류·번호·열람 등급·작성 규칙과 중복 정리 결과는 [IT-STD-002 가이드 분류·작성·열람 기준](common/IT-STD-002_가이드%20분류·작성·열람%20기준.md)에 있습니다.

### 문의 분류 폴더 (7개)

각 분류 폴더는 `guide/`(임직원용, 사내 일반), `manual/`(담당자용 `-M`, 사내 제한), `images/`로 이루어집니다.
가이드와 매뉴얼은 같은 번호로 짝을 이루고 항목 번호(3.x)도 같습니다.

| 폴더 | 다루는 내용 | 가이드 | 매뉴얼 |
| --- | --- | --- | --- |
| `ACC` | 계정·로그인: SSO 로그인 오류, 비밀번호 변경·초기화, MFA 인증 오류 | 3 | 3 |
| `ACS` | 접근권한: 사내 시스템 권한 신청, 개발·검증 서버 접근, 퇴사·부서이동 권한 변경 | 3 | 3 |
| `NET` | VPN·네트워크: VPN 접속 장애, 사내 네트워크 장애, 네트워크 장애 신고·이관 | 3 | 3 |
| `SW` | SW·라이선스: 업무용 SW 설치, 라이선스 신청·인증, 실행·오류 대응 | 3 | 3 (신규) |
| `HW` | HW·업무 PC: PC 기본 장애, 장비 교체·수리 신청, 프린터·복합기 | 3 | 3 |
| `SYS` | 사내 시스템: 그룹웨어·ERP, 성능 저하, 장애 신고·이관, 메일, 메신저·화상회의, 공유 드라이브, 인사·근태, 개발 서버·DB | 8 | 8 |
| `SEC` | 정보보안: 피싱·의심 메일, 백신·EDR 알림, 계정 도용·장비 분실, 보안 예외 신청 | 4 | 4 |

| 문서 | 내용 | 열람 등급 |

### 파일 규칙

- 문서 하나에 같은 내용의 파일 4개: `.pdf` · `.pptx` (장표), `.docx` (편집용), `.md` (코드 저장소·RAG 등록용)
- 파일 이름: `{문서 번호}_{문서명}.{확장자}`

## 열람 등급

- **사내 일반**: 임직원용 가이드, 공통 기준. 전 임직원이 봅니다.
- **사내 제한**: 담당자용 매뉴얼, AI 응대 정책. IT 운영 담당자·관리자만 봅니다.

표지 배지·쪽 꼬리말·파일 속성·`.md` 머리말(`access_level`)에 표시했습니다. 표시만으로는 접근이 막히지 않으므로, RAG 등록 때 `manifest.json`의 `access_level`을 메타데이터로 넣고 백엔드에서 사용자 권한으로 거릅니다. 같은 문서는 한 형식만 등록합니다 (권장: `.md`).

## 원본에서 크게 바뀐 점

- 문서 양식을 IT-SW-001 업무용 SW 설치 가이드 디자인으로 통일하고, 장 구성과 항목(3.x) 구성을 맞췄습니다.
- 처리 상태를 기획서·PRD·SRS 기준 `RDY → WIP → FIN → CLS`로 맞췄습니다.
- 부서이동·퇴사 기준을 데이터셋 값으로 통일했습니다: 발령 다음 날 자동 반영, 퇴사일 18시 계정 비활성화, 메일 30일 팀장 전달 (FAQ-004·035).
- 담당자용 번호를 `-M`으로 통일했습니다 (ACS의 `-OPS` 변경). AI 응대 기준은 `IT-ACS-AI-001` → `common/IT-AI-001`.
- 시연용 표시 문구를 모두 지웠습니다. 본문(표지, 쪽 머리, 그림 설명, 이름 뒤 표시)과 그림 속 글자(ACC·SEC는 팀원 그림 도구로 다시 그림, SYS·NET·ACS는 해당 글자만 지움) 모두 해당합니다. ACS 그림의 입력칸 표본값(김예시, DEMO-001 등)은 그대로 두었습니다. 이 정리본의 회사·조직·시스템은 프로젝트용 가상 환경입니다 (docs/05 가상 기업 환경정의서).
- 22개 문서가 참조하던 IT-STD-001을 새로 만들고, 잘못된 항목 참조 4건과 문서명 불일치를 고쳤습니다.

## 다시 만들기

```bash
pip install python-docx python-pptx reportlab pillow pymupdf
cd dataset/guides_final/tools
python build.py                  # 원천 JSON → pdf·pptx·docx·md 전체 (약 2~3분)
python build.py IT-ACC-001       # 일부만
python manifest.py               # manifest.json
```

내용을 고칠 때는 `tools/source/{분류}/{문서 번호}.json`을 고친 뒤 `build.py`를 실행합니다.
SW·ACS·공통 기준·AI 정책은 `author_*.py`가 원천이므로 그 파일을 고치고 `python pipeline.py` → `python build.py` 순서로 실행합니다.
글꼴은 Windows의 맑은 고딕을 씁니다. 다른 OS에서는 `GUIDE_FONT_DIR`에 malgun.ttf·malgunbd.ttf가 있는 폴더를 지정합니다.

점검 스크립트: `check_refs.py`(문서 사이 참조), `qa_layout.py`(장표 넘침), `qa_content.py`(정답셋 문장·금지 문구).
