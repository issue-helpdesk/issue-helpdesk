## 1. 개요

#### 목적

ERP(SYS-02)와 업무 협업 플랫폼(SYS-05)의 지연·간헐 오류 중 쓸 수는 있는 건을 접수·판단·처리하는 내부 절차를 정한다. 사용자 안내는 IT-SYS-002를 기준으로 한다.

#### 담당 범위

| 항목 | 내용 |
| --- | --- |
| 1차 처리 | 서비스데스크(L1): 캐시·PC·네트워크·VPN 확인 안내, 영향 범위(개인/팀/전사) 확인 후 업무시스템팀 배정 |
| 2차 이관 | 업무시스템팀(L2): 서버 자원·캐시 설정, 조회 인덱스, 연동 커넥션 풀, 메모리 한도, 연동 배치·API 한도, 업로드 모듈 패치 |
| 배정 기준 | 업무시스템팀 L2 · ERP 영역 (SYS-02) |
| 배정 기준 | 업무시스템팀 L2 · 업무 협업 플랫폼 영역 (SYS-05) |
| 관련 시스템 | 업무 협업 플랫폼 모니터링 화면, 연동 배치 관리 화면, ERP 관리 화면 |

## 2. 접수·분류 기준

사용자 가이드의 블록별 기본값이다. 긴급도 기준은 IT-STD-001 IT 서비스 운영 기준을 따른다.

| 번호 | 문의 유형 | 증상·요청 | 기본 긴급도 | 1차 처리 | 처리 방식 | 이관 대상 |
| --- | --- | --- | --- | --- | --- | --- |
| 3.1 | SYS-02, SYS-05 | ERP·PMS 개인 지연 | P2 | 서비스데스크 | 즉시 처리 후 필요 시 티켓 | 업무시스템팀 |
| 3.2 | SYS-05 | 오후 시간대 PMS 지연 | P2 | 업무시스템팀 | 티켓 | 없음 |
| 3.3 | SYS-05 | 업데이트 후 BI 지연 | P2 | 업무시스템팀 | 티켓 | 없음 |
| 3.4 | SYS-05 | PMS 연동 간헐 끊김 | P2 | 업무시스템팀 | 티켓 | 없음 |
| 3.5 | SYS-05 | BI 보고서 생성 중 화면 꺼짐 | P2 | 업무시스템팀 | 티켓 | 없음 |
| 3.6 | SYS-05 | BI 매출 수치 오류 | P2 | 업무시스템팀 | 티켓 | 없음 |
| 3.7 | SYS-05 | BI·PMS 업로드 실패 | P2 | 업무시스템팀 | 티켓 | 없음 |
| 3.8 | SYS-05 | PMS·메신저 API 한도 초과 | P2 | 업무시스템팀 | 티켓 | 없음 |

#### 처리 방식

- 즉시 처리: 서비스데스크(L1)가 안내만으로 끝낸 건. 티켓 없이 상담 기록만 남긴다.
- 티켓: 담당자 조치가 필요한 건. 담당팀에 배정하고 상태를 RDY → WIP → FIN → CLS 으로 관리한다.

#### 긴급도 조정 조건

- 팀 전체가 쓸 수 없거나 업무가 멈추면 SYS-05(팀 단위)로 IT-SYS-003-M에 따라 처리한다. 여러 부서로 번지면 P1로 올린다.
- 개인 한 명의 간헐 오류로 업무를 우회할 수 있으면 P3로 접수한다.
- 같은 업데이트 뒤 여러 팀에서 같은 증상이 나오면 대표 티켓으로 묶는다.

## 3. 증상별 처리 절차

### 3.1 ERP와 PMS 등 여러 업무 시스템이 나만 느림

**문의 유형** SYS-02, SYS-05 · **기본 긴급도** P2 · **1차 처리** 서비스데스크 · **이관 대상** 업무시스템팀

**접수 시 확인 질문**

- 옆자리 사람도 느린가요?
- 다른 사이트도 느린가요?
- 사무실인가요, 재택인가요?

**판단 기준**

- 혼자만 느리면 캐시·PC·네트워크 확인 안내로 즉시 처리한다.
- 같은 팀 여러 명이 느리면 티켓으로 업무시스템팀에 배정한다.


#### 처리 절차

1. 캐시 삭제와 탭 정리를 안내한다.
2. PC 자원과 네트워크 상태를 확인한다.
3. 해결되지 않으면 업무시스템팀에 서버 응답 시간을 확인 요청한다.

#### 처리 후 안내 문구

> 브라우저 캐시를 정리하고 PC·네트워크 상태를 확인했습니다. 다시 느려지면 시각과 메뉴를 알려 주세요.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 느린 시스템과 메뉴
- 발생 시각
- 사용자 PC·네트워크 확인 결과


### 3.2 사람이 많이 쓰는 오후 시간대에 PMS가 느려짐

**문의 유형** SYS-05 · **기본 긴급도** P2 · **1차 처리** 업무시스템팀 · **이관 대상** 없음

**접수 시 확인 질문**

- 몇 시쯤 느려지나요?
- 팀원 모두 느린가요?

**판단 기준**

- 특정 시간대에 팀 단위로 느리면 티켓으로 서버 자원을 점검한다.


#### 처리 절차

1. 피크 시간대 서버 자원과 캐시 서버 메모리 사용률을 확인한다.
2. 캐시 서버 메모리를 증설하고 만료 정책을 조정한다.
3. 다음 피크 시간대 응답 속도를 확인한다.

#### 처리 후 안내 문구

> PMS 서버 자원을 늘리고 설정을 조정했습니다. 오후 시간대 속도를 확인해 주세요.

**재발 방지**

- 피크 시간대 자원 사용률 알림 설정

**이관 시 전달 정보**

- 없음 (업무시스템팀에서 종결)

## 4. 대형 장애 대응

1. 팀 전체가 업무 협업 플랫폼이나 ERP를 쓸 수 없게 되면 SYS-05(팀 단위)·SYS-03으로 전환하고 IT-SYS-003-M을 따른다.
2. 대표 티켓(MI-YYYY-NN)을 만들고, 같은 증상의 개별 문의는 대표 티켓에 연결한다.
3. 그룹웨어 공지사항에 장애 공지를 올리고 30분마다 갱신한다.
4. 복구 후 개별 문의를 대표 티켓 기준으로 일괄 완료(FIN) 처리하고, IT운영·보안 조직장에게 원인을 보고한다.

## 5. 처리 기록 기준

처리 완료(FIN) 시 티켓에 아래 항목을 남긴다. 반복되는 건은 사용자 가이드 반영 여부를 검토한다.

| 항목 | 기록 내용 |
| --- | --- |
| 원인 | 확인된 원인 한 줄 (예: VPN 클라이언트 구버전 사용) |
| 조치 내용 | 실제로 한 조치. 즉시 처리면 앞에 [즉시 처리] |
| 재발 방지 | 같은 문의를 줄이기 위한 조치 (없으면 '없음') |
| 관련 FAQ | 안내에 쓴 FAQ 번호 |
| 가이드 반영 | 사용자 가이드에 추가·수정이 필요한지 (필요 / 불필요) |
