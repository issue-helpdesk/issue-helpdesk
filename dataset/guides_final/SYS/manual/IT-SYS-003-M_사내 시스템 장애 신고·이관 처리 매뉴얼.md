## 1. 개요

#### 목적

ERP 전사 장애(SYS-03), 팀 단위 업무 협업 플랫폼 장애(SYS-05), 메일 서버 장애(SYS-09), 파일서버 전사 장애(SYS-16)를 판단하고 대표 티켓으로 묶어 복구·공지·종료하는 내부 절차를 정한다. 사용자 안내는 IT-SYS-003을 기준으로 한다.

#### 담당 범위

| 항목 | 내용 |
| --- | --- |
| 1차 처리 | 서비스데스크(L1): 다수 접수 판단, 대표 티켓 생성, 같은 증상 문의 연결, 장애 공지 |
| 2차 이관 | 업무시스템팀(L2): ERP·업무 협업 플랫폼 장애 원인 확인과 복구 |
| 2차 이관 | 시스템인프라팀(L2): 메일 서버·파일서버 스토리지 장애 원인 확인과 복구 |
| 배정 기준 | 시스템인프라팀 L2 · SSO·메일 서버 영역 (SYS-09) |
| 배정 기준 | 시스템인프라팀 L2 · 파일서버·복구 영역 (SYS-16) |
| 배정 기준 | 업무시스템팀 L2 · ERP 영역 (SYS-03) |
| 배정 기준 | 업무시스템팀 L2 · 업무 협업 플랫폼 영역 (SYS-05) |
| 관련 시스템 | 시스템 모니터링 화면, 장애 공지 게시판, ERP DB 관리 화면, 스토리지 관리 콘솔 |

## 2. 접수·분류 기준

사용자 가이드의 블록별 기본값이다. 긴급도 기준은 IT-STD-001 IT 서비스 운영 기준을 따른다.

| 번호 | 문의 유형 | 증상·요청 | 기본 긴급도 | 1차 처리 | 처리 방식 | 이관 대상 |
| --- | --- | --- | --- | --- | --- | --- |
| 3.1 | SYS-03 | ERP 전사 접속·저장 불가 | P1 | 서비스데스크 | 티켓 | 업무시스템팀 |
| 3.2 | SYS-05 | 팀 단위 업무 협업 플랫폼 장애 | P2 | 서비스데스크 | 티켓 | 업무시스템팀 |
| 3.3 | SYS-09 | 메일 서버 전사 장애 | P1 | 서비스데스크 | 티켓 | 시스템인프라팀 |
| 3.4 | SYS-16 | 파일서버 전사 장애 | P1 | 서비스데스크 | 티켓 | 시스템인프라팀 |

#### 처리 방식

- 즉시 처리: 서비스데스크(L1)가 안내만으로 끝낸 건. 티켓 없이 상담 기록만 남긴다.
- 티켓: 담당자 조치가 필요한 건. 담당팀에 배정하고 상태를 RDY → WIP → FIN → CLS 으로 관리한다.

#### 긴급도 조정 조건

- 같은 시스템을 쓸 수 없다는 문의가 서로 다른 부서에서 3건 이상 접수되면 P1로 판단한다.
- SYS-05는 팀 단위 P2로 처리하고, 여러 부서로 번지면 P1로 올린다.
- 월말 마감일의 ERP 장애는 접수 즉시 P1로 처리한다.

## 3. 증상별 처리 절차

### 3.1 ERP가 로딩만 되고 열리지 않아 여러 부서 업무가 멈춤

**문의 유형** SYS-03 · **기본 긴급도** P1 · **1차 처리** 서비스데스크 · **이관 대상** 업무시스템팀

**접수 시 확인 질문**

- 어느 부서가 안 되나요?
- 로딩만 되나요, 저장 시 타임아웃이 나나요?
- 마감 작업이 걸려 있나요?

**판단 기준**

- 여러 부서에서 접수되면 P1로 보고 업무시스템팀에 바로 연결한다.
- 혼자만 안 되면 SYS-02로 분류해 IT-SYS-001-M으로 처리한다.


#### 처리 절차

1. 대표 티켓을 만들고 같은 증상 문의를 연결한다.
2. ERP DB 잠금 세션과 실행 중인 배치 작업을 확인한다.
3. 대량 배치를 중단하고 잠금 세션을 정리한다. 배치는 야간으로 옮긴다.
4. 복구 후 공지를 갱신한다.

#### 처리 후 안내 문구

> ERP 장애가 복구되었습니다. 저장하지 못한 작업은 다시 입력해 주세요.

**재발 방지**

- 월말 배치 작업 야간 스케줄 고정

**이관 시 전달 정보**

- 최초 접수 시각
- 접수 건수와 부서
- 증상 (로딩 / 타임아웃)
- 실행 중이던 배치 작업


### 3.2 팀 전체가 업무 협업 플랫폼(PMS·BI·마케팅 툴)에 접속할 수 없음

**문의 유형** SYS-05 · **기본 긴급도** P2 · **1차 처리** 서비스데스크 · **이관 대상** 업무시스템팀

**접수 시 확인 질문**

- 어느 시스템(PMS / BI / 마케팅 툴)인가요?
- 팀 전체가 접속하지 못하나요?
- 언제부터인가요?

**판단 기준**

- 팀 전체가 쓸 수 없으면 P2 티켓으로 업무시스템팀에 바로 연결한다.
- 여러 부서로 번지면 P1로 올리고 대표 티켓으로 묶는다.
- 느리지만 쓸 수 있으면 IT-SYS-002-M으로 분류한다.


#### 처리 절차

1. 플랫폼 서버의 디스크·세션·연동 인증서 상태를 확인한다.
2. 원인에 따라 로그 정리·디스크 증설, WAS 인스턴스 증설·세션 설정 조정, SSO 연동 인증서 갱신을 한다.
3. 서비스를 재기동하고 접속을 확인한다.

#### 처리 후 안내 문구

> 업무 협업 플랫폼 장애를 복구했습니다. 다시 로그인해 주세요.

**재발 방지**

- 디스크 사용률 80% 알림 설정
- PMS 사용량 임계치 모니터링 알림 등록
- 연동 인증서 만료 30일 전 알림 등록

**이관 시 전달 정보**

- 시스템 이름
- 영향 팀·인원
- 발생 시각
- 서버 상태 확인 결과


### 3.3 전 부서에서 메일을 보내지도 받지도 못함

**문의 유형** SYS-09 · **기본 긴급도** P1 · **1차 처리** 서비스데스크 · **이관 대상** 시스템인프라팀

**접수 시 확인 질문**

- 보내기·받기 모두 안 되나요?
- 다른 부서도 같은가요?
- 언제부터인가요?

**판단 기준**

- 여러 부서에서 접수되면 P1로 보고 시스템인프라팀에 바로 연결한다.
- 혼자만 안 되면 SYS-06·SW-06으로 분류한다.


#### 처리 절차

1. 대표 티켓을 만들고 같은 증상 문의를 연결한다.
2. 메일 서버 스토리지 경로 상태를 확인한다.
3. 이중화 경로로 전환하고 대기 중인 메일을 다시 처리한다.
4. 장애 보고서를 작성한다.

#### 처리 후 안내 문구

> 메일 서버 장애가 복구되었습니다. 보내지 못한 메일은 다시 보내 주세요.

**재발 방지**

- 스토리지 경로 이중화 점검 주기 단축

**이관 시 전달 정보**

- 최초 접수 시각
- 접수 건수와 부서
- 송신·수신 영향
- 스토리지 상태


### 3.4 공유 드라이브가 전부 열리지 않고 다른 팀도 같음

**문의 유형** SYS-16 · **기본 긴급도** P1 · **1차 처리** 서비스데스크 · **이관 대상** 시스템인프라팀

**접수 시 확인 질문**

- 화면 메시지가 '네트워크 경로를 찾을 수 없습니다'인가요?
- 다른 팀도 같은가요?

**판단 기준**

- 여러 팀에서 접수되면 P1로 보고 시스템인프라팀에 바로 연결한다.
- 한 팀만 안 되면 SYS-13으로 분류해 IT-SYS-006-M으로 처리한다.


#### 처리 절차

1. 대표 티켓을 만들고 같은 증상 문의를 연결한다.
2. 스토리지 컨트롤러 상태를 확인하고 예비 컨트롤러로 전환한다.
3. 데이터 무결성을 점검한 뒤 서비스를 재개한다.
4. 장애 보고를 작성한다.

#### 처리 후 안내 문구

> 파일서버 장애가 복구되었습니다. PC에 임시로 저장한 파일은 공유 드라이브로 옮겨 주세요.

**재발 방지**

- 스토리지 이중화 전환 훈련 반기 1회 실시

**이관 시 전달 정보**

- 최초 접수 시각
- 접수 건수와 팀
- 화면 메시지
- 스토리지 컨트롤러 상태


## 4. 대형 장애 대응

1. 서로 다른 부서에서 같은 시스템 장애가 동시에 접수되면 대형 장애로 판단한다. 사례: MI-2026-01 월말 대량 배치와 조회가 겹친 ERP DB 잠금 (문의 9건 연결), MI-2026-04 메일 서버 스토리지 장애 (문의 7건 연결), MI-2026-06 파일서버 스토리지 컨트롤러 장애 (문의 5건 연결).
2. 대표 티켓(MI-YYYY-NN)을 만들고, 같은 증상의 개별 문의는 대표 티켓에 연결한다.
3. 그룹웨어 공지사항과 #it-helpdesk 채널에 장애 공지를 올리고 30분마다 갱신한다. 메일 장애 중에는 메일로 공지하지 않는다.
4. 복구 후 개별 문의를 대표 티켓 기준으로 일괄 완료(FIN) 처리하고, IT운영·보안 조직장에게 원인과 재발 방지(월말 배치 야간 고정, 스토리지 경로 이중화 점검 주기 단축, 스토리지 이중화 전환 훈련 반기 1회)를 보고한다.
