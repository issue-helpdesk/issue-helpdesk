## 1. 개요

#### 목적

메일 수신 불가(SYS-06), 메일함 용량(SYS-07), 외부 발송 반송(SYS-08) 문의를 접수·판단·처리·이관하는 내부 절차를 정한다. 사용자 안내는 IT-SYS-004를 기준으로 한다.

#### 담당 범위

| 항목 | 내용 |
| --- | --- |
| 1차 처리 | 서비스데스크(L1): 격리 메일 해제·허용 목록 등록, 용량 정리·아카이브 안내 |
| 2차 이관 | 시스템인프라팀(L2): 반송 원인 분석, 외부 스팸 목록 해제 요청, 발송 인증(SPF/DKIM) 설정 점검 |
| 배정 기준 | 서비스데스크 L1 · 메일·협업 1차 영역 (SYS-06, SYS-07) |
| 배정 기준 | 시스템인프라팀 L2 · SSO·메일 서버 영역 (SYS-08) |
| 관련 시스템 | 메일 보안 게이트웨이 관리 화면(격리함·허용 목록), 메일 관리 콘솔, 발송 로그 |

## 2. 접수·분류 기준

사용자 가이드의 블록별 기본값이다. 긴급도 기준은 IT-STD-001 IT 서비스 운영 기준을 따른다.

| 번호 | 문의 유형 | 증상·요청 | 기본 긴급도 | 1차 처리 | 처리 방식 | 이관 대상 |
| --- | --- | --- | --- | --- | --- | --- |
| 3.1 | SYS-06 | 외부 메일 격리 | P3 | 서비스데스크 | 즉시 처리 후 필요 시 티켓 | 없음 |
| 3.2 | SYS-06 | 용량 초과로 수신 중단 | P3 | 서비스데스크 | 즉시 처리 후 필요 시 티켓 | 없음 |
| 3.3 | SYS-07 | 메일함 용량 부족 | P4 | 서비스데스크 | 즉시 처리 후 필요 시 티켓 | 없음 |
| 3.4 | SYS-08 | 첨부 메일만 반송 | P2 | 시스템인프라팀 | 티켓 | 없음 |
| 3.5 | SYS-08 | 해외 도메인 팀 전체 반송 | P2 | 시스템인프라팀 | 티켓 | 없음 |

#### 처리 방식

- 즉시 처리: 서비스데스크(L1)가 안내만으로 끝낸 건. 티켓 없이 상담 기록만 남긴다.
- 티켓: 담당자 조치가 필요한 건. 담당팀에 배정하고 상태를 RDY → IP → FIN → CLS 으로 관리한다.

#### 긴급도 조정 조건

- 여러 부서에서 동시에 메일을 받지 못하면 SYS-09(P1)로 전환하고 IT-SYS-003-M을 따른다.
- 마감 등 당일 업무 차질을 말하면 SYS-06·SYS-07이라도 한 단계 올린다.
- 팀 전체가 같은 도메인으로 반송되면 SYS-08(P2)로 시스템인프라팀에 바로 배정한다.

## 3. 증상별 처리 절차

### 3.1 거래처에서 보낸 메일이 받은편지함에 없음

**문의 유형** SYS-06 · **기본 긴급도** P3 · **1차 처리** 서비스데스크 · **이관 대상** 없음

**접수 시 확인 질문**

- 보낸 사람 주소와 보낸 시각은 언제인가요?
- 격리함을 확인했나요?

**판단 기준**

- 격리함 해제 안내로 즉시 처리한다.
- 같은 거래처가 반복 격리되면 발신 도메인을 허용 목록에 등록하고 티켓으로 기록한다.
- 피싱이 의심되면 해제하지 말고 SEC-01로 분류한다.


#### 처리 절차

1. 메일 보안 게이트웨이에서 격리 내역을 확인한다.
2. 메일을 해제하고 발신 도메인을 허용 목록에 등록한다.
3. 수신을 확인한다.

#### 처리 후 안내 문구

> 격리함에서 메일을 해제하고 보낸 곳을 허용 목록에 등록했습니다.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 없음 (서비스데스크에서 종결)


### 3.2 오늘 오후부터 메일이 한 통도 들어오지 않음

**문의 유형** SYS-06 · **기본 긴급도** P3 · **1차 처리** 서비스데스크 · **이관 대상** 없음

**접수 시 확인 질문**

- 메일함 용량 경고가 있나요?
- 마지막으로 메일을 받은 시각은 언제인가요?

**판단 기준**

- 용량 초과면 보관·정리 안내로 처리한다.
- 용량에 여유가 있는데도 수신이 안 되면 메일 관리 콘솔에서 수신 거부 로그를 확인한다.


#### 처리 절차

1. 메일함 용량과 수신 거부 로그를 확인한다.
2. 오래된 메일 보관 처리를 안내한다.
3. 테스트 메일 수신을 확인한다.

#### 처리 후 안내 문구

> 오래된 메일을 보관 처리해 다시 메일을 받을 수 있게 되었습니다.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 없음 (서비스데스크에서 종결)


### 3.3 메일함 용량 부족 경고가 계속 뜸

**문의 유형** SYS-07 · **기본 긴급도** P4 · **1차 처리** 서비스데스크 · **이관 대상** 없음

**접수 시 확인 질문**

- 현재 메일함 용량은 얼마인가요?
- 보관(아카이브)이나 큰 메일 정리를 해 봤나요?

**판단 기준**

- 아카이브·대용량 메일 검색 방법 안내로 즉시 처리한다.
- 업무상 증설이 필요하면 증설 기준을 안내하고 티켓으로 검토한다.


#### 처리 절차

1. size:>10MB 검색과 자동 보관 설정을 안내한다.
2. 용량 증설 기준을 안내한다.

#### 처리 후 안내 문구

> 큰 메일을 정리하고 자동 보관을 설정하셨습니다. 메일함 기본 용량은 50GB입니다.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 없음 (서비스데스크에서 종결)


### 3.4 첨부파일이 있는 메일만 반송됨

**문의 유형** SYS-08 · **기본 긴급도** P2 · **1차 처리** 시스템인프라팀 · **이관 대상** 없음

**접수 시 확인 질문**

- 첨부 크기는 얼마인가요?
- 반송 메일 원문이 있나요?

**판단 기준**

- 25MB 초과면 파일 공유 링크 안내로 처리한다.
- 25MB 미만인데도 반송되면 발송 로그를 확인한다.


#### 처리 절차

1. 반송 메일 원문에서 반송 사유를 확인한다.
2. 25MB 초과면 사내 파일 공유 링크 사용을 안내한다.
3. 다른 원인이면 발송 로그를 분석한다.

#### 처리 후 안내 문구

> 첨부가 25MB를 넘어 반송되었습니다. 사내 파일 공유 링크로 보내 주세요.

**재발 방지**

- 발송 도메인 평판 주기 점검

**이관 시 전달 정보**

- 없음 (시스템인프라팀에서 종결)


### 3.5 해외 거래처로 보낸 메일이 팀 전체 반송됨

**문의 유형** SYS-08 · **기본 긴급도** P2 · **1차 처리** 시스템인프라팀 · **이관 대상** 없음

**접수 시 확인 질문**

- 어느 도메인으로 보낼 때 반송되나요?
- 팀 전체가 같은가요?
- 반송 메일 원문이 있나요?

**판단 기준**

- 팀 단위 반송이면 P2 티켓으로 시스템인프라팀에 배정한다.
- 전 부서 송수신 불가면 SYS-09로 전환한다.


#### 처리 절차

1. 반송 메일 원문으로 거부 사유를 확인한다.
2. 발송 서버 IP가 외부 스팸 목록에 올랐으면 해제를 요청한다.
3. 발송 인증(SPF/DKIM) 설정을 점검한다.
4. 재발송을 확인한다.

#### 처리 후 안내 문구

> 외부 스팸 목록 해제를 마쳤습니다. 메일을 다시 보내 주세요.

**재발 방지**

- 발송 도메인 평판 주기 점검

**이관 시 전달 정보**

- 없음 (시스템인프라팀에서 종결)


## 4. 대형 장애 대응

1. 여러 부서에서 동시에 메일을 보내거나 받지 못하면 SYS-09 대형 장애로 판단하고 IT-SYS-003-M을 따른다.
2. 대표 티켓(MI-YYYY-NN)을 만들고, 같은 증상의 개별 문의는 대표 티켓에 연결한다.
3. 그룹웨어 공지사항에 장애 공지를 올리고 30분마다 갱신한다.
4. 복구 후 개별 문의를 대표 티켓 기준으로 일괄 완료(FIN) 처리하고, IT운영·보안 조직장에게 원인을 보고한다.
