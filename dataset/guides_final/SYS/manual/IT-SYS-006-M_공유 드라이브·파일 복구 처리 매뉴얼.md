## 1. 개요

#### 목적

공유 드라이브 접속 장애(SYS-13)와 파일 복구(SYS-14) 문의를 접수·판단·처리하는 내부 절차를 정한다. 사용자 안내는 IT-SYS-006을 기준으로 한다.

#### 담당 범위

| 항목 | 내용 |
| --- | --- |
| 1차 처리 | 서비스데스크(L1): VPN·드라이브 재연결·이전 버전 복원 안내, 간단한 스냅샷 복구 |
| 2차 이관 | 시스템인프라팀(L2): 폴더 권한 상속 복구, 파일서버 경로 안내, 스냅샷 복구 |
| 배정 기준 | 서비스데스크 L1 · PC·네트워크 1차 점검 영역 (SYS-14) |
| 배정 기준 | 시스템인프라팀 L2 · 파일서버·복구 영역 (SYS-13, SYS-14) |
| 관련 시스템 | 파일서버 관리 콘솔, 스냅샷 관리 화면 |

## 2. 접수·분류 기준

사용자 가이드의 블록별 기본값이다. 긴급도 기준은 IT-STD-001 IT 서비스 운영 기준을 따른다.

| 번호 | 문의 유형 | 증상·요청 | 기본 긴급도 | 1차 처리 | 처리 방식 | 이관 대상 |
| --- | --- | --- | --- | --- | --- | --- |
| 3.1 | SYS-13 | 팀 공유 드라이브 액세스 거부 | P2 | 시스템인프라팀 | 티켓 | 없음 |
| 3.2 | SYS-13 | 드라이브 재연결 경로 오류 | P2 | 시스템인프라팀 | 티켓 | 없음 |
| 3.3 | SYS-14 | 이전 버전 직접 복원 | P3 | 서비스데스크 | 즉시 처리 후 필요 시 티켓 | 시스템인프라팀 |
| 3.4 | SYS-14 | 삭제 파일 복구 | P3 | 서비스데스크 | 즉시 처리 후 필요 시 티켓 | 시스템인프라팀 |

#### 처리 방식

- 즉시 처리: 서비스데스크(L1)가 안내만으로 끝낸 건. 티켓 없이 상담 기록만 남긴다.
- 티켓: 담당자 조치가 필요한 건. 담당팀에 배정하고 상태를 RDY → IP → FIN → CLS 으로 관리한다.

#### 긴급도 조정 조건

- 팀 전체가 접근하지 못하면 SYS-13(P2)으로 시스템인프라팀에 바로 배정한다.
- 여러 팀에서 동시에 접근하지 못하면 SYS-16(P1)으로 전환하고 IT-SYS-003-M을 따른다.
- 마감 파일 복구는 P3를 P2로 올린다.

## 3. 증상별 처리 절차

### 3.1 팀 공유 드라이브에서 '액세스가 거부되었습니다'가 뜨고 팀원 전부 같음

**문의 유형** SYS-13 · **기본 긴급도** P2 · **1차 처리** 시스템인프라팀 · **이관 대상** 없음

**접수 시 확인 질문**

- 팀원 모두 같은가요?
- 폴더 경로는 무엇인가요?
- 최근 폴더 권한을 바꾼 일이 있나요?

**판단 기준**

- 팀 전체면 P2 티켓으로 시스템인프라팀에 배정한다.
- 혼자만 안 되면 권한 신청(ACS-01)으로 안내한다.
- 여러 팀이면 SYS-16으로 전환한다.


#### 처리 절차

1. 파일서버 관리 콘솔에서 폴더 권한과 상속 설정을 확인한다.
2. 권한 상속을 복구한다.
3. 팀원 접근을 확인한다.

#### 처리 후 안내 문구

> 폴더 권한을 복구했습니다. 공유 드라이브를 다시 열어 주세요.

**재발 방지**

- 권한 변경 작업 시 사전 검토 절차 추가

**이관 시 전달 정보**

- 없음 (시스템인프라팀에서 종결)


### 3.2 공유 드라이브 연결이 끊겨 다시 연결하려니 '경로를 찾을 수 없음'

**문의 유형** SYS-13 · **기본 긴급도** P2 · **1차 처리** 시스템인프라팀 · **이관 대상** 없음

**접수 시 확인 질문**

- 재택 중인가요? VPN에 연결되어 있나요?
- 기존 드라이브 경로는 무엇인가요?

**판단 기준**

- 파일서버 주소 변경이면 새 경로로 다시 연결하도록 안내하고 티켓을 완료한다.


#### 처리 절차

1. 파일서버 주소 변경 여부를 확인한다.
2. 새 경로를 안내하고 재연결을 확인한다.

#### 처리 후 안내 문구

> 공유 드라이브 주소가 바뀌었습니다. 새 경로로 다시 연결해 주세요.

**재발 방지**

- 권한 변경 작업 시 사전 검토 절차 추가

**이관 시 전달 정보**

- 없음 (시스템인프라팀에서 종결)


### 3.3 지운 파일을 '이전 버전'으로 직접 복원하기

**문의 유형** SYS-14 · **기본 긴급도** P3 · **1차 처리** 서비스데스크 · **이관 대상** 시스템인프라팀

**접수 시 확인 질문**

- 언제 지웠나요?
- 폴더의 [이전 버전] 탭을 열어 봤나요?

**판단 기준**

- 30일 안이면 이전 버전 복원 방법 안내로 즉시 처리한다.
- 목록에 없거나 폴더 전체를 지웠으면 3.4 기준으로 복구한다.


#### 처리 절차

1. 이전 버전 복원 방법을 안내한다.
2. 파일이 복원됐는지 확인한다.

#### 처리 후 안내 문구

> 폴더 [속성] > [이전 버전]에서 지우기 전 날짜를 골라 복원해 주세요.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 폴더 경로
- 지운 시각
- 이전 버전 목록 확인 결과


### 3.4 삭제한 파일 복구 요청

**문의 유형** SYS-14 · **기본 긴급도** P3 · **1차 처리** 서비스데스크 · **이관 대상** 시스템인프라팀

**접수 시 확인 질문**

- 파일·폴더 경로와 이름은 무엇인가요?
- 언제 지웠나요?

**판단 기준**

- 30일 안이면 스냅샷에서 복구하고 셀프 복원 방법도 안내한다.
- 30일이 지났으면 복구할 수 없다고 안내한다.


#### 처리 절차

1. 스냅샷 관리 화면에서 삭제 전 날짜를 찾는다.
2. 전일 버전을 원래 위치에 복구한다.
3. '이전 버전' 셀프 복원 방법을 안내한다.

#### 처리 후 안내 문구

> 스냅샷에서 파일을 복구했습니다. 다음에는 폴더 [이전 버전]에서 직접 복원할 수도 있습니다.

**재발 방지**

- 없음

**이관 시 전달 정보**

- 경로
- 파일 이름
- 지운 시각


## 4. 대형 장애 대응

1. 여러 팀에서 동시에 공유 드라이브에 접근하지 못하면 SYS-16 대형 장애로 판단하고 IT-SYS-003-M을 따른다.
2. 대표 티켓(MI-YYYY-NN)을 만들고, 같은 증상의 개별 문의는 대표 티켓에 연결한다.
3. 그룹웨어 공지사항에 장애 공지를 올리고 30분마다 갱신한다.
4. 복구 후 개별 문의를 대표 티켓 기준으로 일괄 완료(FIN) 처리하고, IT운영·보안 조직장에게 원인을 보고한다.

| --- | --- |
| 원인 | 확인된 원인 한 줄 (예: VPN 클라이언트 구버전 사용) |
| 조치 내용 | 실제로 한 조치. 즉시 처리면 앞에 [즉시 처리] |
| 재발 방지 | 같은 문의를 줄이기 위한 조치 (없으면 '없음') |
| 관련 FAQ | 안내에 쓴 FAQ 번호 |
| 가이드 반영 | 사용자 가이드에 추가·수정이 필요한지 (필요 / 불필요) |
