## 1. 개요

**목적**

- 모든 IT 가이드가 함께 따르는 문의 창구, 처리 흐름, 긴급도와 처리 목표, 공통 규칙을 정합니다.

**적용 대상**

- 전 임직원과 IT운영·보안 조직이 대상입니다.
- 분류별 해결 방법은 각 분류 가이드(IT-ACC~SEC)를 봅니다.

**적용 환경**

- ITssue 챗봇, 사내 IT 포털(hanwha-admin), 그룹웨어
- Jira (담당자 티켓 처리)


## 2. 문의 창구와 처리 흐름

#### 문의 창구

| 창구 | 연락처 | 이용 기준 |
| --- | --- | --- |
| ITssue 챗봇 | 사내 IT 포털(hanwha-admin) 상단 [챗봇 문의] | 24시간. 모든 IT 문의의 기본 창구입니다. 챗봇이 해결하지 못하면 확인을 거쳐 담당 팀에 티켓으로 접수합니다. |
| IT 헬프데스크 (서비스데스크) | 내선 1000 (평일 09:00~18:00) | PC나 챗봇을 쓸 수 없을 때, 여러 사람이 함께 업무를 못 할 때, 본인 확인이 필요한 처리 |
| 정보보안팀 | 내선 1119 | 링크 클릭·비밀번호 입력·감염 의심·계정 도용·장비 분실처럼 바로 알려야 할 보안 문제 |
| 메신저 | #it-helpdesk 채널 | 일반 IT 문의 (챗봇을 쓸 수 없을 때) |
| 메일 | it-helpdesk@hanwha-ict.example | 일반 IT 문의. 비밀번호·인증번호는 메일로 보내지 않습니다. |
| 처리 상황 알림 | 사내 메신저 알림 | 접수·담당자 배정·처리 완료를 알려 드립니다. 진행 상황은 [내 요청 현황]에서도 봅니다. |

#### 처리 흐름

**STEP 1 문의**: ITssue 챗봇에 증상을 적습니다 → **STEP 2 AI 안내**: 가이드를 근거로 해결 방법을 안내합니다 → **STEP 3 담당자 연결**: 필요하면 연결을 제안하고, 접수 내용을 확인받습니다 → **STEP 4 처리**: 담당자가 Jira 티켓으로 처리합니다 → **STEP 5 해결 확인**: 결과를 안내받고 해결을 확인합니다

> ※ **접수는 사용자가 담당자 연결을 선택하고 접수 내용을 최종 확인한 뒤에 합니다. ITssue 접수는 필요한 승인 절차(권한 신청·결재)를 대신하지 않습니다.**

#### 티켓 처리 상태

| 상태 | 뜻 | 사용자에게 보이는 것 |
| --- | --- | --- |
| RDY | 담당자 처리 대기 | 접수되어 담당자 배정을 기다리거나 작업 전 |
| IP | 담당자 처리 중 | 담당자가 작업하고 있음 |
| FIN | 담당자 처리 완료 / 문의자 해결 확인 대기 | 처리 결과와 해결 확인 요청이 옴 |
| CLS | 문의자 해결 확인 완료 / 최종 종료 | 해결을 확인하면 종료 |

> ※ **응답하지 않았다고 해결로 처리하지 않습니다. 해결되지 않았으면 해결 확인 요청에 "해결되지 않음"으로 답합니다. 과거 처리 이력의 IP는 IP와 같은 뜻입니다.**

#### 처리 방식

| 방식 | 뜻 |
| --- | --- |
| 즉시 처리 | 챗봇·상담원 안내만으로 끝난 건. 티켓을 만들지 않고 상담 기록만 남깁니다. |
| 티켓 | 담당자 조치가 필요한 건. 담당 팀에 배정해 RDY → IP → FIN → CLS로 처리합니다. |
| 대형 장애 | 여러 사람이 같은 장애를 겪는 건. 대표 티켓 하나로 묶어 처리합니다 (6장). |

## 3. 긴급도와 처리 목표

| 등급 | 명칭 | 판단 기준 | 응답 목표 | 해결 목표 |
| --- | --- | --- | --- | --- |
| P1 | 긴급 | 전사 또는 여러 부서의 업무가 멈춘 경우 | 15분 | 4시간 |
| P2 | 높음 | 부서 단위로 영향이 있거나 개인 업무를 전혀 할 수 없는 경우, 보안 사고 의심 | 30분 | 8시간 |
| P3 | 보통 | 개인 업무 일부에 지장이 있지만 우회할 수 있는 경우 | 2시간 | 16시간 (약 2영업일) |
| P4 | 낮음 | 단순 문의·요청으로 업무 지장이 없는 경우 | 4시간 | 40시간 (약 5영업일) |

#### 긴급도를 올리는 기준

- "팀 전체", "다른 분들도", "전부"처럼 여러 사람이 영향을 받으면 한 단계 이상 올립니다.
- 링크 클릭·비밀번호 입력·계정 도용 의심처럼 보안 사고 가능성이 있으면 최소 P2로 처리하고 정보보안팀에 바로 넘깁니다.
- 당일 마감·고객 미팅처럼 시간 제약이 있으면 한 단계 올릴 수 있습니다.
- "급하다"는 말만으로는 올리지 않습니다. 같은 이유를 두 번 반영하지 않습니다.

> ※ **챗봇에 문의할 때 영향 범위(나만 / 팀 / 여러 부서), 마감 시각, 이미 해 본 조치를 적으면 긴급도를 정확히 판단합니다.**

#### 신청 건의 처리 기간

신청 건(설치·라이선스·권한·장비)은 긴급도와 별개로 각 가이드의 "처리 기간"을 따릅니다. 승인이 필요한 건은 승인이 끝난 때부터 셉니다.

| 문의 | 분류 (볼 문서) | 구분 |
| --- | --- | --- |

| PC에 설치한 메일 프로그램 오류 | SW-06 (IT-SW-003 3.7) | 메일 수신·용량·반송·메일 서버는 SYS (IT-SYS-004) |
| 메신저·화상회의 | SYS-10 (IT-SYS-005) | VPN 중에만 느리면 NET-02, 사무실 전체가 느리면 NET-04 |
| 프린터·복합기 | HW (IT-HW-003) |  |
| 공유 드라이브 "액세스 거부" | 팀 전체: SYS-13 (IT-SYS-006 3.1) | 혼자만: ACS-01 (IT-ACS-001 3.4), 부서 이동 뒤: ACS-02 (IT-ACS-003 3.2) |
| 개발 서버 SSH 실패 | 팀 전체·배포 중단: SYS-15 (IT-SYS-008 3.1) | 혼자만·권한: ACS-01 (IT-ACS-002 3.4) |

| 부서 이동·퇴사 문의 | ACS-02 (IT-ACS-003) | "부서 이동", "퇴사", "발령"이 있으면 ACS-02, 새로 필요한 권한이면 ACS-01 |

> ※ **담당 조직은 분류를 기본으로 추천하되, 대상 시스템과 요청 업무에 따라 조정합니다. 예를 들어 SSO 로그인 안내는 서비스데스크가, SSO 서비스 장애는 시스템인프라팀이 맡습니다.**

## 5. 공통 규칙

> ★ **모든 IT 문의에 똑같이 적용합니다**

| 규칙 | 내용 |
| --- | --- |
| 본인 확인 후 조치 | 비밀번호 초기화·잠금 해제·MFA 초기화처럼 계정에 손대는 조치는 본인 확인(사번 + 휴대폰 인증) 뒤에만 합니다. 비밀번호는 메신저·메일로 보내지 않습니다. |
| 비밀정보는 묻지도 보내지도 않음 | IT 헬프데스크·챗봇·담당자는 비밀번호·인증번호를 묻지 않습니다. 묻는 연락은 사칭일 수 있으니 정보보안팀에 알립니다. |
| 보안 장치를 끄지 않음 | 백신·EDR을 끄거나 지우는 방법, SSL 검증을 끄는 방법처럼 보안 장치를 피해 가는 방법은 쓰지 않습니다. |
| 관리자 권한은 주지 않음 | 설치가 필요하면 소프트웨어 센터를 쓰거나 담당자가 원격으로 설치합니다. |
| 승인은 담당자에게 | 권한 부여·보안 예외처럼 승인이 필요한 일은 챗봇이 처리하지 않습니다. 절차를 안내하고 담당자에게 연결합니다. |
| 영향 범위 먼저 | 나만 겪는지, 팀·층 전체인지, 회사 전체인지 먼저 확인합니다. |
| 장비 안전 | 물에 젖었거나 파손된 장비는 전원을 끄고 충전기를 빼며 다시 켜지 않습니다. |
| 기밀 정보 보호 | 고객 정보·개인정보·소스코드 같은 기밀은 승인되지 않은 외부 도구(생성형 AI 포함)에 넣지 않습니다 (IT-SEC-004 3.4). |

#### 문의할 때 알려 주실 정보

- 증상과 화면 메시지(캡처)
- 영향 범위 (나만 / 팀 / 여러 부서)
- 발생 시각
- 이미 해 본 조치와 결과
- 마감 등 시간 제약

## 6. 여러 사람이 함께 겪는 장애 (대형 장애)

#### 임직원이 할 일

1. 옆자리·같은 층 동료도 같은지 확인합니다. 같으면 개인 조치(재설치·비밀번호 변경 등)를 반복하지 않습니다.
2. IT 헬프데스크(내선 1000)에 알리거나 ITssue 챗봇에 "여러 명"과 영향 범위를 적어 신고합니다. 보안 문제(대량 피싱 등)는 정보보안팀(내선 1119)에 알립니다.
3. 장애 공지가 나오면 공지를 따릅니다. 같은 장애를 여러 창구로 반복 신고하지 않습니다.
4. 복구 공지 후 다시 해 보고, 그래도 안 되면 개인 문의로 알립니다.

#### 장애별 기준 문서

| 장애 | 볼 문서 |
| --- | --- |
| 통합 로그인(SSO) 전체 장애 | IT-ACC-001 3.3 |
| VPN·사내망·인터넷 전체 장애 | IT-NET-003 |
| ERP·협업 플랫폼·메일 서버·파일서버 전체 장애 | IT-SYS-003 |
| 피싱 메일 대량 유입 | IT-SEC-001 3.5 |
| 층 단위 복합기 장애 | IT-HW-003 3.1 |

> ※ **IT운영·보안 조직은 대표 티켓 1건을 정해 같은 증상 티켓을 연결하고, 전사 공지와 챗봇 첫 화면 안내를 띄웁니다. 복구 뒤에는 연결된 티켓을 한꺼번에 종료하고 장애 보고서(원인·조치·재발 방지)를 남깁니다.**

## 부록 · 관련 문서 · 용어

#### 사내 시스템과 용어

| 용어 | 설명 |
| --- | --- |
| ITssue 챗봇 | 사내 IT 문의를 받는 AI 상담 창구. 가이드를 근거로 안내하고, 필요하면 담당자에게 연결한다 |
| 사내 IT 포털 (hanwha-admin) | 소프트웨어 센터, IT 요청, 내 요청 현황, 장애 공지, 챗봇 문의를 모아 둔 사이트. 그룹웨어 [IT 요청]에서도 들어간다 |
| 그룹웨어 | 메일, 전자결재, 조직도, IT 요청·권한 신청을 쓰는 사내 시스템 |
| 통합 로그인 (SSO) | 사번 계정 하나로 그룹웨어·ERP·메일·VPN·메신저에 로그인하는 방식 (sso.hanwha-ict.example) |
| 셀프 비밀번호 재설정 포털 | 사번과 휴대폰 인증으로 비밀번호를 직접 바꾸는 사이트 (password.hanwha-ict.example) |
| 정보보안 포털 | 장비 분실 신고, 승인된 생성형 AI 도구 목록, 보안 예외 신청을 보는 사이트 |
| IT 헬프데스크 | 서비스데스크가 운영하는 전화 창구 (내선 1000) |
| 티켓 | 담당자가 처리할 IT 요청 한 건. ITssue에서 접수하면 Jira에 만들어진다 |
| L1 / L2 | L1은 서비스데스크 1차 상담, L2는 분야별 전문팀 담당자 |
