IT와 이슈를 연결하는 AI 기반 IT 헬프데스크 서비스 ITssue입니다. 레트로 감성은 로고와 그래픽에만 담고, 업무 화면은 면과 여백으로 정돈합니다.

01

선보다 면으로 구분한다

바닥·패널·카드 세 겹의 면으로 위계를 만듭니다. 테두리는 꼭 필요한 곳에만 1px로 씁니다.

02

브랜드는 포인트와 그래픽으로

오렌지는 로고·핵심 행동·포커스에만 씁니다. 레트로 감성은 그래픽 요소에 담고, 업무 화면은 조용하게 비웁니다.

03

상태는 색과 글자로 함께

긴급·진행·완료 같은 상태는 브랜드 컬러와 겹치지 않는 별도 팔레트로 분리하고, 항상 글자 라벨을 함께 보여줍니다.

브랜드 로고

로고는 두꺼운 픽셀 계단 형태의 워드마크입니다. "IT"는 오렌지, "ssue"는 잉크색이며, 아래에 작은 설명줄 AI HELPDESK를 둡니다. 기본형은 A입니다.

A · 기본형
B · 픽셀 포인트
C · 확장 창 (애경형)
▢✕
D · 모노크롬

확장 창 장식형 (새 문의 첫 화면)

새 문의 첫 화면의 인사말 위에만 쓰는 꾸밈 버전입니다. 확장 창 로고(C) 뒤에 옅은 창(#CFE4EE 제목줄), 오렌지 픽셀 스파크 3개, 픽셀 커서를 겹칩니다. 로고 도형 자체는 건드리지 않고, 업무 화면에는 쓰지 않습니다.

▢✕
▢✕

사용 규칙

  • 위치 새 문의 첫 화면의 인사말 바로 위. 이 화면에는 상단바 제목("새 문의 / 사내 IT 지원")을 두지 않고, 그래픽과 입력창을 화면 세로 가운데에 둡니다. 모바일에서는 왼쪽 위에 메뉴 버튼만 둡니다.
  • 크기 앞 창 가로 250px, 로고 170px. 뒤 창은 175×95px.
  • 움직임 커서만 3.2초 주기로 6px 안쪽에서 천천히 움직이고, 움직임 줄이기 설정에서는 멈춥니다.
  • 금지 말풍선·마스코트·외곽선·그림자를 로고 글자에 더하지 않습니다. 창의 그림자(4px 5px)만 허용합니다.

로고 색상 변형

흰 바탕 · 잉크 바탕(ssue만 흰색) · 서피스 바탕. 오렌지 위나 사진 위에서는 모노크롬(D)을 씁니다.

로고 사용 기준

여백과 최소 크기

  • 여백 사방으로 글자 "I" 높이의 절반(x)을 비웁니다.
  • 최소 크기 가로 96px(설명줄 포함) 이상. 가로 160px 미만에서는 설명줄을 빼고 워드마크만 씁니다.
  • 사이드바 워드마크 가로 112px, 왼쪽 여백 20px. 로그인 가로 144px.

쓰지 않는 방식

  • "I"에 깨진 픽셀이나 노이즈를 넣지 않습니다. 획은 끊김 없이 단단하게 채웁니다.
  • 일반 폰트나 다른 픽셀 글꼴로 다시 쓰지 않습니다. 이 가이드의 로고 도형을 그대로 씁니다.
  • 말풍선·고양이·마스코트를 로고나 아바타에 붙이지 않습니다.
  • 늘리기, 기울이기, 외곽선, 그림자, 정해진 색 외의 채우기를 하지 않습니다.
  • B·C 변형과 장식형은 소개·시작 화면에만 쓰고, 업무 화면에는 A를 씁니다.

크기·줄 높이·여백·모서리는 px, 자간만 em으로 정의합니다. em은 글자 크기에 맞춰 자동으로 커지고 작아지기 때문에, 글자 크기를 바꿔도 자간 비율이 유지됩니다. 디자인 도구에서 쓰도록 px 환산값을 괄호에 함께 적습니다.

한글 제목 규칙

  • 한글 제목의 자간은 -0.01em보다 좁히지 않습니다. 더 좁히면 글자 덩어리가 서로 붙어 깨져 보입니다.
  • 줄바꿈은 어절 단위로 합니다 (word-break: keep-all).
  • 글꼴이 늦게 로드되면 시스템 고딕이 잠깐 보입니다. 폭이 달라져도 줄바꿈이 무너지지 않게 만듭니다.

파비콘 · 앱 아이콘 · AI 아바타

"IT" 두 글자만 로고 도형 그대로 씁니다. 48px 이상은 은은한 세로 그라데이션(위 #FF8F45 → #F37321 → #E0640D)과 위쪽 1px 하이라이트로 살짝 입체감을 주고, 32px 이하와 AI 답변 아바타(오렌지 바탕 32px)는 단색으로 씁니다.

05 · 제작 규칙

비주얼을 유지하는 수정 규칙

레이아웃, 창 일러스트, 오렌지 그라데이션, 아이콘, 컴포넌트 밀도는 앞의 보드를 기준으로 합니다.

01

로고: I의 결손만 제거

  • 로고 "I"의 안쪽과 가장자리에서 깨진 흰 픽셀을 메워 끊김 없는 단단한 획으로 만듭니다.
  • T와 ssue의 형태·무게·비례는 유지합니다. 일반 폰트나 다른 픽셀 글꼴로 바꾸지 않습니다.
  • 기본형·확장 창·반전형·파비콘에 똑같이 적용합니다. 이 문서의 로고는 PDF를 보고 다시 그린 벡터이며, 최종 원본 패스는 제작 시 확정합니다.
02

폰트: 기본은 일반 고딕

  • 본문·제목·버튼·입력·메뉴·배지는 노토 산스 KR(또는 IBM Plex Sans KR)로 만듭니다.
  • 디스플레이 36/46·600, 타이틀 22/30·600, 헤딩 16/24·600, 본문 15/27·400, UI 14/20·500, 캡션 12/16·400.
  • 식별자는 IBM Plex Mono 12.5/20. 픽셀 표현은 로고와 확장 그래픽에 한정합니다.
03

브랜드 그래픽: 완성도 유지

  • 겹친 레트로 창, 픽셀 커서, 따뜻한 오렌지 음영을 보존하고 업무 폼에는 확장하지 않습니다.
  • 마스코트와 실제 기업 로고는 쓰지 않습니다. 장식 창의 버튼은 실제 조작 요소가 아닙니다.
  • 참고 이미지는 비주얼 기준이며 편집 가능한 벡터 원본이 아닙니다. 작은 글자는 이 규칙의 값을 우선합니다.

면 · 여백 · 컴포넌트 제작 기준

01

면으로 구분

  • 사이드바 #FAFAFB / 캔버스·패널 #FFFFFF / 카드 #F8F9FA / 쉘 #F3F4F6.
  • 운영 화면(대시보드~AI 운영)도 문의 화면과 같은 캔버스(크림) 바탕과 아래쪽 오렌지 번짐을 씁니다. 회색 쉘 바탕은 쓰지 않습니다.
  • 화면 모드 전환(예: Ticket / AI 해결)은 회색 바 대신 알약 버튼 둘로 만듭니다. 선택은 연한 오렌지 면 + 1.5px #C2540A 테두리, 비선택은 흰 면 + 1px 회색 테두리.
  • 흰 면 위의 흰 카드에만 #E5E7EB 링을 씁니다. 입력 경계는 접근성을 위해 #6B7280을 씁니다.
  • 카드 모서리 16, 버튼·메뉴 12, 패널 20, 칩 8, 배지·전송 999px. 활성 메뉴는 흰 면과 약한 그림자.
02

변형과 상태

  • 버튼은 주요·보조·고스트·아이콘. 기본·호버·눌림·초점·비활성·로딩을 모두 만듭니다.
  • 입력은 기본·입력됨·초점·오류·비활성·읽기 전용. 라벨을 유지하고 오류를 필드와 연결합니다.
  • 채팅은 비어 있음·입력 중·전송 중·실패·오프라인. 실패하면 원문을 유지하고, 한글 조합 중 Enter 전송은 막습니다.
03

정보와 피드백

  • 배지는 일곱 처리 상태와 긴급도를 분리합니다. 읽지 않은 수는 0 숨김, 99+ 표시, 미확인은 0으로 추정하지 않습니다.
  • 카드·탭·내비·상세 패널은 기본·선택·초점·로딩·오류·빈 상태를 함께 만듭니다.
  • 채움 버튼·숫자 배지는 #E56E1B(흰 글자 3.2:1이라 굵은 라벨 전용), 링크·텍스트는 #C2540A.
  • #F37321은 브랜드 장식, 흰 글자 버튼은 #C2540A. 상태는 색과 글자를 함께 쓰고 터치 영역은 44px를 확보합니다.
06 · 개발 전달

상태 · 반응형 · 개발 전달 기준

API와 서버 필드는 아직 확인되지 않았으므로 아래 매핑은 구현 가정입니다. 실제 계약을 먼저 확인합니다.

01

티켓과 인터랙션

  • 기본 흐름은 접수 → 담당자 배정 → 처리 중 → 해결 완료. 추가 답변 필요는 처리 단계 안의 답변 대기입니다. 해결 확인 대기는 담당자 처리 완료 후 문의자의 해결 확인을 기다리는 표시이며, 문의자가 확인하면 해결 완료가 됩니다.
  • 번호는 접수번호(ITssue 내부, 예: RCPT-1041)와 Jira Ticket 번호(생성 후 연결, 예: ITSD-1520)를 구분해 표시합니다.
  • 재배정은 담당 변경 이벤트로 보존합니다. 과거 이력을 지우거나 단순한 진행률 후퇴로 그리지 않습니다.
  • 서버 응답으로 상태를 확정합니다. 전송에 실패하면 중복 요청을 막고, 입력을 유지하고, 다시 시도할 수 있게 합니다.
02

반응형과 접근성

  • 데스크톱: 사이드바 248px + 유동 채팅 + 상세 440px. 공간이 부족하면 상세는 오버레이로 띄웁니다.
  • 모바일: 한 열, 여백 20~24px, 상세는 전체 화면, 브랜드 장식은 줄입니다. 입력 글자는 최소 16px.
  • 좁은 화면의 서랍: 사이드바(860px 이하)와 상세 패널(1180px 이하)은 본문 위로 올라오고, 배경은 비치지 않는 흰색으로 둡니다. 뒤 화면은 40% 어두운 막으로 덮습니다. 데스크톱의 반투명 유리 면은 서랍에서 쓰지 않습니다.
  • 좁은 화면의 진행 단계: 단계 아래 보조 글(담당자·시각)은 숨기지 않고 10.5px로 줄여 두 줄까지 접어서 보여줍니다.
  • Safari: backdrop-filter는 -webkit-backdrop-filter를 함께 씁니다. color-mix()가 필요한 면에는 대체 색을 먼저 적습니다.
  • 키보드 초점·라벨·오류 안내·명도 대비·200% 확대를 확인하고, 모달을 닫으면 초점을 되돌립니다.
03

React / FastAPI 매핑 (가정)

  • StatusBadge ← ticket.status / urgency, TicketStepper ← status + events, ThreadItem ← unread_count?.
  • TicketDetailPanel ← GET /tickets/{id} (가칭). 인증·읽음·첨부·실시간은 기존 계약을 먼저 확인합니다.
  • 기존 API를 바꾸기보다 adapter로 연결합니다. 로고·아이콘 SVG, 토큰, 상태별 컴포넌트, 화면을 함께 전달합니다.
