# 프로토타입·디자인 가이드 기준 전달사항 (임시 파일, 확인 후 삭제)

작성일 2026-10-22 · 기준: `design/ITssue-Prototype.html`, `design/ITssue 디자인 가이드.html`
화면이 먼저 바뀐 부분을 담당자별로 알립니다. 요청이 아니라 참고인 항목은 (참고)로 표시했습니다.
프로토타입의 숫자는 예시 데이터이고 API·DB는 붙어 있지 않습니다.

---

## 문서 담당자 (docs/09 대화 상태 정의)

1. **입력창 잠금 (참고)**
   접수 초안 확인 단계와 담당자 처리 완료 뒤 해결 확인 단계에서도 잠금 기능이 필요할 것 같습니다. 프로토타입에 반영해 두었습니다.
   (docs/09 T23은 초안 단계에서 글을 쓰면 안내만 한다고 되어 있습니다.)
2. **응답 없음 (참고)**
   종료 10분 전 안내는 문서(T28) 그대로이고, 화면에서는 입력창 위 띠로도 보여 줍니다. 종료 시점의 안내 문구는 화면에서 보여 주는 문구입니다.
3. **긴급 건 안내 (참고)**
   연결 거절(T17)과 접수 취소(T22) 모두 아래 문구를 보여 주도록 해 두었습니다. 문구를 정할 때 참고해 주세요.
   > 긴급 징후가 있었어요. 의심스러운 링크·첨부파일은 더 열지 마시고, 계정 정보는 어디에도 입력하지 마세요. 문제가 계속되면 IT 헬프데스크 내선 1000으로 연락해 주세요.

## API 담당자 (docs/07, docs/api)

1. **대시보드·통계**
   화면은 대시보드(지금 할 일)와 통계(기간·구역별 조회)를 나눈 형태입니다. 구조는 담당자께서 새로 정해 주시면 이후 화면을 맞춰 수정하겠습니다. 화면이 보여 주는 값은 다음과 같습니다.
   - 관리자 대시보드: RDY·WIP·FIN 건수, 연동·배정 확인 대상, 긴급·높음 미해결(P1·P2 중 CLS 아님) 건수와 3건
   - 담당자 대시보드: 새 답변이 온 문의 건수, 먼저 볼 문의 3건
   - 통계: 내·팀 접수 추이(일·주·월), 개인 현황 도넛, 팀·분류 진행도, 긴급도 분포
2. **추이 기준 (질문)**
   `trend.closedCount`가 접수일 기준(그날 접수된 티켓 중 지금 CLS)인지, 종료 시각(`closed_at`) 기준인지 정해 주세요. 화면은 지금 접수일 기준으로 표시합니다.

## 백엔드 담당자 (docs/06 테이블)

1. **새 답변 데이터 (질문)**
   담당자 대시보드의 "새 답변이 온 문의 건수"에는 "문의자가 답을 남겼고 담당자가 아직 안 본" 상태가 필요합니다. 이 값을 담을 칸이 있는지 확인해 주세요.
