## 문서 담당자 (PRD · docs/09)

1. **입력창 잠금 (확인)**
   docs/09는 초안 단계도 입력창을 끄는 것으로 바뀌었습니다. PRD(선택지 단계의 입력창)는 "프로토타입은 시연용 버튼을 두었으므로 이 단계에서도 입력이 가능하다"고 적혀 있는데, 프로토타입은 서버 규칙과 같게 이 단계의 입력창을 잠가 두었습니다. PRD 문장을 프로토타입도 잠근다는 내용으로 고쳐 주세요.
2. **응답 없음 (확정 반영)**
   5시간(해결 확인)·2시간(대화 이탈) 안내 문구는 PRD 예시 그대로 화면에 넣었습니다. 아래 결정을 docs/09 6.5에 반영해 주세요.
   - 초안 단계에도 2시간을 씁니다. 초안을 만들고 확인하지 않은 채 2시간이 지나면 안내하고, 돌아오면 팝업을 보여 줍니다.
   - 팝업에서 "새로운 문의하기"를 고르면 이전 문의는 바로 끝내고 삭제합니다(보안·로그 대상은 숨김).
   - 5시간과 2시간은 단계로 나뉘어(답변 뒤=5시간, 그 밖=2시간) 겹치지 않으며, 겹치면 5시간을 따릅니다.
   - 아직 정해지지 않은 것: 안내 뒤 실제 삭제까지의 대기 시간, 삭제 뒤 문의 행(미확인)을 남길지.
3. **민감정보 안내 (참고)**
   docs/10 6.1의 안내 문구(비밀정보, 비밀번호 추가 안내, 고유식별·금융, 근거 차단)를 프로토타입과 프론트 mock에 반영했습니다. 프론트 `mask.ts`도 2.3 규칙(A·B 등급 찾기, C 등급·0x 예외)에 맞췄습니다. 문구나 규칙이 바뀌면 알려 주세요.

## API 담당자 (docs/07, docs/api)

1. **대시보드·통계**
   화면은 대시보드(지금 할 일)와 통계(기간·구역별 조회)를 나눈 형태입니다. 구조는 담당자께서 새로 정해 주시면 이후 화면을 맞춰 수정하겠습니다. 담당자·관리자 화면의 변경안(`design/대시보드_티켓현황_변경안.md`)이 확정되면 필요한 값을 다시 정리하겠습니다.
2. **추이 기준 (질문)**
   `trend.closedCount`가 접수일 기준(그날 접수된 티켓 중 지금 CLS)인지, 종료 시각(`closed_at`) 기준인지 정해 주세요. 화면은 지금 접수일 기준으로 표시합니다.
