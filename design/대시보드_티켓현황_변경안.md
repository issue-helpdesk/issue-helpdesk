## 0. 요약

변경의 핵심은 **기간별로 돌아보는 화면(대시보드)과 오늘 처리할 일을 모아 보는 화면(운영현황)을 분리**하는 것이다. 현재는 두 역할이 A02 대시보드에 섞여 있다.

| 화면 | 현안 | 변경안 |
| --- | --- | --- |
| 담당자 T02 | 상태 타일 3개 + 새 답변 띠 + 처리할 문의 3건 | 검색·동기화 추가, 상태 카드 4개, 「답변 대기중」 신설, 우리 팀 현황 추가 |
| 관리자 A02 대시보드 | 연동·배정 확인 띠, 상태 4단계, 긴급·높음 미해결 | 기간 기준 화면으로 정리. 긴급·연동 등 당일 처리 건은 운영현황으로 이동 |

# Part 1. 담당자 페이지

## 1. T02 내 담당 문의

### 1.1 현안 (프로토타입 v2)
1. 머리말: 「지금 처리할 일」 안내 문구
2. 상태 타일 3개: 처리 대기(RDY)·처리 중(WIP)·해결 확인 대기(FIN). 내가 담당자인 ticket만 집계하며 종결(CLS)은 없다
3. 새 답변 알림 띠: 문의자가 새로 답변한 문의 N건
4. 처리할 문의 최대 3건: RDY·WIP인 내 ticket. 새 답변 → 긴급도 → 접수 오래된 순
5. 통계 안내 카드: 추이·분포는 통계 화면에서 확인

손볼 점
- 새 답변이 0건이어도 알림 띠가 계속 표시된다.
- 목록이 3건으로 고정이라 처리 중이 8건이어도 3건만 보인다.
- 기한·SLA 표시가 없다. SLA 기준은 아직 정하지 않았다.
- 왼쪽 메뉴 배지(12)는 RDY+WIP+FIN 합계인데 집계 기준 설명이 화면에 없다.

### 1.2 변경안

| # | 영역 | 내용 | 사유 |
| --- | --- | --- | --- |
| 1 | 검색·동기화 | 접수번호, ITHD 번호, 이름, 제목으로 검색. 마지막 동기화 시각과 **새로고침 버튼**(누르면 Jira와 바로 동기화) 표시. 기본은 1분마다 자동 동기화 | 전화로 번호만 전달받는 경우가 있음. 실시간 동기화가 어려워 자동 + 수동 방식으로 함 |
| 2 | 상태 카드 4개 | 처리 대기(RDY)·처리 중(WIP)·처리 완료(FIN)·종결(CLS) 건수. 카드를 누르면 해당 상태 목록으로 이동. 카드마다 가장 오래된 건의 경과 시간 표시 | CLS까지 노출하고, 장기 미처리 건을 바로 파악하기 위함 |
| 3 | 답변 대기중 | 「답변·회신 대기」와 「문의자 확인 대기」를 「답변 대기중」 하나로 통합. ITssue의 「새 답변 알림」은 삭제 | 문의자와는 Jira 댓글·멘션으로 소통하고 새 댓글 알림도 Jira에서 수신하므로 |
| 4 | 먼저 볼 문의 (3건) | 긴급도 높은 순 → 새 댓글 있는 순 → 오래된 순. 전체는 「모두 보기」. 기한은 예시 값(P1 4시간, P2 1일, P3 2일, P4 5일) | 기한과 함께 보여 처리 우선순위를 판단하기 쉽게 |
| 5 | 우리 팀 현황 (간소화) | 소속 담당 그룹만 한 줄 요약: 근무·부재 인원, 담당 그룹의 처리 대기·처리 중 건수, 담당자 없는 문의 수. 팀원별은 「팀원별 보기」 | 팀 상황은 가볍게 보여주고 화면 복잡도는 낮추기 위함 |

### 1.3 정할 것
- Jira 댓글 알림으로 새 답변 띠를 대체해도 되는지 (알림 누락 대비책 포함)
- 기한(SLA) 기준 값. 현재는 예시이며 팀 기준이 필요하다.
- 「답변 대기중」을 카드로 둘지, 목록 탭으로만 둘지

# Part 2. 관리자 페이지

## 2. A02 대시보드

### 2.1 현안 (프로토타입 v2)
1. 연동·배정 확인 띠: 확인이 필요한 문의 N건, 최대 3건 표시. 0건이면 숨김
2. 처리 현황 4단계: 처리 대기·처리 중·해결 확인 대기·연동·배정 확인 (전체 ticket 기준)
3. 긴급·높음 미해결: P1·P2 중 CLS가 아닌 문의. 합계와 상위 3건
4. 통계 안내 카드

10.22 팀 논의(협의 중)와의 차이

| 항목 | 현재 | 논의 | 정할 것 |
| --- | --- | --- | --- |
| 상태 카드 | 4단계 (연동·배정 확인이 띠와 카드에 중복) | 5개 (전체·RDY·WIP·FIN·CLS) | 전체·CLS 추가 여부 |
| 기간 필터 | 없음 (기간은 통계에서 선택) | 연도·월 필터 추가 | 대시보드에 둘지, 통계에만 둘지 |
| Jira 동기화 | 표시 없음 | 주기 + 수동(새로고침), 마지막 동기화 시각 표시 | 버튼·시각 위치, 주기 |
| 티켓 운영 영역 | 긴급·높음 미해결 목록이 대시보드에 있음 | 대시보드에서 분리 | 목록을 남길지, 옮길지 |
| 범위 | 운영 현황 요약 4구역 | 간략하게 | 구역 수 |

### 2.2 변경안

| # | 영역 | 내용 |
| --- | --- | --- |
| 1 | 기간 필터 | 연간·월간·기간 지정 중 선택하고 연·월을 바꿀 수 있다. 대시보드의 모든 수치가 선택한 기간 기준으로 바뀐다. 마지막 Jira 동기화 시각과 새로고침 버튼(바로 동기화)을 함께 표시. 기본은 1분마다 자동 동기화 |
| 2 | 처리 현황 5개 카드 | 전체, 처리 대기(RDY), 처리 중(WIP), 처리 완료(FIN), 종결(CLS) 건수. 카드를 누르면 전체 문의(A03)에 같은 상태·기간 조건이 적용된다. 긴급·연동·보안 알림 등 당일 처리 건은 모두 운영현황으로 이동 |
| 3 | 담당 그룹별 처리 현황 | 같은 기간 기준으로 담당 그룹별 상태별 건수와 종결률. 업무가 몰리는 담당 그룹을 파악하는 용도. 접수 추이·분류별 진행도는 통계에서 확인 |
| 4 | 긴급도별 접수 | 같은 기간의 P1~P4 접수 건수를 막대로 표시. 오늘 기준 긴급 건은 운영현황에서 확인 |

### 2.3 정할 것
- 기간 필터를 대시보드에 둘지 (논의 단계에서 미결)
- 「전체」「종결」 카드 추가 여부
- 담당 그룹별 종결률 산정 기준 (접수 기준인지, 종결 시점 기준인지)

## 3. A06 운영현황 (기존 「연동·배정 확인」)

### 3.1 현안 (프로토타입 v2)
1. 머리말: 「확인이 필요한 접수예요」. Jira 이슈 생성이나 담당자 배정이 끝나지 않은 문의
2. 접수 카드 윗줄: 접수번호·제목·문의자·담당 그룹·긴급도, 오른쪽에 Jira 배지·배정 배지
3. 사유 · 다음 조치 · 확인 담당 · 경과 (4줄)
4. 중복 생성 경고: Jira 생성 여부를 확인 중일 때만 표시
5. 조치 버튼: [Jira 생성 확인·재시도], [담당자 지정], [상세]

손볼 점
- [담당자 지정] 모달 목록이 그룹 구성원 전원이며, 부재 여부와 업무량이 표시되지 않는다.
- 한 건씩만 처리할 수 있다.
- 이 상태는 시연 도구의 오류 시나리오를 켜야 발생하며, 실제 Jira 호출은 없다.
- A03의 「연동·배정 예외 재처리」가 이 화면으로 이동했다. A03 ↔ Jira 연동 명세와 API 계약서가 정해지면 키값과 사유 문구를 다시 맞춰야 한다.

### 3.2 변경안

| # | 영역 | 내용 |
| --- | --- | --- |
| 1 | 오늘 기준 필터 | 기간은 「오늘」로 고정하고 담당 그룹으로 좁혀 볼 수 있다. 마지막 Jira 동기화 시각과 **새로고침 버튼**(바로 동기화)을 함께 표시한다. 메뉴 이름을 「연동·배정 확인」에서 **「운영현황」** 으로 변경 |
| 2 | 긴급 조치 필요(P1) · 당일 미종결 예외 | 왼쪽: 오늘 접수된 P1 중 처리 대기·처리 중인 건. 오른쪽: P1·P2인데 접수 당일 안에 종결되지 않은 예외 건. 보안·감사 알림은 별도 메뉴가 있어 제외 |
| 3 | Ticket 연동 확인 | Jira Ticket이 생성되지 않은 건을 한 건 한 줄로 표시. 긴급도 → 오래된 순 정렬. 줄마다 막힌 단계(접수 → Jira 생성 → 담당자 배정, 빨간 점이 막힌 단계), 원인, 경과 시간 표시. [확인]을 누르면 ① Jira에서 찾기 ② 결과 기록 창이 열린다. 3건까지 표시하고 나머지는 「전체 보기」 |
| 4 | 담당자 배정 확인 | Jira Ticket은 생성됐으나 담당자가 비어 있는 건. 선택한 줄의 담당 그룹 현황이 아래 「담당자 현황」에 표시된다. [지정]을 누르면 사유 입력 창이 열린다. 잘못된 그룹으로 접수된 건은 담당 그룹·분류를 변경할 수 있게 할 계획 |
| 5 | 담당자 현황 | 선택한 배정 건의 그룹 구성원을 같은 화면에 표시: 오늘 근무·부재(등록한 연차·반차 일정 기준 자동 표시, 연차/반차 구분 표기, 반차는 해당 시간대에만 부재), 처리 대기·처리 중 건수, Jira 계정 연결. 업무량이 적은 근무자를 「추천」으로 맨 위에 표시. 상단 칩으로 다른 그룹도 조회 가능, 숫자는 근무 인원/전체 인원 |

**담당자 지정 창 (변경안):** 담당자 현황에서 [지정]을 누르면 열린다. 근무·부재, 업무량, Jira 계정 연결을 다시 보여주고 **지정 사유를 필수로** 입력받는다. 부재자에게 예외로 배정할 때도 동일하다.

### 3.3 정할 것
- 「운영현황」 명칭과 「오늘 기준」 고정이 적절한지
- 담당 그룹·분류 변경 기능의 범위 (재배정 규칙과 함께 결정)
- 「추천」 순서를 자동배정 규칙(`docs/11.Jira_티켓_담당자_배정_로직.md` 2.4)과 동일하게 할지

### 3.4 부재 정보 반영 범위

부재 정보는 `time_off` 표(연차·반차 일정)에서 가져온다. 표 구조와 등록 권한, 반차 기준은 `docs/11.Jira_티켓_담당자_배정_로직.md` 3.1을 따른다.

| 화면 | 반영 | 내용 |
| --- | --- | --- |
| A06 운영현황 | 반영 | 담당자 현황의 근무·부재, 담당자 지정 창의 부재 표시. 구성원 목록(RF-04)에 `onLeave` 필요 |
| T02 내 담당 문의 | 반영 | 「우리 팀 현황」의 근무·부재 인원. 같은 출처를 쓴다 |
| A02 대시보드 | 반영 안 함 | 기간 기준 처리 건수 집계라 부재 정보가 필요 없다 |
| 연차·반차 일정 등록 화면 | 신규 | 담당자 본인은 내 일정, 관리자는 구성원별 일정, 팀장은 자기 그룹 구성원 일정을 등록·수정. 유형(연차/오전 반차/오후 반차) 선택. 대시보드가 아닌 별도 화면이며 위치(메뉴)는 정해야 한다 |

팀장이 부재인 날의 「팀장 확인」 알림을 대신 받을 대리 확인자는 두지 않는다(범위 제외, `docs/11` 6.2).

## 4. A03 티켓 현황

- 별도 변경안 시안은 없으며 현안 화면(전체 문의 목록)을 그대로 쓴다.
- 이번 변경으로 달라지는 점
  - 대시보드 상태 카드(2.2의 2번)를 누르면 A03이 상태·기간 조건이 적용된 채로 열린다.
  - 「연동·배정 예외 재처리」는 이미 A06으로 이동했다.
- 정할 것: A03 필터에 기간 조건이 있는지 확인한다.

현재 `frontend`에는 담당자·관리자 대시보드와 Ticket 목록 화면이 없다. 로그인, FAQ, 문의(ChatView·DraftCard·NewInquiryView·TicketCard) 화면만 있다. 따라서 이 문서는 기존 코드의 수정안이 아니라 **신규 화면의 기준안**이다. 시안의 건수와 이름은 시연용 데이터다.
