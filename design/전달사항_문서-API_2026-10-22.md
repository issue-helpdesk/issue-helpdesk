# 프로토타입·디자인 가이드 기준 전달사항 (문서·API·프론트)

작성일 2026-10-22 · 작성 배경: docs 06~09와 `docs/api/`를 프로토타입과 비교한 결과입니다.
화면(프로토타입·디자인 가이드)이 최신 기준이고, 아래는 문서·API·프론트가 맞춰 주면 좋은 내용입니다.

표기: **확정** = 화면에서 이미 결정해 반영함 · **제안** = 팀 확인이 필요함

## 1. 모두에게: 챗봇 버튼 문구 (확정)

버튼에 쓰는 **문구**는 화면이 정합니다. API는 `nextActions`·`action` 같은 **코드와 의미**만 맞으면 되고, 문구까지 같을 필요는 없습니다.
다만 문서 표와 프론트 mock에 옛 문구가 적혀 있어 헷갈리므로, 예시 문구를 아래로 바꾸거나 "예시 문구"라고 표시해 주세요.

| 자리 | 옛 문구 | 새 문구 |
| --- | --- | --- |
| AI 답변 뒤 | 해결됐어요 / 아직 안 돼요 (아직 해결되지 않았어요) | **해결 / 미해결** |
| 담당자 연결 제안 | 담당자 연결하기·연결할게요 / 연결하지 않을게요·연결 안 할게요 | **담당자 연결 / 미연결 (종료)** |
| 접수 초안 카드 | 이 내용으로 접수하기 / 수정할게요 / 접수하지 않을래요(접수하지 않을게요) | **접수 / 수정 / 미접수 (종료)** |
| 해결 확인 카드(티켓) | 해결됐어요 / 아직 해결되지 않았어요 | **해결 / 미해결** (+ 상세 보기) |

- 누른 버튼 문구는 그대로 내 말풍선으로 남습니다.
- "계속 해볼게요" 버튼은 없앴습니다. 답변 뒤·연결 제안 단계는 입력창을 끄므로 이어서 쓸 곳이 없습니다 (docs/09 6.3 ③과 같은 결정).
- 문의자 화면에는 `RDY·WIP·FIN·CLS` 같은 상태 코드를 쓰지 않고 한글 상태 이름만 씁니다 (담당자·관리자 화면은 코드를 함께 씁니다).

## 2. M5 김현우 · M1 박민경: 대시보드와 통계 분리 (제안)

### 2.1 왜 나누나
`OP-01 /dashboard/overview`가 `totals·byCategory·byUrgency·byGroup·byMember·trend`를 한 번에 줍니다. 대시보드는 가장 자주 여는 화면인데 통계용 집계까지 매번 부르게 됩니다. 화면은 이렇게 나눴습니다.

- **대시보드**: 지금 확인할 일과 현재 건수만. 첫 진입 요청을 요약 1개로 줄이는 것이 목표입니다.
- **통계**: 기간·대상을 골라 추이·분포·진행도를 보는 화면. 열 때만 부르고, 구역마다 따로 불러옵니다. 구성원별은 팀·분류를 누를 때, 개인 현황은 이름을 누를 때만 부릅니다. 한 구역이 실패해도 나머지는 보이고 그 구역만 다시 불러옵니다.

요약을 하나로 묶는 것과 서버 집계 부하가 줄어드는 것은 다릅니다. 부하는 미리 집계해 두기·짧은 캐시·인덱스 같은 별도 대책이 필요합니다.

### 2.2 화면이 필요로 하는 값 (지금 API에 없거나 부족한 것)

| 화면 | 필요한 값 | 지금 |
| --- | --- | --- |
| 관리자 대시보드 | 처리 대기(RDY)·처리 중(WIP)·해결 확인 대기(FIN) 건수 | OP-01 `totals`에 RDY가 없음 (`byGroup`에만 있음) |
| 관리자 대시보드 | **연동·배정 확인 대상 최대 3건**과 전체 건수 | TK-05 필터로 가능하지만 한 번에 받으려면 요약에 포함 필요 |
| 관리자 대시보드 | **긴급·높음 미해결** 건수와 대상 3건 (P1·P2 중 CLS가 아닌 것, 기한·SLA와 무관) | 없음 (`byUrgency`는 전체 접수 건수) |
| 담당자 대시보드 | 내 처리 대기·처리 중·해결 확인 대기 건수 | OP-02 `me` (RDY·WIP·FIN·CLS) |
| 담당자 대시보드 | **새 답변이 온 문의 건수** (상태별 건수와 겹칠 수 있어 합계 아님) | 없음 |
| 담당자 대시보드 | **먼저 볼 문의 3건** (새 답변 우선, 긴급도 순) | TK-05로 가능 |
| 담당자 통계 | **내·팀 접수 추이** (일·주·월) | OP-02에 추이 없음 |
| 담당자·관리자 통계 | **개인 현황(분류별 도넛)** — 이름을 눌렀을 때 | `byMember`는 WorkCounts뿐 |
| 통계 | 팀별·분류별 진행도, 긴급도 분포(P1~P4 전체, 배정 전 포함) | OP-01 `byGroup`·`byCategory`·`byUrgency` |

### 2.3 제안 구조 (주소 이름은 예시)
- `GET /dashboard/summary` — 대시보드용 한 번 응답(위 표의 건수·대상 3건·새 답변 건수)
- 통계는 구역별: 상태·AI 해결 요약 / 접수 추이 / 팀·분류 진행도 / 구성원별(팀·분류 선택 시) / 개인 현황(이름 선택 시) / 긴급도 분포
- 공통 Query는 기존 `from·to·interval`을 그대로 쓰되 아래 범위에 맞춥니다.

### 2.4 통계 기간·단위 (확정, API와 맞춤)
- 화면의 조회 기간은 **오늘 / 최근 30일 / 최근 1년**, 집계 단위는 **일·주·월**입니다. "전체"와 "연별"은 API 범위(최대 1년, `DAY·WEEK·MONTH`)를 벗어나 뺐습니다.
- 오늘은 단위가 없고 건수만 보여 줍니다. 30일=일·주, 1년=주·월.

### 2.5 확인이 필요한 정의
1. **`trend.closedCount`의 기준**: 접수일 기준(그날 접수된 티켓 중 지금 CLS)인지, 종료 시각 기준(`closed_at`)인지. 화면은 지금 "접수일 기준 해결 완료(CLS)"로 표시합니다. 종료 시각 기준 추이나 평균 처리 시간은 `finished_at`·`closed_at`·`ticket_status_history`로 낼 수 있으므로 필요하면 별도로 정해 주세요.
2. **확인 필요(`needsAdmin`)** 에 `transition_status = NEEDS_ADMIN`이 들어갑니다. 지금 화면은 Jira 연동과 배정 두 가지만 보여 줍니다. 상태 변경이 Jira에 반영되지 않은 건(반영 확인 중 `PENDING`, 확인 필요 `NEEDS_ADMIN`)을 화면에 어떻게 보일지는 화면 쪽에서 따로 정해 알려 드리겠습니다.
3. **AI 해결**은 티켓이 없는 문의라 CLS와 합산하지 않습니다 (화면도 따로 표시, OP 공통 규칙과 같음).

## 3. 화면에서 이미 문서와 맞춘 것 (참고)
- 입력창: 답변 뒤(`answered`)·연결 제안(`offer`) 단계에서 끕니다 (docs/09 1장). 질문·초안은 켭니다.
- 응답 없음: 종료 10분 전 시스템 메시지 "추가 문의사항이 없으면 채팅을 종료하겠습니다." (docs/09 T28), 2시간 뒤 답변 뒤는 미확인, 그 밖의 단계는 대화만 끝나고 문의는 진행 중 유지 (T15·T24). 시연 도구에 "응답 없음 시연"을 추가했습니다.
- 긴급 건 연결 거절·접수 취소: 행동 안내 + IT 헬프데스크 내선 1000 안내와 보안 신호 기록 (docs/09 3.4).
- 접수번호 `RCPT-` + 4자리, 출처 표시는 문서번호+위치(과거 사례는 "과거 처리 사례 참고").

화면이 쓰는 새 문구(문서에 적을 때 참고)
- 종료 안내: 추가 문의사항이 없으면 채팅을 종료하겠습니다.
- 답변 뒤 종료: 일정 시간 응답이 없어 상담을 종료했어요. 해결된 것으로 처리하지 않았어요.
- 그 밖의 단계 종료: 일정 시간 응답이 없어 대화를 마쳤어요. 문의는 진행 중으로 남아 있고, 이어서 쓰거나 버튼을 누르면 같은 단계부터 계속돼요.
- 긴급 거절 안내: 긴급 징후가 있었어요. 의심스러운 링크·첨부파일은 더 열지 마시고, 계정 정보는 어디에도 입력하지 마세요. 문제가 계속되면 IT 헬프데스크 내선 1000으로 연락해 주세요.

## 4. 프로토타입 한계 (예시 데이터)
- 프로토타입의 모든 숫자·추이는 예시 데이터이며 화면에 "프로토타입용 예시 데이터"라고 적었습니다. 최근 1년 값은 최근 30일 예시를 바탕으로 만든 임의의 값입니다.
- 실제 API·DB는 붙어 있지 않고, 요청 횟수나 속도는 측정하지 않았습니다.
