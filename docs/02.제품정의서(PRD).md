## 1. 프로젝트 개요

**ITssue HelpDesk**는 사내 IT 문의를 AI Agent가 이해하고, 사내 Guide를 기반으로 1차 대응하는 서비스이다.

AI만으로 해결하기 어렵거나 실제 담당자의 조치가 필요한 문의는 **담당자 배정을 제안하고, 사용자의 확인을 거쳐 Jira Ticket으로 연결**한다.

PRD에서는 기획서에서 정의한 서비스 방향을 바탕으로 **ITssue가 제공해야 하는 기능, 제품 정책 및 MVP 범위**를 정의한다.

> 프로젝트의 기획 배경, 서비스 목표 및 기대효과는 **프로젝트 기획서**에서 정의한다.

## 2. Target User

### 👤 일반 임직원

IT 문제를 문의하고 AI로부터 해결 방법을 안내받는다.

AI만으로 해결되지 않는 경우 담당자 연결을 요청하고, 이후 처리 상태와 결과를 확인한다.

### 🛠 IT 운영 담당자

AI가 해결하지 못했거나 실제 조치가 필요한 Ticket을 전달받아 처리한다.

배정된 Ticket의 상태를 변경하고 처리 결과를 등록한다.

IT 운영 담당자 역시 일반 임직원으로서 ITssue의 문의 기능을 사용할 수 있다.

### ⚙️ 관리자

전체 문의 및 Ticket 현황을 관리하고 사용자·권한·Guide를 관리한다.

Ticket 담당자를 확인·변경할 수 있으며, 담당자가 해결한 사례를 검토하여 새로운 Guide로 활용할 수 있다.

관리자 역시 일반 임직원 및 IT 운영 담당자의 기능을 사용할 수 있다.

## 3. 서비스 범위

### 3.1 IT 문의 Category

ITssue는 다음 **7개 Category**의 IT 문의를 대상으로 한다.

| Category | 주요 범위 |
| --- | --- |
| 계정·로그인 | 계정, SSO, MFA, 로그인 오류 |
| 접근권한 | 사내 시스템·개발 서버 권한 신청·변경·회수 |
| VPN·네트워크 | VPN, 사내망, Wi-Fi, 네트워크 장애 |
| SW·라이선스 | 업무용 SW 설치·실행·업데이트, 라이선스 |
| HW·업무 PC | PC, 노트북, 모니터, 주변기기, 장비 교체·수리 |
| 사내 시스템 | 그룹웨어, ERP 등의 접속 오류·성능 저하·장애 |
| 정보보안 | 피싱, 악성코드·EDR, 계정 도용, 장비 분실, 보안 예외·정책 |

각 Category별로 사내 IT 환경을 가정한 Guide를 구축하여 RAG Knowledge로 활용한다.

### 3.2 핵심 서비스 Flow

```
로그인 / 사용자 확인
        ↓
      IT 문의
        ↓
   문의 명확성 확인
        ↓
   필요 시 추가 질문
        ↓
      통합 검색
Guide + 과거 유사 Ticket
        ↓
 문의 유형·긴급도 분류
        ↓
    처리 방향 판단
      ↙        ↘
 AI 답변 가능    담당자 처리 필요
      ↓              │
근거 기반 AI 답변     │
      ↓              │
  해결 여부 확인      │
    ↙     ↘       │
  해결     미해결 ────┘
   ↓              ↓
  종료       담당자 배정 제안
                  ↓
              사용자 선택
                  ↓
              Ticket 초안
                  ↓
             사용자 확인·수정
                  ↓
             Jira Ticket 생성
                  ↓
               담당자 처리
                  ↓
          RDY → IP → FIN
                  ↓
             문의자 해결 확인
                  ↓
                 CLS
```

> **Ticket은 AI의 판단만으로 즉시 생성하지 않는다.**
> 
> 
> 담당자 배정을 사용자가 선택하고 Ticket 초안을 확인한 후 Jira Ticket을 생성한다.
>

## 4. 핵심 기능 및 제품 정책

### 4.1 IT 문의 접수 및 명확성 확인

사용자는 자연어로 IT 문의를 입력할 수 있다.

AI는 먼저 문의 내용이 처리에 충분한지 확인하고, 필요한 정보가 부족한 경우 추가 질문을 진행한다.

필요한 정보가 확보되면 관련 정보를 검색하고, **검색 결과와 문의 내용을 바탕으로 문의 유형과 긴급도를 판단**한다.

---

### 4.2 통합 검색

AI는 문의 해결에 필요한 정보를 찾기 위해 **사내 Guide와 과거 유사 Ticket을 검색**한다. 

사내 Guide는 RAG 검색을 통해 관련 근거를 찾으며, 사용자의 부서와 접근 권한을 고려하여 **사용자가 접근 가능한 Guide만 검색 대상**으로 사용한다.

과거 유사 Ticket은 이전에 발생한 유사 문의와 처리 사례를 참고하기 위해 활용한다.

검색 결과는 문의 유형·긴급도 판단 및 AI 답변의 근거로 활용한다.

충분한 근거를 찾지 못한 경우 임의로 답변을 생성하지 않고 **담당자 처리 대상으로 판단한다.**

AI 답변에는 사용한 Guide의 출처를 제공한다.

---

### 4.3 처리 방향 판

AI는 문의 내용, 검색 결과, Category 및 긴급도를 바탕으로 **AI가 답변할 수 있는 문의인지, 담당자의 처리가 필요한 문의인지 판단**한다.

충분한 근거를 기반으로 안내할 수 있는 경우 AI가 답변을 제공한다.

실제 시스템 조치, 권한 변경, 담당자의 판단이 필요하거나 충분한 답변 근거를 확보하지 못한 경우 **담당자 처리 대상으로 판단**한다.

담당자 처리 대상으로 판단되더라도 Jira Ticket을 즉시 생성하지 않으며, **사용자에게 담당자 배정을 제안**한다.

---

### 4.4 해결 여부 확인

**AI 답변 이후** 사용자에게 실제 문제가 해결되었는지 확인한다.

- **해결** → AI 자체 해결로 종료
- **미해결** → 담당자 배정 제안
- **미확인** → 일정 시간 응답이 없는 경우 `미확인` 상태로 Chat Session 종료

종료된 Session의 문의 및 대화 이력은 유지하며, 사용자는 이후 해당 문의를 다시 열어 대화를 이어갈 수 있다.

> 
> 
> 
> **미확인 문의를 일정 시간 이후 자동 완료 처리할지 여부와 기준 시간은 미확정 사항**으로 관리한다.
> 
> 문의 상태값과 세부 전환 조건은 **SRS 요구사항 정의서**에서 정의한다.
> 

---

### 4.5 담당자 연결 및 Ticket 생성

사람의 판단·승인 또는 실제 시스템 조치가 필요한 경우 AI가 직접 해당 업무를 수행하지 않는다.

AI 답변 후 문제가 해결되지 않았거나 처리 방향 판단에서 담당자 처리가 필요하다고 판단한 경우 사용자에게 **담당자 배정을 제안**한다.

기본 Flow는 다음과 같다.

> **담당자 배정 제안 → 사용자 선택 → Ticket 초안 → 사용자 확인·수정 → Jira Ticket 생성**
> 

사용자가 담당자 배정을 원하지 않는 경우 Jira Ticket을 생성하지 않으며 해당 문의는 미해결 상태로 종료한다. AI는 사용자의 최종 확인 없이 Jira Ticket을 임의로 생성하지 않는다.
Ticket에는 문의 내용과 함께 담당자 처리에 필요한 사용자·문의 정보를 포함한다.

---

### 4.6 Jira 연동 및 Ticket 처리

사용자가 Ticket 초안을 최종 확인하면 Jira Ticket을 생성한다.

Jira에서는 **담당자 또는 담당 그룹을 지정**하고 실제 업무 처리를 수행한다.

기본 Ticket 처리 상태는 다음과 같다.

**RDY → IP → FIN → CLS**

- `RDY` : 담당자 처리 대기
- `IP` : 담당자 처리 중
- `FIN` : 담당자 처리 완료 / 문의자 해결 확인 대기
- `CLS` : 문의자 해결 확인 완료 / Ticket 최종 종료

담당자가 처리를 완료하여 `FIN` 상태가 된 후 문의자가 문제가 해결되었음을 확인하면 `CLS` 상태로 변경한다.

Jira를 Ticket 처리 상태의 기준으로 사용하며, ITssue는 필요한 상태 및 처리 결과를 연동한다.

담당자 또는 관리자는 필요한 경우 Ticket 담당자를 변경할 수 있다.

Jira 연동 방식, 실패 처리 및 중복 생성 방지 등의 세부 사항은 **시스템 설계서**에서 정의한다.

---

### 4.7 Slack 알림

담당자 처리로 전환된 문의의 주요 Ticket 진행 상황을 Slack을 통해 안내한다.

일반 임직원에게는 **Ticket 접수, 주요 처리 상태 및 처리 결과**를 안내한다.

Ticket이 `FIN` 상태가 된 경우 처리 결과와 해결 내용을 안내하고, **문의자가 해결 여부를 확인할 수 있는 경로를 제공**한다.

IT 운영 담당자에게는 Ticket 배정 및 처리와 관련된 정보를 안내한다.

담당자와 문의자 사이의 추가적인 Slack 양방향 소통은 MVP 진행 상황에 따라 검토한다.

---

### 4.8 Guide 관리

관리자는 사내 IT Guide를 등록하고 관리할 수 있다.

지원하는 Guide 문서 Format은 **PPTX / PDF / DOCX**로 제한한다.

등록된 Guide는 RAG Knowledge로 활용할 수 있도록 처리한다.

**기존 Guide만으로 해결되지 않아 담당자에게 전달된 문의가 최종적으로 해결된 경우, 관리자는 해당 해결 사례를 검토하여 새로운 Guide로 활용할 수 있다.**

```
Ticket 처리 완료
      ↓
관리자 검토
      ↓
Guide 등록 여부 결정
      ↓
Guide 등록
      ↓
RAG Knowledge 반영
```

Guide의 문서 Format, Parsing·Chunking·Embedding 방식 등 세부 기술 구조는 **시스템 설계서**에서 정의한다.

---

### 4.9 사용자 및 권한 관리

관리자는 사용자 계정을 등록하거나 상태 및 권한을 변경할 수 있다.

신규 입사, 부서 이동, 권한 변경, 퇴사 등의 상황을 고려하여 사용자의 소속 및 접근 권한을 관리한다.

사용자의 권한 정보는 Guide 검색 범위를 제한하는 데 활용한다.

세부 권한 Level과 접근 정책은 별도로 정의한다.

---

### 4.10 관리자 및 Dashboard

관리자는 전체 서비스 운영 현황을 확인할 수 있다.

주요 확인 대상은 다음과 같다.

- 전체 문의 현황
- AI 자체 해결 및 담당자 이관 현황
- Category별 문의 현황
- Ticket 처리 현황
- 담당자별 처리 현황
- 사용자 및 권한
- Guide

IT 운영 담당자는 자신의 Ticket 및 처리 현황을 확인할 수 있다.

*SLA 및 세부 운영 지표는 기준 확정 후 추가한다.*

---

### 4.11 Logging (검토)

**※ 본 기능의 적용 범위 및 필요성은 멘토 검토 후 확정한다.**

사용자의 문의와 AI 처리 과정, 담당자 연결 및 Ticket 처리 과정에서 주요 활동을 기록한다.

특히 접근권한 및 정보보안과 같이 추적이 필요한 문의는 Ticket이 생성되지 않고 종료되더라도 필요한 범위에서 문의 및 처리 이력을 남길 수 있도록 한다.

Logging 대상과 저장 항목 등 세부 기준은 **SRS 요구사항 정의서 및 시스템 설계서**에서 정의한다.

## 5. 공통 정책

### AI는 근거 없이 답변하지 않는다

충분한 검색 근거가 없는 경우 임의로 답변하지 않고 **담당자 처리 대상으로 판단한다.**

### AI가 사람의 권한을 대신하지 않는다

승인, 권한 부여·변경 등 실제 사람이 수행해야 하는 업무를 AI가 임의로 실행하지 않는다.

### 사용자 확인 없이 Ticket을 생성하지 않는다

담당자 처리가 필요하다고 판단하더라도 바로 Jira Ticket을 생성하지 않는다.

### Ticket 생성은 해결 완료가 아니다

Jira Ticket 생성은 **업무 접수 및 담당자 이관**을 의미하며 실제 처리 완료와 구분한다.

### 사용자 권한에 따라 검색 범위를 제한한다

사용자가 접근할 수 없는 Guide는 RAG 검색 및 AI 답변의 근거로 사용하지 않는다.

# 6. MVP Scope

## 6.1 MVP 목표

이번 MVP에서는 다음 **End-to-End Flow가 실제로 동작하는 것**을 핵심 목표로 한다.

> **로그인 → IT 문의 → 문의 명확성 확인 → 필요 시 추가 질문 → 통합 검색 → 문의 유형·긴급도 분류 → 처리 방향 판단 → AI 답변 또는 담당자 처리 → 해결 여부 확인 → 필요 시 담당자 배정 제안 → Ticket 초안 → 사용자 확인 → Jira 생성 → 담당자 처리 → 문의자 해결 확인 → Ticket 종료**
> 

MVP는 AI가 모든 IT 업무를 자동화하는 것이 아니라, **AI가 해결 가능한 문의와 사람의 조치가 필요한 문의를 구분하고 실제 HelpDesk 업무까지 연결할 수 있는지를 검증하는 것**에 초점을 둔다.

---

## 6.2 Must Have

MVP에서 반드시 동작해야 하는 기능이다.

| 영역 | MVP 구현 범위 |
| --- | --- |
| 사용자 | 로그인 및 사용자 정보·부서·권한 확인 |
| 문의 | 자연어 IT 문의 접수 |
| 추가 질문 | 문의 정보가 부족한 경우 필요한 정보 추가 확인 |
| 통합 검색 | 사내 Guide 및 과거 유사 Ticket 검색 |
| 권한 기반 RAG | 사용자 권한에 따라 검색 가능한 Guide 제한 |
| 분류 | 검색 결과와 문의 내용을 기반으로 7개 IT Category 및 긴급도 판단 |
| 처리 방향 판단 | AI 답변 가능 여부 또는 담당자 처리 필요 여부 판단 |
| AI 답변 | Guide 근거 기반 답변 및 출처 제공 |
| 해결 확인 | AI 답변 후 실제 해결 여부 확인 |
| 담당자 배정 | 미해결 또는 실제 조치가 필요한 경우 담당자 배정 제안 |
| Ticket 초안 | 문의 내용과 수집 정보를 기반으로 초안 생성 |
| 사용자 확인 | Ticket 확인·수정 및 최종 생성 여부 선택 |
| Jira | 확인된 Ticket을 Jira에 생성 |
| Ticket 처리 | `RDY → IP → FIN → CLS` 상태로 Ticket 처리 및 종료 |
| 상태 확인 | Ticket 처리 상태 및 결과 확인 |
| Evaluation | Golden Set 기반 AI / RAG 평가 |
| Session | 미응답 시 Chat Session 종료 및 문의·대화 이력 유지·재개 |

# 8. 평가

ITssue MVP는 **핵심 End-to-End Flow의 정상 동작 여부**와 **AI / RAG 품질**을 기준으로 평가한다.

| 평가 영역 | 평가 내용 |
| --- | --- |
| End-to-End | AI 자체 해결 Scenario와 담당자 처리 Scenario가 처음부터 끝까지 정상 동작하는지 확인 |
| 문의 명확성 확인 | 문의 정보가 부족한 경우 필요한 추가 질문을 적절하게 제공하는지 평가 |
| 문의 분류 | 문의 Category 및 긴급도 판단의 적절성 평가 |
| 검색 | 문의와 관련된 Guide 및 과거 유사 Ticket 검색 결과 평가 |
| AI 답변 | 검색된 근거를 기반으로 적절한 답변과 출처를 제공하는지 평가 |
| 처리 방향 판단 | AI 답변 또는 담당자 처리 방향을 적절하게 판단하는지 평가 |
| 권한 | 사용자 권한에 따라 허용된 Guide만 검색·활용되는지 확인 |

**AI / RAG 품질은 Golden Set을 기반으로 평가하고, 시스템 기능 및 End-to-End Flow는 Test Case를 기반으로 검증한다.** 세부 평가 지표와 목표 수치는 별도의 **Test & Evaluation 자료**에서 관리한다.
