## 1. 문서 개요

본 문서는 PRD에서 정의한 ITssue의 제품 범위를 기반으로, 시스템이 충족해야 하는 **기능 요구사항과 비기능 요구사항**을 정의한다.

각 요구사항에는 고유 ID와 우선순위를 부여하여 개발 및 테스트 과정에서 동일한 기준으로 추적한다.

> 프로젝트의 기획 배경과 서비스 목표는 **프로젝트 기획서**, 제품 범위와 MVP는 **제품 정의서(PRD)**에서 정의한다.
> 

### 1.1 요구사항 ID 규칙

기능 요구사항은 `[기능 영역]-[번호]`, 비기능 요구사항은 `NFR-[영역]-[번호]` 형식으로 관리한다.

### 1.2 우선순위

| 우선순위 | 기준 |
| --- | --- |
| **Must** | 핵심 MVP End-to-End Flow에 반드시 필요한 요구사항 |
| **Should** | 핵심 Flow 이후 우선적으로 구현할 요구사항 |
| **Could** | 일정 및 핵심 기능 완성도에 따라 추가할 요구사항 |

우선순위는 PRD의 MVP Scope와 동일한 기준을 사용한다.

# 4. 상태 정의

## 4.1 문의 처리 상태

: ITssue의 문의 상태는 **AI 문의 처리 과정**과 **담당자 이관 여부를 기준**으로 관리한다.

| 상태 | 의미 |
| --- | --- |
| `진행 중` | AI가 문의 내용을 확인하고 처리 중인 상태 |
| `AI 해결` | AI 답변 후 사용자가 문제가 해결되었음을 확인한 상태 |
| `미확인` | AI 답변 후 사용자의 해결 여부 확인 없이 Chat Session이 종료된 상태 |
| `미해결 종료` | 문제가 해결되지 않았으나 사용자가 담당자 배정을 선택하지 않아 종료된 상태 |
| `담당자 이관` | 사용자가 담당자 배정 및 Ticket 생성을 확인하여 담당자 처리 단계로 전환된 상태 |

사용자가 일정 시간 응답하지 않을 경우 **Chat Session은 종료**한다. **단, 문의 및 대화 이력은 유지하며 사용자는 이후 해당 문의를 다시 열어 대화를 이어갈 수 있어**야 한다.

**AI 답변 후** **사용자가 해결 여부를 확인하지 않은 경우** 해당 문의는 **`미확인`** 상태로 관리한다. 미확인 문의를 일정 시간 이후 자동 완료 처리할지 여부와 기준 시간은 제품 정책 확정 후 반영한다.

담당자에게 이관된 문의는 **Chatbot에서는 `담당자 이관` 상태로 종료**한다. 이후 **실제 처리 과정은 Jira Ticket 상태를 기준으로 관리하며, 주요 진행 상황과 처리 결과는 Slack을 통해 문의자에게 안내**한다.

## 4.2 Ticket 처리 상태

: 담당자에게 이관되어 Jira Ticket이 생성된 문의는 다음 상태로 관리한다.

| 상태 | 의미 |
| --- | --- |
| `RDY` | Ticket이 생성되어 담당자 처리를 기다리는 상태 |
| `IP` | 담당자가 Ticket을 처리 중인 상태 |
| `FIN` | 담당자의 처리가 완료되어 문의자의 해결 확인을 기다리는 상태 |
| `CLS` | 문의자가 문제가 해결되었음을 확인하여 Ticket 처리가 최종 종료된 상태 |

기본 Ticket 상태 Flow는 다음과 같다.

**`RDY → IP → FIN → CLS`**

`FIN`은 **담당자의 처리 완료**, `CLS`는 **문의자의 해결 확인까지 완료된 최종 종료 상태**를 의미한다.

Ticket의 실제 처리 상태는 Jira를 기준으로 관리하며, ITssue는 필요한 상태 및 처리 결과를 연동하여 사용자에게 제공한다.

# 5. 평가 및 검증

: ITssue는 **AI / RAG 품질과 시스템 기능을 구분하여 평가 및 검증**한다.

## 5.1 Golden Set 평가

: Golden Set은 AI 및 RAG의 판단 품질을 평가하기 위한 **정답이 정의된 평가 데이터셋**이다.

| 평가 영역 | 주요 검증 내용 |
| --- | --- |
| 문의 분류 | 문의에 **적절한 Category 및 긴급도를 판단**하는지 평가 |
| 통합 검색 | 문의와 **관련된 Guide 및 과거 유사 Ticket을 검색**하는지 평가 |
| 처리 방향 판단 | **AI 답변 또는 담당자 처리 방향을 적절하게 판단**하는지 평가 |
| AI 답변 | **검색된 근거를 기반으로 적절한 답변과 출처를 제공**하는지 평가 |

Golden Set의 세부 평가 지표 및 목표 수치는 별도의 **Test & Evaluation 자료**에서 관리한다.

## 5.2 Test Case 검증

: Test Case는 시스템의 개별 기능과 End-to-End Flow가 SRS의 요구사항대로 동작하는지 검증하기 위한 **기능 테스트 시나리오**이다.

주요 검증 대상은 다음과 같다.

- 사용자 및 권한에 따른 기능 동작
- 문의 접수 및 추가 질문
- 통합 검색 및 AI 답변
- 담당자 배정 제안 및 사용자 선택
- Ticket 초안 확인 및 Jira Ticket 생성
- Ticket 상태 `RDY → IP → FIN → CLS` 처리
- Slack을 통한 Ticket 진행 상태 및 처리 결과 안내
- AI 해결 Scenario 및 담당자 처리 Scenario의 End-to-End 동작

> **AI / RAG 품질은 Golden Set을 기반으로 평가하고, 시스템 기능 및 End-to-End Flow는 Test Case를 기반으로 검증한다.**
>

# 6. 요구사항 추적

각 요구사항은 Requirement ID를 기준으로 구현 기능 및 Test Case와 연결한다.

```
PRD 기능
   ↓
SRS Requirement ID
   ↓
구현 기능 / API
   ↓
Test Case
   ↓
검증 결과
```

이를 통해 요구사항의 구현 여부와 테스트 결과를 추적한다.

---

제품 정책 및 기능 범위와 관련된 미확정 사항은 **제품 정의서(PRD)**에서 통합 관리한다.

구현 기술과 관련된 세부 결정 사항은 **시스템 설계서** 에서 관리한다.
