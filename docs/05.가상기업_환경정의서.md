## 1. 문서 개요

본 문서는 ITssue 프로젝트에서 사용하는 **가상 기업의 조직, 사용자 및 사내 IT 환경을 정의**한다.

ITssue는 실제 기업 내부 데이터가 아닌 본 문서에서 정의한 가상 환경을 기반으로 구현하며, 해당 환경은 **사용자·조직·권한, Knowledge Guide, IT 문의 및 Ticket Scenario 구성의 공통 기준**으로 사용한다.

> 제품 범위와 정책은 **제품 정의서(PRD)**, 시스템 요구사항은 **소프트웨어 요구사항 명세서(SRS)**, 구현 방식은 **시스템 설계서**, Category별 RAG용 사내 Guide는 **Knowledge Guide**에서 정의한다.

# 4. 사용자 및 역할

가상 기업의 사용자는 다음 역할을 기준으로 구성한다.

| 역할 | 정의 |
| --- | --- |
| **일반 임직원** | 사내 IT 서비스를 이용하고 문의를 등록하며, 접수·처리 상태와 결과를 확인하는 사용자 |
| **IT 운영 담당자** | 담당 업무에 따라 배정된 Ticket을 처리하는 사용자. 일반 임직원의 문의 기능도 이용한다. |
| **관리자** | 권한 범위 내에서 사용자·Guide·접수·배정을 관리하고, 연동·배정 예외를 확인하는 사용자 |

역할은 별도 인원을 추가하는 구분이 아니라 기존 임직원에게 부여하는 **ITssue 서비스상의 권한**이다.

사용자의 소속 부서·역할·개별 권한에 따라 열람 가능한 Guide·문의·Ticket·상담 이력이 달라진다. **ITssue 관리자 역할이 실제 사내 시스템의 접근권한 승인·부여 권한을 자동으로 의미하지는 않는다.**

서비스데스크의 접수 확인 역할과 분야별 담당 그룹의 배정 관리 역할을 구분하며, 구체적인 관리자 지정은 사용자 데이터에서 관리한다.

> 역할별 기능과 권한 범위는 **PRD·SRS**, 실제 시스템 권한 신청·승인 절차는 **Knowledge Guide**에서 정의한다.
> 

**Guide 열람 등급과 역할**

✏️ Knowledge Guide(`dataset/guides_final`)는 열람 범위 3단계로 구분하며, 사용자의 역할에 따라 열람 가능한 Guide가 달라진다.

| 열람 범위 | 열람 등급 | 열람 대상 | 대상 문서 |
| --- | --- | --- | --- |
| `ALL` | 사내 일반 | 전 임직원 (일반 임직원·IT 운영 담당자·관리자) | 임직원용 가이드, 공통 기준 |
| `AGENT` | 사내 제한 | IT 운영 담당자·관리자 | 담당자용 매뉴얼, AI 응대 정책 |
| 🆕 `ADMIN` | 관리자 전용 | 관리자 | 열람 범위가 지정되지 않은 문서·과거 이력의 기본값, 관리자만 봐야 하는 문서 |

> 열람 등급 표시만으로 접근이 제한되지 않는다. 백엔드가 사용자 권한으로 검색·답변·출처를 제한한다. 외부 모델 전송 허용 여부는 열람 등급과 별도로 판단한다.
>
> 🆕 외부 전송 정책은 허용(`ALLOWED`) · 마스킹 후 허용(`MASKED`) · 금지(`BLOCKED`) 3가지이다. 열람 범위와 전송 정책이 지정되지 않았거나 불명확하면 가장 제한적인 값(`ADMIN`·`BLOCKED`)을 적용한다.
>

# 5. 사내 IT 환경

## 5.1 업무 PC 및 Network

- 회사 지급 Windows / macOS Notebook 사용
- 개발 직군은 Windows / macOS 중 선택, 그 외 직군은 Windows 기본
- 업무 PC 교체 주기 **3년**
- 사내 유선 LAN 및 Wi-Fi 사용
- 재택·외부 접속 시 VPN 사용
- 개인 기기는 Guest Wi-Fi만 사용하며 사내 시스템 접근 불가
- 개발 직군은 개발 Server·DB 및 사내 개발 환경 사용

## 5.2 계정 및 인증

| 항목 | 기준 |
| --- | --- |
| 통합 로그인 | SSO |
| 추가 인증 | MFA |
| 비밀번호 | 12자 이상 / 90일마다 변경 |
| 계정 잠금 | 로그인 5회 실패 시 잠금 |
| 잠금 해제 | 10분 후 해제 |
| 비밀번호 구성 | 4종류 문자 모두 포함, 최근 5개 재사용 불가 |
| 부서 이동 | 발령 다음 날 권한 자동 반영 |
| 퇴사 | 퇴사일 18시 계정 비활성화, 메일은 30일간 팀장에게 전달 |

🆕 **ITssue 서비스 계정:** ITssue는 사번과 비밀번호로 로그인하는 자체 로그인을 쓴다. (위 SSO는 회사 통합 로그인 환경이며, ITssue의 SSO 연동은 이후 확장이다.) 회원가입 기능은 없고, 신규 입사자는 관리자가 계정을 생성해 임시 비밀번호와 함께 제공하며 첫 로그인에서 비밀번호를 바꾼다. 계정 상태는 정상(`ACTIVE`) · 잠김(`LOCKED`, 5회 실패 시 잠기고 10분 후 해제) · 이용 제한(`INACTIVE`, 관리자 제한·퇴사)이다.

## 5.3 파일 및 주변기기

- 부서별 공유 Drive 사용
- 매일 Snapshot 저장 / **30일 보관**
- 층별 공용 복합기 사용

| 구분 | 환경 |
| --- | --- |
| **협업** | 사내 Mail, Messenger, 화상회의 |
| **Mail** | Mailbox 50GB / 첨부파일 25MB |
| **Groupware** | 조직도, 전자결재, Group Mail, IT 요청·권한 신청 |
| **업무 시스템** | ERP, 인사·근태 시스템 |

ITssue는 IT 문의 접수와 담당자 연결 창구로 사용하며, 담당자의 Ticket 처리는 Jira와 연결한다. **이번 프로젝트의 업무 알림 채널은 Slack으로 정한다.** ITssue의 접수·배정·처리 결과 알림 연동은 PRD의 Should 범위로 구현을 목표로 한다. *(Knowledge Guide에서 "사내 메신저 알림"으로 표기한 것은 이 Slack 알림을 뜻한다.)*

**IT 문의 창구**

| 창구 | 연락처·위치 | 이용 기준 |
| --- | --- | --- |
| ITssue 챗봇 | 사내 IT 포털 상단 [챗봇 문의] | 24시간. 모든 IT 문의의 기본 창구 |
| IT 헬프데스크 (서비스데스크) | 내선 1000 (평일 09:00~18:00) | 챗봇을 쓸 수 없을 때, 여러 사람이 함께 업무를 못 할 때, 본인 확인이 필요한 처리. **ITssue 내부 접수 저장이 실패했을 때의 대체 접수 경로** |
| 정보보안팀 | 내선 1119 | 링크 클릭·감염 의심·계정 도용·장비 분실 등 즉시 알려야 할 보안 문제 |
| 그룹웨어 IT 요청 | 그룹웨어 > IT 요청 (= 사내 IT 포털 [IT 요청]) | 권한 신청 등 승인이 필요한 요청. ITssue 접수는 이를 대체하지 않음 |

사내 IT 포털은 소프트웨어 센터, IT 요청, 내 요청 현황, 장애 공지, 챗봇 문의를 모아 둔 사이트이다. 세부 연락처와 운영 기준은 Knowledge Guide의 **IT-STD-001 IT 서비스 운영 기준**을 따른다.

기존 Groupware의 권한 신청·전자결재 기능은 유지한다. **ITssue Ticket 접수는 필요한 승인 절차를 대체하지 않는다.**

# 7. 정보보안 환경

가상 기업은 다음과 같은 기본 정보보안 환경을 운영한다.

- 백신 / EDR
- 정보유출방지(DLP)
- Web·Mail 보안
- 비밀번호 관리자
- MFA
- USB·파일 반출 및 보안 예외 정책
- 회사 승인 생성형 AI 사용

위 보안 제품은 **가상 기업의 운영 환경으로 가정하며, ITssue의 직접 구현 범위에 포함하지 않는다.**

임직원은 생성형 AI에 기밀정보와 비밀번호·MFA 인증값·API Key 등의 비밀정보를 입력하지 않는다. **사내 정보의 열람 권한과 외부 서비스 전송 허용 여부는 구분**한다.

Guide와 ✏️ 과거 이력에는 열람 범위와 외부 전송 정책을 적용한다. 구체적인 접근·전송·민감정보 보호 방식은 **PRD·SRS·시스템 설계서**에서 정의한다.

피싱·악성코드·계정 도용·장비 분실 등 보안 사고 의심 문의는 정보보안팀이 확인한다. 실제 사고 여부와 필요한 조치는 담당자가 판단한다.

# 8. IT 지원 조직

사내 IT HelpDesk는 **IT운영·보안** 조직이 담당하며, 문의 영역에 따라 전문 담당 조직이 지원한다.

| 담당 조직 | 주요 지원 영역 |
| --- | --- |
| **서비스데스크** | 계정·로그인 및 일반 IT 문의 |
| **엔드포인트지원팀** | HW·업무 PC / SW·라이선스 |
| **네트워크팀** | VPN·네트워크 |
| **시스템인프라팀** | Server·DB·File Server·SSO·Mail |
| **업무시스템팀** | 사내 시스템 및 접근권한 |
| **정보보안팀** | 정보보안 |

담당 그룹은 카테고리를 기본 기준으로 추천하되, **대상 시스템과 요청 업무에 따라 조정**한다.

예를 들어 SSO 로그인 문의의 기본 안내는 서비스데스크가 담당하지만, SSO 서비스 장애는 시스템인프라팀이 담당할 수 있다. 접근권한 문의도 업무시스템 권한과 Server·DB·File Server 권한에 따라 담당 조직이 달라질 수 있다.

개인 자동배정을 위해 담당자 데이터에는 **소속 그룹·처리 가능한 업무·배정 가능 여부·Jira 사용자 식별정보**를 관리한다.

담당 그룹이 불명확하거나 Jira 접수 연결에 문제가 있는 경우 서비스데스크·관리자가 확인한다. 담당 그룹은 확정되었으나 개인 후보가 없거나 배정에 실패한 경우 해당 그룹의 관리자가 확인·재배정한다.

> 개인 선정과 예외 처리 규칙은 **별도 배정 기준·SRS**, 기술 연동 복구 책임자는 운영 기준 확정 시 지정한다. Category별 해결·승인 절차는 **Knowledge Guide**에서 정의한다.

| **담당자** | IT운영·보안 조직, 처리 가능 업무, 배정 가능 여부 및 Jira 식별정보 |

실제 기업의 임직원 정보, 내부 시스템 정보 및 실제 Ticket Data는 사용하지 않는다.
