# ITssue API 계약서 (초안 v0.1)

> 백엔드 · 프론트엔드 · Jira 연동이 같은 이름과 값으로 데이터를 주고받기 위한 약속입니다.
> 노션 S3 "키값 정합성 — 변경·협의 항목"의 '변경 제안'을 정리했습니다. **팀 확인 전 제안**이며, 항목 번호(#)는 노션 표 번호와 같습니다.

## 0. 원칙

1. **기준 이름은 06 테이블 설계서의 DB 컬럼 이름**입니다. API JSON 은 같은 단어를 camelCase 로 씁니다 (`target_system` → `targetSystem`).
2. 대소문자 변환은 백엔드 응답 모델에서 자동으로 합니다. 손으로 쓰는 대응표는 두지 않습니다. (#25)
   ```python
   # 백엔드 공통 응답 모델 (FastAPI 도입 시)
   from pydantic import BaseModel, ConfigDict
   from pydantic.alias_generators import to_camel

   class ApiModel(BaseModel):
       model_config = ConfigDict(alias_generator=to_camel, populate_by_name=True)
   ```
3. **코드 값도 DB 값 그대로**(영문) 주고받습니다. 한글은 화면 라벨표(`frontend/src/api/catalog.ts`, 역할은 `core/roles.ts`)에서만 붙입니다.
4. 우리가 정하지 않는 이름(Jira 필드 ID·필드명, 과거 데이터셋 CSV 컬럼명)과 화면 문구는 그대로 둡니다. 변환은 Jira 어댑터와 이관 스크립트 한 곳에서만 합니다.
5. ID 와 표시용 이름은 짝으로 줍니다: `groupId`·`groupName`, `assigneeId`·`assigneeName`.
6. 목록(배열)은 복수형 이름을 씁니다: `urgencyReasons`, `sources`.
7. 시각은 모두 ISO 8601(`+09:00`)입니다. '어제' 같은 표시는 프론트가 계산합니다. (#27)

## 1. 응답 형식 (#26)

```jsonc
// 성공
{ "ok": true, "data": { ... } }
// 실패. message 는 사용자에게 그대로 보여 줄 수 있는 한국어 문구
{ "ok": false, "error": { "code": "ACCOUNT_LOCKED", "message": "…", "lockedUntil": "2026-10-19T14:20:00+09:00" } }
```

- 문의 대화 동작(메시지·빠른 응답·초안 수정·접수·해결 확인 등)은 **갱신된 `Inquiry` 전체**를 `data` 로 돌려줍니다.

|---|---|---|

| `ACCOUNT_LOCKED` | 로그인 5회 실패로 잠김 (#4) | `lockedUntil` |
| `ACCOUNT_INACTIVE` | 이용 제한 계정 (`account_status = INACTIVE`) (#4) | |

### ChatMessage · GuideSource (#24)

- `ChatMessage`: `id`, `role`(`user`·`assistant`·`staff`·`sys`), `text?`, `blocks?`, `sources?`, `legacy?`, `replies?`, `locked?`, `card?`, `from?`, `groupName?`, `kind?`, `createdAt?`
- 긴급 카드 블록: `{ type: 'urgent', groupName, urgency, urgencyReasons }`
- `GuideSource`: `{ docCode, title, version, section, excerpt }`. `version` 은 문자열(`v2`). 문의 화면·로그인 전 상담(`ConsultReply.sources`)·FAQ(`Faq.sources`)가 같은 형태를 씁니다.

### Faq · ConsultReply · InquirySummary

- `Faq`: `{ id(문서 코드, 예 FAQ-001), categoryCode, question, answer, sources: GuideSource[] }`
- `ConsultReply`: `{ paragraphs: string[], sources: GuideSource[] }`
- `InquirySummary`: `{ id, title, stateLabel, stateKind, unread, updatedAt }`
  - `stateKind`: `progress`·`assigned`·`received`·`resolved`·`ai`·`warn`·`needs_reply`·`reassigned`·`awaiting_confirm` (뒤의 셋은 SRS 보조 상태 값)

## 4. 상태 전환 (#16 · #20)

| 시점 | `workStatus` | `assignStatus` | `jiraSyncStatus` | 문의자 화면 |
|---|---|---|---|---|
| 접수 저장 직후 | null | PENDING | PENDING | 접수 완료 · 담당자 연결 중 |
| Jira 생성 성공 | RDY | PENDING | SYNCED | 접수 완료 · 담당자 연결 중 |
| 담당자 배정 | RDY | ASSIGNED | SYNCED | 처리 대기 (담당자 이름 표시) |
| Jira 생성 실패 | null | PENDING | NEEDS_ADMIN | **접수 완료 · 담당자 확인 중** (실패를 노출하지 않음) |
| 배정 실패 | RDY | NEEDS_ADMIN | SYNCED | **접수 완료 · 담당자 확인 중** |
| 처리 시작 | WIP | ASSIGNED | SYNCED | 처리 중 |
| 처리 결과 등록 | FIN | ASSIGNED | SYNCED | 해결 확인 대기 |
| 문의자 해결 확인 | CLS | ASSIGNED | SYNCED | 해결 완료 |

- 업무 상태는 Jira 생성 직후 RDY 가 되고, 배정 여부는 `assignStatus` 가 따로 나타냅니다. (배정 전 `workStatus = null` 이라는 기존 프론트 전제는 쓰지 않음)
- `finished_at` = Jira 웹훅의 FIN 전환 시각. 웹훅을 놓치면 동기화 때 Jira 변경 이력으로 보정합니다.
- `closed_at` = 문의자 '해결 확인' 요청 시각. 두 시각 모두 `ticket_status_history` 에도 기록합니다.
- 배지 값은 SRS 를 따릅니다: `needs_reply`(추가 답변 필요) · `reassigned`(재배정) · `awaiting_confirm`(해결 확인 대기). RDY 라벨은 '처리 대기'.

## 5. Jira 연동 (#5 · #6 · #14 · #17 · #29)

- `backend/app/integrations/jira/field_mapping.yaml` 의 키는 위 기준 이름을 씁니다. 과거 데이터셋 컬럼명은 각 필드의 `dataset_column` 에 남깁니다.
- 선택값의 키도 DB 영문 코드입니다 (예: `INCIDENT` → label '장애'). 한글 → 영문 변환은 과거 이관 스크립트에만 둡니다.
- API·AI 출력의 세부 유형은 `inquiryTypeCode`(예 `NET-02`)로 주고받고, 저장할 때 `inquiry_types.code` 로 찾아 `inquiry_type_id` 에 넣습니다.
- 접수 채널 `CHATBOT`(Jira 저장값 '챗봇')을 추가하고 ITssue 신규 접수의 기본값으로 씁니다. 신규 접수는 `tickets` 에 채널 컬럼이 없으므로 Jira 로 보낼 때 고정값으로 넣습니다.
- 문의자 이메일은 Jira 로 보내지 않습니다 (담당자 회신은 ITssue 메시지). 기획안 매핑표에서도 뺍니다.
- 담당자 실계정 3명은 `support_group_members.jira_account_id` 에 기입합니다. 계정 없는 담당자는 Jira 기본 담당자를 비우고 '처리 담당자' 글 칸에만 이름을 적습니다. (정책 합의 전 구현하지 않음)
