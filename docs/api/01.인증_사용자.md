## 0. 읽는 법

- 경로는 Base URL `/api/v1` 이후 부분이다.
- 표의 **컬럼**은 테이블 설계서의 컬럼이다. `(파생)`은 테이블 컬럼이 아닌 계산값이다.
- **null** 열: `Y`면 값이 없을 때 `null`을 준다.
- **공통 에러는 API별 표에서 생략한다.** 모든 인증 API에서 날 수 있는 에러:

| HTTP | code | 조건 |
|---|---|---|
| 401 | `UNAUTHORIZED` | 토큰 없음·잘못된 토큰 |
| 401 | `TOKEN_EXPIRED` | 토큰 만료 |
| 403 | `AUTH_ACCOUNT_INACTIVE` | 토큰 발급 이후 계정이 이용 제한됨 |
| 403 | `AUTH_PASSWORD_CHANGE_REQUIRED` | 임시 비밀번호 상태 (AU-03·AU-04·AU-02 제외 모든 API) |
| 422 | `VALIDATION_ERROR` | 입력값 검증 실패 |
| 429 | `TOO_MANY_REQUESTS` | 요청 횟수 제한 초과 |
| 500 | `INTERNAL_ERROR` | 서버 오류 |

## 2. 인증 (AU)

### AU-01 로그인

`POST /auth/login` · 권한: 공개 · 요구사항: USER-01·02

사번과 비밀번호로 로그인하고 Access Token을 발급한다.

**Request Body**

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| employeeNo | string | Y | `users.employee_no` | 1~20자 |
| password | string | Y | (`users.password_hash`와 대조) | 1~64자 |

```json
{
  "employeeNo": "E2024017",
  "password": "********"
}
```

**처리**

1. 사번으로 사용자를 찾는다. 없으면 `AUTH_INVALID_CREDENTIALS`.
2. `account_status = LOCKED`이고 `locked_until`이 지났으면 `ACTIVE`로 바꾸고 `failed_login_count = 0`으로 되돌린다.
3. `LOCKED`(해제 전)면 `AUTH_ACCOUNT_LOCKED`, `INACTIVE`면 `AUTH_ACCOUNT_INACTIVE`. 비밀번호가 맞아도 같다.
4. 비밀번호가 틀리면 `failed_login_count + 1`. 5가 되면 `account_status = LOCKED`, `locked_until = now() + 10분`으로 바꾸고 `AUTH_ACCOUNT_LOCKED`를 준다. 아니면 `AUTH_INVALID_CREDENTIALS`.
5. 성공하면 `failed_login_count = 0`, `last_login_at = now()`.
6. 잠금·이용 제한 계정 로그인 시도는 `audit_logs`에 남긴다 (`event_type = LOGIN_BLOCKED`).

**Response** `200 OK`

| 필드 | 타입 | 설명 |
|---|---|---|
| accessToken | string | `Authorization: Bearer {accessToken}`로 사용 |
| tokenType | string | 항상 `"Bearer"` |
| expiresIn | number | 만료까지 남은 초 |
| user | Me | 내 정보. `user.passwordChangeRequired = true`면 비밀번호 변경 화면으로 보낸다 |

```json
{
  "accessToken": "eyJhbGciOi...",
  "tokenType": "Bearer",
  "expiresIn": 3600,
  "user": {
    "id": 17,
    "employeeNo": "E2024017",
    "name": "김민지",
    "email": "minji.kim@itssue.example",
    "departmentId": 4,
    "department": { "id": 4, "name": "재무팀" },
    "position": "팀원",
    "serviceRole": "EMPLOYEE",
    "accountStatus": "ACTIVE",
    "passwordChangeRequired": false,
    "lastLoginAt": "2026-10-21T09:02:11+09:00",
    "supportGroups": []
  }
}
```

**Errors**

| HTTP | code | 조건 | details |
|---|---|---|---|
| 401 | `AUTH_INVALID_CREDENTIALS` | 사번 없음, 비밀번호 불일치 (구분하지 않음) | `null` |
| 403 | `AUTH_ACCOUNT_LOCKED` | 잠긴 계정, 또는 이번 실패로 5회가 됨 | `[{ "reason": "LOCKED_UNTIL", "message": "잠금 해제 시각", "value": "2026-10-21T14:13:00+09:00" }]` |
| 403 | `AUTH_ACCOUNT_INACTIVE` | 이용 제한 계정 | `null` |
| 422 | `VALIDATION_ERROR` | 필드 누락·길이 초과 | 필드별 |
| 429 | `TOO_MANY_REQUESTS` | 같은 IP의 로그인 시도 제한 초과 (기준 미결) | `null` |

```json
{
  "error": {
    "code": "AUTH_ACCOUNT_LOCKED",
    "message": "로그인 5회 실패로 계정이 잠겼습니다. 10분 후 다시 시도하거나 IT 헬프데스크(내선 1000)로 문의해 주세요.",
    "details": [
      { "reason": "LOCKED_UNTIL", "message": "잠금 해제 시각", "value": "2026-10-21T14:13:00+09:00" }
    ],
    "traceId": "9f1c2a7e-3b4d-4e5f-8a9b-0c1d2e3f4a5b"
  }
}
```

---

**인증 공통 보완**

비밀번호는 공백을 제거하거나 빈 문자열을 null로 바꾸지 않는다. AU-02·03·04는 임시 비밀번호 상태에서도 허용한다. 보호 API는 계정 상태와 현재 서비스 권한을 서버에서 재확인한다.

토큰 만료 시간·저장 방식은 미결이나 다음 의미는 필수이다: 로그아웃은 현재 세션을 무효화하고, 비밀번호 변경·관리자 재발급은 기존 세션 전체를 무효화한다. 비밀번호 변경 성공 후에는 다시 로그인한다. 계정 이용 제한·권한 하향은 이미 발급된 토큰에도 다음 요청부터 적용한다. 토큰 무효화 저장 구조(세션 저장소 또는 토큰 버전)는 인증 구현 전에 별도 확정한다.


### AU-02 로그아웃

`POST /auth/logout` · 권한: 로그인

현재 토큰을 무효화한다. 무효화 방식은 토큰 방식 결정에 따른다 (API 설계서 6장).

**Request Body** 없음

**Response** `204 No Content`

**Errors** 공통 에러만. 이미 만료된 토큰이면 `401 TOKEN_EXPIRED` (Frontend는 그대로 로그인 화면으로 보낸다).

### AU-04 비밀번호 변경

`PUT /users/me/password` · 권한: 로그인 · 요구사항: ADMIN-02

첫 로그인(임시 비밀번호)이거나 사용자가 직접 바꿀 때 쓴다. 임시 비밀번호 상태에서도 호출할 수 있다.

**Request Body**

| 필드 | 타입 | 필수 | 제약 |
|---|---|---|---|
| currentPassword | string | Y | 현재(또는 임시) 비밀번호 |
| newPassword | string | Y | 1.5 비밀번호 규칙 |

```json
{
  "currentPassword": "Tmp#4kd9QzP1",
  "newPassword": "New!Passw0rd"
}
```

**처리**: `password_hash` 갱신, `password_changed_at = now()`, `updated_at = now()`.

**Response** `204 No Content`

**Errors**

| HTTP | code | 조건 | details |
|---|---|---|---|
| 400 | `AUTH_CURRENT_PASSWORD_MISMATCH` | 현재 비밀번호 불일치 | `null` |
| 422 | `AUTH_PASSWORD_POLICY_VIOLATION` | 새 비밀번호가 규칙 위반 | `[{ "field": "newPassword", "reason": "TOO_SHORT", "message": "8자 이상 입력해 주세요." }]` 등 |
| 422 | `VALIDATION_ERROR` | 필드 누락 | 필드별 |

`AUTH_PASSWORD_POLICY_VIOLATION`의 `details[].reason`

| reason | message |
|---|---|
| `TOO_SHORT` | 8자 이상 입력해 주세요. |
| `TOO_LONG` | 64자 이하로 입력해 주세요. |
| `INVALID_VALUE` | 영문 대·소문자, 숫자, 특수문자 중 3종류 이상을 섞어 주세요. |
| `DUPLICATE` | 현재 비밀번호나 사번과 다른 값을 입력해 주세요. |

### US-02 계정 생성

**Request Body**

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| employeeNo | string | Y | `employee_no` | 1~20자, 중복 불가 |

| serviceRole | string | Y | `service_role` | `EMPLOYEE` / `AGENT` / `ADMIN` |

{
  "employeeNo": "E2026101",
  "name": "이도윤",
  "email": "doyun.lee@itssue.example",

### US-04 사용자 정보·상태 변경

`PATCH /users/{userId}` · 권한: ADMIN · 요구사항: ADMIN-02·04

보낸 필드만 바꾼다.

**Path**: `userId` (number)

**Request Body**

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| name | string | | `name` | 1~50자 |
| email | string | | `email` | 이메일 형식, 중복 불가 |
| departmentId | number \| null | | `department_id` | 있는 부서 |
| position | string \| null | | `position` | |
| serviceRole | string | | `service_role` | `EMPLOYEE` / `AGENT` / `ADMIN` |
| accountStatus | string | | `account_status` | `ACTIVE` / `INACTIVE`만. `LOCKED`는 서버만 설정 |
| slackUserId | string \| null | | `slack_user_id` | |
| reason | string | 조건부 | (`audit_logs.reason`) | `serviceRole`·`accountStatus`를 바꿀 때 필수. 1~500자 |

- `employeeNo`는 바꿀 수 없다 (`NOT_ALLOWED`).
- `LOCKED` 계정을 `ACTIVE`로 바꾸면 잠금을 푼다: `failed_login_count = 0`, `locked_until = null`.
- 상태·권한 변경은 `audit_logs`에 남긴다 (`event_type = USER_STATUS_CHANGE` / `USER_ROLE_CHANGE`, `reason`).

```json
{
  "accountStatus": "INACTIVE",
  "reason": "퇴사 (2026-10-31)"
}
```

**Response** `200 OK` — `User`

**Errors**
