## 0. 읽는 법

- 경로는 Base URL `/api/v1` 이후 부분이다.
- 표의 **컬럼**은 테이블 설계서의 컬럼이다. `(파생)`은 테이블 컬럼이 아닌 계산값이다.
- **공통 에러는 API별 표에서 생략한다**: `401 UNAUTHORIZED`, `401 TOKEN_EXPIRED`, `403 AUTH_ACCOUNT_INACTIVE`, `403 AUTH_PASSWORD_CHANGE_REQUIRED`, `422 VALIDATION_ERROR`, `429 TOO_MANY_REQUESTS`, `500 INTERNAL_ERROR`
- 참조 객체 `CategoryRef`·`GroupRef`·`UserRef`는 [02. 문의·상담](02.문의_상담.md) 2.1을 따른다.

## 1. 열람 범위

문서는 **현행 버전**(`document_versions.is_current = true`)의 `view_scope`로 열람 여부를 정한다.

| service_role | 볼 수 있는 view_scope |
|---|---|
| `EMPLOYEE` | `ALL` |
| `AGENT` | `ALL`, `AGENT` |
| `ADMIN` | `ALL`, `AGENT`, `ADMIN` |

- 열람 범위 밖 문서는 목록에서 빼고, 상세는 `404 DOCUMENT_NOT_FOUND`로 응답한다. 제목·문서 번호도 드러내지 않는다 (SRS GUIDE-06).
- ADMIN이 아닌 사용자에게는 **현행 버전이 있고 `is_active = true`인 문서만** 보인다.
- 열람 범위와 전송 정책 값이 없거나 불명확하면 `ADMIN`·`BLOCKED`로 본다 (SRS GUIDE-07).

### 1.1 버전 상태 `versionState` (파생)

SRS GUIDE-05의 현행·만료·초안을 컬럼으로 계산한다.

| versionState | 화면 | 조건 |
|---|---|---|
| `CURRENT` | 현행 | `is_current = true` |
| `DRAFT` | 초안 | 현행이 아니고 `activated_at is null` (한 번도 현행으로 사용하지 않음) |
| `EXPIRED` | 만료 | 현행이 아니고 `activated_at is not null` (과거 현행) |

### DC-02 문서 등록

`POST /documents` · 권한: ADMIN · 요구사항: GUIDE-01

문서 메타정보만 만든다. 파일은 DC-07로 버전을 올린다.

**Request Body**

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| docCode | string | Y | `doc_code` | `^IT-[A-Z]{2,4}-\d{3}(-M)?$`, 중복 불가 |
| docType | string | Y | `doc_type` | `GUIDE` / `MANUAL` / `STANDARD` |
| title | string | Y | `title` | 1~200자 |
| categoryCode | string \| null | 조건부 | `category_code` | `GUIDE`·`MANUAL`은 필수, `STANDARD`는 `null` |
| ownerGroupId | number | | `owner_group_id` | 있는 담당 그룹 |

```json
{
  "docCode": "IT-NET-004",
  "docType": "GUIDE",
  "title": "사내 Wi-Fi 접속 가이드",
  "categoryCode": "NET",
  "ownerGroupId": 5
}
```

**Response** `201 Created` — `Document` (`currentVersion = null`)

**Errors**

| HTTP | code | 조건 | details |
|---|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아님 | |
| 409 | `DOCUMENT_CODE_DUPLICATE` | 문서 번호 중복 | `docCode` / `DUPLICATE` |
| 422 | `VALIDATION_ERROR` | 형식 오류, `GUIDE`인데 `categoryCode` 없음(`REQUIRED`), `STANDARD`인데 있음(`NOT_ALLOWED`), 없는 코드·그룹(`NOT_FOUND`) | 필드별 |

### DC-07 새 버전 업로드

`POST /documents/{documentId}/versions` · 권한: ADMIN · 요구사항: GUIDE-01·05·07

`Content-Type: multipart/form-data`. 폼 필드 이름도 camelCase이다.

**Form Data**

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| file | file | Y | (`file_path`, `file_format`) | `.pdf` `.docx` `.pptx` `.md` `.txt`. 크기 제한 미결 |
| version | string | Y | `version` | 1~20자. 같은 문서 안에서 중복 불가. 예: `v1.3` |
| viewScope | string | | `view_scope` | 기본 `ADMIN` |
| transferPolicy | string | | `transfer_policy` | 기본 `BLOCKED` |

```
POST /api/v1/documents/3/versions
Content-Type: multipart/form-data; boundary=----X

------X
Content-Disposition: form-data; name="file"; filename="IT-NET-001_v1.3.pdf"
Content-Type: application/pdf
(binary)
------X
Content-Disposition: form-data; name="version"

v1.3
------X
Content-Disposition: form-data; name="viewScope"

ALL
------X
Content-Disposition: form-data; name="transferPolicy"

ALLOWED
------X--
```

**처리**: 파일 저장 → `document_versions`(`is_current = false`, `ingest_status = PENDING`, `registered_by` = 요청자) 생성 → 적재(파싱·청킹·임베딩)를 백그라운드로 시작. 끝나면 `DONE`, 실패하면 `FAILED`·`ingest_error`. **현행 전환은 자동으로 하지 않는다** (DC-09).

**Response** `202 Accepted` — `DocumentVersion` (`ingestStatus = PENDING`). DC-08로 적재 상태를 확인한다.

**Errors**

| HTTP | code | 조건 | details |
|---|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아님 | |
| 404 | `DOCUMENT_NOT_FOUND` | 문서 없음 | |
| 409 | `DOCUMENT_VERSION_DUPLICATE` | 같은 `version`이 있음 | `version` / `DUPLICATE` |
| 413 | `DOCUMENT_FILE_TOO_LARGE` | 파일 크기 초과 | `[{ "field": "file", "reason": "OUT_OF_RANGE", "message": "최대 크기", "value": "20MB" }]` |
| 415 | `DOCUMENT_FILE_FORMAT_UNSUPPORTED` | 지원하지 않는 확장자·형식 | `file` / `INVALID_VALUE` |
| 422 | `VALIDATION_ERROR` | `file`·`version` 없음, enum 값 오류 | 필드별 |

### DC-09 현행 전환·정책 변경

`PATCH /documents/{documentId}/versions/{versionId}` · 권한: ADMIN · 요구사항: GUIDE-05·07

보낸 필드만 바꾼다.

**Request Body**

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| isCurrent | boolean | | `is_current` | `true`만. `ingest_status = DONE`인 버전만 |
| viewScope | string | | `view_scope` | `ALL` / `AGENT` / `ADMIN` |
| transferPolicy | string | | `transfer_policy` | `ALLOWED` / `MASKED` / `BLOCKED` |

```json
{ "isCurrent": true }
```

**처리**

- `isCurrent: true`: 한 트랜잭션에서 기존 현행 버전을 `false`로, 이 버전을 `true`로 바꾼다. 검색은 바로 새 버전을 쓴다. 최초 전환이면 `activated_at = now()`를 기록하고 이후 전환에서도 보존한다.
- 현행 버전을 끄기만 하는 요청(`false`)은 받지 않는다. 문서를 검색에서 빼려면 DC-05를 쓴다.
- 현행 버전의 `viewScope`·`transferPolicy`를 바꾸면 검색·답변에 바로 반영된다.
- `audit_logs`(`event_type = DOCUMENT_VERSION_ACTIVATE` / `DOCUMENT_POLICY_CHANGE`).

**Response** `200 OK` — `DocumentVersion`

**Errors**

| HTTP | code | 조건 | details |
|---|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아님 | |
| 404 | `DOCUMENT_NOT_FOUND` | 문서 없음 | |
| 404 | `DOCUMENT_VERSION_NOT_FOUND` | 버전 없음 | |
| 409 | `DOCUMENT_VERSION_NOT_READY` | 적재가 끝나지 않은(`PENDING`·`FAILED`) 버전을 현행으로 | `[{ "reason": "INGEST_STATUS", "message": "적재 상태", "value": "PENDING" }]` |
| 422 | `VALIDATION_ERROR` | `isCurrent: false`(`INVALID_VALUE`), enum 값 오류 | 필드별 |

### FAQ 게시·출처 정책

FAQ는 전 직원용이다. 등록·수정·게시 시 활성 문서의 적재 완료 현행 GUIDE이고 view_scope = ALL인 출처가 존재해야 한다. 출처는 현행 청크의 meta.faq_ids로 확인하며, 같은 FAQ 코드가 제한 문서에도 연결돼 있으면 게시를 거절한다. 조건 불충족은 `409 FAQ_SOURCE_NOT_PUBLIC`이다. 초안(isActive=false)은 출처 없이 저장할 수 있다.

출처 연결은 가이드 적재 단계에서 준비한 후 게시한다. 자동 FAQ 번호를 발급받아 연결을 준비하려면 먼저 비게시로 등록한다. 문서 비활성화·현행 전환·열람 정책 변경 시 관련 FAQ를 같은 트랜잭션에서 재검사하고 조건을 잃으면 자동 비게시·운영 기록을 남긴다. FAQ 본문이 공개 범위를 준수하는지는 게시 관리자가 확인한다.

구현 기준: 공개 출처는 활성 문서의 현행 버전이고 `doc_type = GUIDE`, `view_scope = ALL`인 청크다. 제한 문서는 활성 문서의 현행 버전 중 `view_scope`가 `ALL`이 아닌 것(문서 종류 무관)이다. 현행 버전은 적재 완료(`DONE`)만 될 수 있다.

FQ-01·02는 출처만 제거하지 않고 이 조건을 충족하지 않는 FAQ 자체를 숨긴다(상세 404). ADMIN 관리 조회에서는 비게시 FAQ도 볼 수 있다. 조건 확인은 페이지 개수 집계 전 수행한다. 정책 변경과 게시의 동시 실행은 문서 → FAQ 순으로 잠가 직렬화한다.


## 4. FAQ API (FQ)

### FQ-01 FAQ 목록

`GET /faqs` · 권한: 로그인 · 요구사항: FAQ-01

ADMIN이 아니면 게시 중(`is_active = true`)이며 위 게시·출처 정책을 충족하는 FAQ만 보인다. FAQ를 열람해도 문의는 만들어지지 않는다.

**Query**

| 파라미터 | 타입 | 필수 | 컬럼 | 설명 |
|---|---|---|---|---|
| page | number | | | 기본 1 |
| size | number | | | 기본 20, 최대 100 |
| sort | string | | | 기본 `faqCode,asc`. 가능: `faqCode`, `updatedAt` |
| categoryCode | string (반복) | | `category_code` | |
| q | string | | `question`, `keywords` | 질문 부분 일치, 키워드 부분 일치 |
| isActive | boolean | | `is_active` | **ADMIN만** |

**Response** `200 OK` — `Page<Faq>`

```json
{
  "items": [
    {
      "id": 1, "faqCode": "FAQ-001", "categoryCode": "ACC",
      "category": { "code": "ACC", "name": "계정·로그인" },
      "question": "비밀번호를 5회 틀려서 계정이 잠겼어요.",
      "answer": "10분 후 자동으로 잠금이 풀립니다. ...",
      "keywords": ["잠금", "비밀번호"],
      "isActive": true, "updatedBy": null,
      "createdAt": "2026-10-20T12:00:00+09:00", "updatedAt": null
    }
  ],
  "page": 1, "size": 20, "totalCount": 1, "totalPages": 1
}
```

**Errors**

| HTTP | code | 조건 |
|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아닌데 `isActive` 지정 |

### FQ-02 FAQ 상세

`GET /faqs/{faqId}` · 권한: 로그인 · 요구사항: FAQ-01

**Path**: `faqId` (number, `faqs.id`)

**Response** `200 OK` — `FaqDetail`

```json
{
  "id": 1, "faqCode": "FAQ-001", "categoryCode": "ACC",
  "category": { "code": "ACC", "name": "계정·로그인" },
  "question": "비밀번호를 5회 틀려서 계정이 잠겼어요.",
  "answer": "10분 후 자동으로 잠금이 풀립니다. ...",
  "keywords": ["잠금", "비밀번호"],
  "isActive": true, "updatedBy": null,
  "createdAt": "2026-10-20T12:00:00+09:00", "updatedAt": null,
  "sources": [
    { "documentId": 1, "docCode": "IT-ACC-001", "title": "계정·로그인 가이드", "version": "v1.0", "location": "FAQ Q1" }
  ]
}
```

화면에서 "해결되지 않았어요"를 누르면 FAQ 질문을 `content`로 IQ-01을 호출해 새 문의를 시작한다 (PRD 4.16).

**Errors**

| HTTP | code | 조건 |
|---|---|---|
| 404 | `FAQ_NOT_FOUND` | FAQ 없음, 또는 ADMIN이 아닌데 비게시·공개 출처 조건 불충족 |

### FQ-03 FAQ 등록

`POST /faqs` · 권한: ADMIN · 요구사항: FAQ-02

**Request Body**

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| faqCode | string | | `faq_code` | `^FAQ-\d{3,}$`, 중복 불가. 없으면 서버가 다음 번호 발급 |
| categoryCode | string | Y | `category_code` | 있는 분류 |
| question | string | Y | `question` | 1~500자 |
| answer | string | Y | `answer` | 1~4000자 |
| keywords | string[] | | `keywords` | 각 1~30자, 최대 20개. 기본 `[]` |
| isActive | boolean | | `is_active` | 기본 `true` |

```json
{
  "categoryCode": "NET",
  "question": "VPN 접속 시 '인증 서버에 연결할 수 없습니다'가 나와요.",
  "answer": "VPN 클라이언트를 최신 버전으로 다시 설치해 주세요. ...",
  "keywords": ["VPN", "인증 서버"]
}
```

**처리**: `updated_by` = 요청자. `faqCode`가 없으면 기존 `FAQ-숫자` 가운데 가장 큰 번호 + 1을 세 자리 이상으로 발급한다 (예: `FAQ-041`).

**Response** `201 Created` — `Faq`

게시 출처 조건 위반은 `409 FAQ_SOURCE_NOT_PUBLIC`이다.

**Errors**

| HTTP | code | 조건 | details |
|---|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아님 | |
| 409 | `FAQ_CODE_DUPLICATE` | `faqCode` 중복 | `faqCode` / `DUPLICATE` |
| 422 | `VALIDATION_ERROR` | 필드 누락·길이 초과, 없는 `categoryCode`(`NOT_FOUND`) | 필드별 |

---

### FQ-04 FAQ 수정

`PATCH /faqs/{faqId}` · 권한: ADMIN · 요구사항: FAQ-02

보낸 필드만 바꾼다. 게시 중단은 `isActive: false`.

**Request Body**: FQ-03의 `categoryCode`, `question`, `answer`, `keywords`, `isActive` (모두 선택). `faqCode`는 바꿀 수 없다 (`NOT_ALLOWED`).

**처리**: `updated_by` = 요청자, `updated_at = now()`. 수정 뒤에도 게시 중(`isActive = true`)이면 게시 조건을 다시 확인한다. 게시 중단(`isActive: false`)은 조건과 관계없이 허용한다.

**Response** `200 OK` — `Faq`

게시 출처 조건 위반은 `409 FAQ_SOURCE_NOT_PUBLIC`이다.

**Errors**

| HTTP | code | 조건 |
|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아님 |
| 404 | `FAQ_NOT_FOUND` | FAQ 없음 |
| 422 | `VALIDATION_ERROR` | 길이 초과, `faqCode` 포함(`NOT_ALLOWED`) |

---

### FQ-05 FAQ 삭제

`DELETE /faqs/{faqId}` · 권한: ADMIN · 요구사항: FAQ-02

FAQ 행을 지운다 (다른 테이블이 참조하지 않음). 잠시 내리기만 하려면 FQ-04 `isActive: false`를 쓴다.

**처리**: `audit_logs`(`event_type = FAQ_DELETE`, `target_type = faq`).

**Response** `204 No Content`

**Errors**

| HTTP | code | 조건 |
|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아님 |
| 404 | `FAQ_NOT_FOUND` | FAQ 없음 |
