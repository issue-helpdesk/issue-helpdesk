## 0. 읽는 법

- 경로는 Base URL `/api/v1` 이후 부분이다.
- 표의 **컬럼**은 테이블 설계서의 컬럼이다. `(파생)`은 테이블 컬럼이 아닌 계산값이다.
- **공통 에러는 API별 표에서 생략한다**: `401 UNAUTHORIZED`, `401 TOKEN_EXPIRED`, `403 AUTH_ACCOUNT_INACTIVE`, `403 AUTH_PASSWORD_CHANGE_REQUIRED`, `422 VALIDATION_ERROR`, `429 TOO_MANY_REQUESTS`, `500 INTERNAL_ERROR`
- 참조 객체 `CategoryRef`·`GroupRef`·`UserRef`는 [02. 문의·상담](02.문의_상담.md) 2.1을 따른다.

## 1. 열람 범위

문서는 **현행 버전**(`document_versions.is_current = true`)의 `view_scope`로 열람 여부를 정한다.

| service_role | 볼 수 있는 view_scope |
|---|---|
| `EMPLOYEE` | `ALL` |
| `AGENT` | `ALL`, `AGENT` |
| `ADMIN` | `ALL`, `AGENT`, `ADMIN` |

- 열람 범위 밖 문서는 목록에서 빼고, 상세는 `404 DOCUMENT_NOT_FOUND`로 응답한다. 제목·문서 번호도 드러내지 않는다 (SRS GUIDE-06).
- ADMIN이 아닌 사용자에게는 **현행 버전이 있고 `is_active = true`인 문서만** 보인다.
- 열람 범위와 전송 정책 값이 없거나 불명확하면 `ADMIN`·`BLOCKED`로 본다 (SRS GUIDE-07).

### 1.1 버전 상태 `versionState` (파생)

SRS GUIDE-05의 현행·만료·초안을 컬럼으로 계산한다.

| versionState | 화면 | 조건 |
|---|---|---|
| `CURRENT` | 현행 | `is_current = true` |
| `DRAFT` | 초안 | 현행이 아니고 `activated_at is null` (한 번도 현행으로 사용하지 않음) |
| `EXPIRED` | 만료 | 현행이 아니고 `activated_at is not null` (과거 현행) |

### DC-02 문서 등록

`POST /documents` · 권한: ADMIN · 요구사항: GUIDE-01

`PATCH /documents/{documentId}` · 권한: ADMIN · 요구사항: GUIDE-01

### DC-07 새 버전 업로드

`POST /documents/{documentId}/versions` · 권한: ADMIN · 요구사항: GUIDE-01·05·07

`Content-Type: multipart/form-data`. 폼 필드 이름도 camelCase이다.

**Form Data**

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| file | file | Y | (`file_path`, `file_format`) | `.pdf` `.docx` `.pptx` `.md` `.txt`. 최대 20MB |
| version | string | Y | `version` | 1~20자. 같은 문서 안에서 중복 불가. 예: `v1.3` |
| viewScope | string | | `view_scope` | 기본 `ADMIN` |
| transferPolicy | string | | `transfer_policy` | 기본 `BLOCKED` |

```
POST /api/v1/documents/3/versions
Content-Type: multipart/form-data; boundary=----X

------X
Content-Disposition: form-data; name="file"; filename="IT-NET-001_v1.3.pdf"
Content-Type: application/pdf
(binary)
------X
Content-Disposition: form-data; name="version"

v1.3
------X
Content-Disposition: form-data; name="viewScope"

ALL
------X
Content-Disposition: form-data; name="transferPolicy"

ALLOWED
------X--
```

**처리**: 파일 저장(`storage/documents/{documentId}/`, 파일 이름은 서버가 새로 만듦) → `document_versions`(`is_current = false`, `ingest_status = PENDING`, `registered_by` = 요청자) 생성 → 적재(파싱·청킹·임베딩)를 서버 안 백그라운드로 시작. 적재는 한 번에 한 건씩 하고, DB 연결 실패나 서버 중단으로 10분 넘게 `PENDING`으로 남으면 서버 시작 때와 그 뒤 5분마다 이어서 한다. 크기 제한을 넘으면 본문을 끝까지 받지 않고 멈춘다. 이 경우 브라우저가 응답을 읽지 못해 네트워크 오류로 보일 수 있으므로 화면에서 먼저 파일 크기를 검사한다. 끝나면 `DONE`, 실패하면 `FAILED`·`ingest_error`. **현행 전환은 자동으로 하지 않는다** (DC-09).

**Response** `202 Accepted` — `DocumentVersion` (`ingestStatus = PENDING`). DC-08로 적재 상태를 확인한다.

**Errors**

| HTTP | code | 조건 | details |
|---|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아님 | |
| 404 | `DOCUMENT_NOT_FOUND` | 문서 없음 | |
| 409 | `DOCUMENT_VERSION_DUPLICATE` | 같은 `version`이 있음 | `version` / `DUPLICATE` |
| 409 | `DOCUMENT_FILE_DUPLICATE` | 내용이 같은 파일이 이미 있음 (모든 문서·상태 대상). 다시 파싱·임베딩하지 않으려고 막는다 | `file` / `DUPLICATE`, `value`에 `documentId`·`docCode`·`versionId`·`version`·`ingestStatus` |
| 413 | `DOCUMENT_FILE_TOO_LARGE` | 파일 크기 초과 | `[{ "field": "file", "reason": "OUT_OF_RANGE", "message": "최대 크기", "value": "20MB" }]` |
| 415 | `DOCUMENT_FILE_FORMAT_UNSUPPORTED` | 지원하지 않는 확장자, 내용이 확장자와 다름, 빈 파일, 손상, 암호 (저장 전에 검사) | `file` / `INVALID_VALUE`, `message`에 사유 |
| 422 | `VALIDATION_ERROR` | `file`·`version` 없음, enum 값 오류 | 필드별 |

### DC-10 적재 다시 시도

`POST /documents/{documentId}/versions/{versionId}/retry` · 권한: ADMIN · 요구사항: GUIDE-05

적재에 실패한(`FAILED`) 버전을 다시 적재한다. 버전 번호를 새로 쓰지 않아도 된다.

**Form Data** (없어도 된다)

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| file | file | | (`file_path`, `file_format`, `file_sha256`) | DC-07과 같다. 보내면 파일을 교체하고, 없으면 같은 파일로 다시 시도한다 |

**처리**: `ingest_status = PENDING`, `ingest_error = null` → 백그라운드 적재. 교체된 이전 파일은 업로드로 저장한 파일일 때만 지운다. 보낸 파일이 이 버전의 파일과 같으면 교체하지 않는다. `audit_logs`(`event_type = DOCUMENT_VERSION_RETRY`).

**Response** `202 Accepted` — `DocumentVersion`

**Errors**

| HTTP | code | 조건 | details |
|---|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아님 | |
| 404 | `DOCUMENT_NOT_FOUND` | 문서 없음 | |
| 404 | `DOCUMENT_VERSION_NOT_FOUND` | 버전 없음 또는 다른 문서의 버전 | |
| 409 | `DOCUMENT_VERSION_NOT_RETRYABLE` | `FAILED`가 아님 | `[{ "reason": "INGEST_STATUS", "message": "적재 상태", "value": "DONE" }]` |
| 409 | `DOCUMENT_FILE_DUPLICATE` | 교체할 파일이 다른 버전과 같음 | DC-07과 같다 |
| 413·415 | | DC-07과 같다 | |

### DC-09 현행 전환·정책 변경

`PATCH /documents/{documentId}/versions/{versionId}` · 권한: ADMIN · 요구사항: GUIDE-05·07

보낸 필드만 바꾼다.

**Request Body**

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| isCurrent | boolean | | `is_current` | `true`만. `ingest_status = DONE`인 버전만 |
| viewScope | string | | `view_scope` | `ALL` / `AGENT` / `ADMIN` |
| transferPolicy | string | | `transfer_policy` | `ALLOWED` / `MASKED` / `BLOCKED` |
| reason | string | 조건부 | `audit_logs.reason` | 최대 500자. 외부 전송을 넓힐 때(`BLOCKED` → `MASKED`·`ALLOWED`, `MASKED` → `ALLOWED`) 필수 |

```json
{ "isCurrent": true }
```

**처리**

- `isCurrent: true`: 한 트랜잭션에서 기존 현행 버전을 `false`로, 이 버전을 `true`로 바꾼다. 검색은 바로 새 버전을 쓴다. 최초 전환이면 `activated_at = now()`를 기록하고 이후 전환에서도 보존한다.
- 현행 버전을 끄기만 하는 요청(`false`)은 받지 않는다. 문서를 검색에서 빼려면 DC-04 `isActive: false`를 쓴다.
- 현행 버전의 `viewScope`·`transferPolicy`를 바꾸면 검색·답변에 바로 반영된다.
- **해결 사례 묶음 검사**: 이 버전에 등록한 해결 사례 묶음(`guide_clusters.registered_version_id`)이 있으면 전환 전에 본다. 거절한 묶음이 하나라도 있으면 막고, 검토 중인 묶음의 기준 버전(`base_version_id`)이 지금 현행과 다르면 막는다 (그사이 현행에 들어간 수정이 사라지지 않게). 이미 반영된 묶음의 버전으로 되돌리는 것과 기준 버전이 없는 새 가이드 묶음은 막지 않는다. 막히면 정책 변경도 하지 않는다. 전환하면 같은 트랜잭션에서 검토 중인 묶음과 소속 티켓(`ticket_guide_states`)을 `APPLIED`로 바꾼다. 묶음이 없는 일반 업로드 버전은 이전과 같다. 명령줄 적재(`app.rag.ingest`)의 현행 전환은 시드·검수용이라 이 검사를 하지 않는다.
- `audit_logs`(`event_type = DOCUMENT_VERSION_ACTIVATE` / `DOCUMENT_POLICY_CHANGE`). 정책 변경은 보낸 사유를 `reason`에 남긴다. 값이 그대로면 기록하지 않는다. 조건을 잃어 비게시한 FAQ는 `FAQ_AUTO_UNPUBLISH`.

**Response** `200 OK` — `DocumentVersion`

**Errors**

| HTTP | code | 조건 | details |
|---|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아님 | |
| 404 | `DOCUMENT_NOT_FOUND` | 문서 없음 | |
| 404 | `DOCUMENT_VERSION_NOT_FOUND` | 버전 없음 | |
| 409 | `DOCUMENT_VERSION_NOT_READY` | 적재가 끝나지 않은(`PENDING`·`FAILED`) 버전을 현행으로 | `[{ "reason": "INGEST_STATUS", "message": "적재 상태", "value": "PENDING" }]` |
| 409 | `DOCUMENT_VERSION_HAS_REJECTED_CLUSTER` | 거절한 해결 사례 묶음이 들어 있는 버전을 현행으로. 거절한 항목을 빼고 다시 등록해야 한다 | `[{ "reason": "REJECTED_CLUSTER", "message": "거절한 묶음", "value": [12] }]` (묶음 id) |
| 409 | `DOCUMENT_VERSION_BASE_CHANGED` | 검토 중인 묶음을 만든 뒤 현행 버전이 바뀜. 바뀐 현행과 비교해 다시 등록해야 한다 | `[{ "reason": "BASE_VERSION_CHANGED", "message": "기준 버전이 현행과 다른 묶음", "value": [12] }]` (묶음 id) |

### DC-11 가이드 그림

`GET /guide-images/{category}/{fileName}` · 권한: 로그인 · 요구사항: FAQ-01, GUIDE-06

출처 응답의 `images[].key`로 그림 파일을 받는다 (예: `/guide-images/SW/sw001_portal_home.png`). 토큰을 헤더로 보내야 하므로 `<img src>`에 주소를 바로 넣을 수 없고, `fetch`로 받아 blob URL로 보여 준다.

**처리**: 이름표 형식(`^[A-Z]+/[A-Za-z0-9][A-Za-z0-9._-]*\.(png|jpe?g)$`)을 확인하고, 이 그림을 `meta.images`에 가진 청크 가운데 활성 문서의 적재 완료 버전이 요청자 열람 범위 안에 하나라도 있어야 한다. 현행이 아닌 버전도 인정한다 (이전 버전을 근거로 한 대화의 출처가 있다). 정리본 MD로 적재한 문서만 그림이 있고, DOCX·PDF·PPTX로 올린 문서는 `images`가 비어 있어 설명만 보인다.

**Response** `200 OK` — 그림 파일 (`image/png` 또는 `image/jpeg`). `Cache-Control: private, max-age=3600`

**Errors**

| HTTP | code | 조건 |
|---|---|---|
| 401 | 인증 오류 | 로그인 안 함 |
| 404 | `GUIDE_IMAGE_NOT_FOUND` | 형식이 틀림, 파일 없음, 쓰는 청크 없음, 열람 범위 밖 (이유를 구분하지 않는다) |

### DC-12 현행 버전 본문

`GET /documents/{documentId}/content` · 권한: 로그인 · 요구사항: GUIDE-06

가이드 열람 화면과 가이드 관리의 "보기"가 문서 전체를 읽는다. 열람 범위는 DC-03과 같다. ADMIN이 아니면 활성 문서이고 현행 버전이 요청자 열람 범위 안이어야 하며, 아니면 존재를 드러내지 않도록 `404 DOCUMENT_NOT_FOUND`이다. ADMIN은 비활성 문서도 볼 수 있다.

**처리**: 버전의 업로드 파일(`document_versions.file_path`)을 요청마다 읽는다. 변환한 본문은 저장하지 않는다.

- MD 파일은 그대로 쓰고, DOCX·PPTX·PDF·TXT는 적재와 같은 파서로 읽어 가이드 md로 바꾼다. 그림 이름표 확인도 적재와 같다(`to_checked_md`).
- 화면용으로 머리말(front matter)을 떼고, 그림 줄 `![설명](…)`은 출처 본문과 같은 `[그림] 설명` 줄로 바꾼다. 표 밖의 `<br>`은 줄바꿈으로 되돌리고, 표 칸 안의 `<br>`은 표가 깨지지 않도록 그대로 둔다. 코드 블록 안은 바꾸지 않는다.
- `images`는 그 버전 청크의 `meta.images`다. `[그림] 설명` 줄을 `caption`이 같은 그림과 짝지어 DC-11로 받는다. 적재 전·적재 실패 버전과 이름표 없는 그림은 `images`에 없어 설명만 보인다.

**Response** `200 OK` — `DocumentContent`

| 필드 | 타입 | 설명 |
|---|---|---|
| documentId | number | |
| versionId | number | 본문을 읽은 버전 |
| version | string | 예: `v2.0` |
| content | string | 화면용 md |
| images | GuideImage[] | 없으면 `[]` |

```json
{
  "documentId": 12,
  "versionId": 31,
  "version": "v2.0",
  "content": "# 업무용 SW 실행·오류 대응 가이드\n\n…\n\n[그림] 그림 3.1-1. Office 복구 방법 선택\n…",
  "images": [{ "key": "SW/IT-SW-003_3.1-1.png", "caption": "그림 3.1-1. Office 복구 방법 선택" }]
}
```

**Errors**

| HTTP | code | 조건 |
|---|---|---|
| 404 | `DOCUMENT_NOT_FOUND` | 문서 없음, 또는 ADMIN이 아닌데 비활성·현행 없음·열람 범위 밖 |
| 404 | `DOCUMENT_VERSION_NOT_FOUND` | ADMIN이 현행 버전 없는 문서를 요청 |
| 409 | `DOCUMENT_CONTENT_UNAVAILABLE` | 파일 위치가 없거나, 파일이 서버에 없거나, 읽지 못함. 파일을 다시 올려야 한다(DC-10) |

### FAQ 게시·출처 정책

FAQ는 전 직원용이다. 등록·수정·게시 시 활성 문서의 적재 완료 현행 GUIDE이고 view_scope = ALL인 출처가 존재해야 한다. 출처는 현행 청크의 meta.faq_ids와 직접 지정한 문서(`sourceDocumentIds`)로 확인하며, 같은 FAQ 코드가 제한 문서에도 연결돼 있으면 게시를 거절한다. 조건 불충족은 `409 FAQ_SOURCE_NOT_PUBLIC`이다. 초안(isActive=false)은 출처 없이 저장할 수 있다.

출처는 FQ-03·04에서 문서를 직접 지정하거나, 가이드 적재 단계에서 청크에 FAQ 번호를 넣어 연결한다. 문서 비활성화·현행 전환·열람 정책 변경 시 그 문서의 청크와 연결되거나 그 문서를 직접 지정한 FAQ를 같은 트랜잭션에서 재검사하고 조건을 잃으면 자동 비게시·운영 기록을 남긴다. 조건을 되찾아도 자동으로 다시 게시하지 않는다. FAQ 본문이 공개 범위를 준수하는지는 게시 관리자가 확인한다.

구현 기준: 공개 출처는 활성 문서의 현행 버전이고 `doc_type = GUIDE`, `view_scope = ALL`인 청크다. 제한 문서는 활성 문서의 현행 버전 중 `view_scope`가 `ALL`이 아닌 것(문서 종류 무관)이다. 현행 버전은 적재 완료(`DONE`)만 될 수 있다.

FQ-01·02는 출처만 제거하지 않고 이 조건을 충족하지 않는 FAQ 자체를 숨긴다(상세 404). ADMIN 관리 조회에서는 비게시 FAQ도 볼 수 있다. 조건 확인은 페이지 개수 집계 전 수행한다. 정책 변경과 게시의 동시 실행은 문서 → FAQ 순으로 잠가 직렬화한다.

### FQ-04 FAQ 수정

`PATCH /faqs/{faqId}` · 권한: ADMIN · 요구사항: FAQ-02

보낸 필드만 바꾼다. 게시 중단은 `isActive: false`.

**Request Body**: FQ-03의 `categoryCode`, `question`, `answer`, `keywords`, `isActive`, `sourceDocumentIds` (모두 선택). `faqCode`는 바꿀 수 없다 (`NOT_ALLOWED`). `sourceDocumentIds`는 보내면 그 목록으로 통째로 바꾸고(`[]`면 모두 해제), 안 보내면 그대로 둔다.

**처리**: `updated_by` = 요청자, `updated_at = now()`. 수정 뒤에도 게시 중(`isActive = true`)이면 게시 조건을 다시 확인한다. 게시 중단(`isActive: false`)은 조건과 관계없이 허용한다. 게시 중인 FAQ의 마지막 공개 출처를 빼면 `FAQ_SOURCE_NOT_PUBLIC`으로 거절하고 연결도 바꾸지 않는다.

**Response** `200 OK` — `Faq`

게시 출처 조건 위반은 `409 FAQ_SOURCE_NOT_PUBLIC`이다.

**Errors**

| HTTP | code | 조건 |
|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아님 |
| 404 | `FAQ_NOT_FOUND` | FAQ 없음 |
| 422 | `VALIDATION_ERROR` | 길이 초과, `faqCode` 포함(`NOT_ALLOWED`), 연결할 수 없는 문서(`sourceDocumentIds` / `NOT_PUBLIC_GUIDE`) |

## 4A. 해결 사례 가이드화 (GC)

주간 분석이 해결(CLS) 티켓을 묶어 만든 가이드 초안을 관리자가 검토한다 (기획 `기획_해결사례_가이드화`, SRS GUIDE-03·08). 묶음은 API로 만들지 않고 주간 분석이 만든다. 저장 구조는 [06 테이블 설계서](../06.테이블_설계서.md) H장 `guide_clusters`·`ticket_guide_states`.

- 권한은 모두 ADMIN이다. 다른 사람이 부르면 `403 FORBIDDEN`.
- 초안 등록과 넣을 문서 변경 API는 이어서 추가한다. 현행 전환은 DC-09를 쓰며, 거절한 묶음·기준 버전 검사와 `APPLIED` 연결은 DC-09가 한다.
- 상태를 바꾸면 소속 티켓(`ticket_guide_states.status`)도 같은 트랜잭션에서 같은 값으로 바꾼다. 거절·반영 표시는 `audit_logs`(`target_type = guide_cluster`)에 남긴다.

| judgment | 화면 | 초안 |
|---|---|---|
| `ADD_ITEM` | 항목 추가 | 기존 가이드의 다음 버전 초안 (3장 끝에 새 항목) |
| `CHANGE` | 변경 | 수정 위치와 제안문 (`reviewInfo`) |
| `NEW_GUIDE` | 새 가이드 | 뼈대 초안. 문서 등록(DC-02) 전까지 `targetDocument`가 없다 |
| `MANUAL_CANDIDATE` | 매뉴얼 후보 | 없음 (`draftMd = null`). 관리자가 매뉴얼에 직접 반영한 뒤 반영 표시 |
| `SEC_MANUAL` | SEC 직접 검토 | AI 없이 티켓 글을 옮긴 초안. SEC 티켓 1건당 1묶음 |

| status | 화면 | 뜻 |

### GC-05 초안 수정 저장

`PATCH /guide-clusters/{clusterId}` · 권한: ADMIN · 요구사항: GUIDE-03

**Request Body**

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| draftMd | string | Y | `draft_md` | 고친 초안 전체. 1~1,000,000자 |
| draftRevision | number | Y | `draft_revision` | GC-02에서 받은 값 (0 이상) |


**처리**: 검토 중이고 **등록하지 않은** 묶음만 저장한다. 등록한 뒤 고치면 등록한 파일과 초안이 달라지기 때문이다. 보낸 `draftRevision`이 지금 값과 같을 때만 저장하고 1 올린다. 다르면 다른 관리자가 먼저 고친 것이므로 저장하지 않는다. 화면은 GC-02로 최신 초안을 다시 불러와 고친다. 넣을 문서 변경(`targetDocument`)은 초안을 다시 만들어야 해서 이 API로 받지 않는다. 상태 변경이 아니라 운영 기록은 남기지 않는다.

**Response** `200 OK` — GC-02와 같은 상세 (`draftRevision`이 1 오름)

**Errors**

| HTTP | code | 조건 | details |
|---|---|---|---|
| 403 | `FORBIDDEN` | ADMIN이 아님 | |

### GC-03 묶음 거절

`POST /guide-clusters/{clusterId}/reject` · 권한: ADMIN · 요구사항: GUIDE-03

**Request Body**

| 필드 | 타입 | 필수 | 컬럼 | 제약 |
|---|---|---|---|---|
| reason | string | Y | `reject_reason`, `audit_logs.reason` | 1~500자 (앞뒤 공백 제거) |


**처리**: 검토 중(`REVIEWING`)인 묶음만 거절한다. 등록한 뒤라도 현행 전환 전이면 거절할 수 있다. `status = REJECTED`, `reject_reason`, `reviewed_by`·`reviewed_at`을 저장하고 소속 티켓도 `REJECTED`로 바꾼다. 등록한 버전(`registeredVersion`)은 지우지 않으며, 그 버전의 현행 전환은 DC-09가 `DOCUMENT_VERSION_HAS_REJECTED_CLUSTER`로 막는다. 같은 버전에 다른 묶음이 함께 있으면 거절한 항목을 빼고 다시 등록한 뒤 전환한다. 거절한 티켓은 다시 분석하지 않고, 같은 주제의 새 티켓을 묶을 때 비교만 한다. `audit_logs`(`event_type = GUIDE_CLUSTER_REJECT`, `result = <판단> REVIEWING → REJECTED`, `reason` = 사유).
