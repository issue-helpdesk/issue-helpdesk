# 문서 정합성 점검 — FIN 재처리·가이드 업로드

2026-11-08 · 코드·명세 대조 결과 · 실행 코드·배포 변경 없음

## 확정 기준

- FIN은 담당자의 처리 완료이며, 문의자 미해결 선택은 기존 티켓 WIP 복귀다. 기존 문의·세션·접수번호·Jira 번호를 유지한다. 미응답은 FIN 유지, 해결 확인은 CLS다.
- TK-07 요청의 202는 Jira 반영 완료가 아니다. Jira WIP 확인 후 상태를 확정한다. 재완료에는 새 처리 결과가 필요하다.
- 현재 업로드 지원은 PDF·DOCX·PPTX·MD·TXT다. 원본 파일 보관, 원본 파싱 후 검색 청크·임베딩 저장, 본문 조회 시 마크다운 반환을 구분한다.

PRD·SRS·설계서·API·Jira 연동 문서·가이드화 README의 관련 설명을 검색·대조했다. 과거 변경 이력·검증 날짜·실제 시험 결과는 현재 기능 설명으로 바꾸지 않았다. 이번 주제 밖의 모든 요구사항을 전수 검증했다는 의미는 아니다.

## 구현 차이 — 문서만으로 해결하지 않은 항목

1. **finished_at:** API 03·테이블 명세와 `jira_webhook.sync_work_status`는 FIN→WIP 때 NULL이다. `jira_transition._save_confirmed`는 이전 시각을 유지하며 `test_reopen_runs_leaves_reason_comment_and_keeps_previous_result`도 이를 확인한다. 기존 계약과 실행기·테스트를 백엔드에서 맞춰야 한다. WIP 복귀 자체가 미구현이라는 뜻은 아니다. [06 확인 목록](../api/06.프론트_연동_요청.md)에 기록했다.
2. **Jira 직접 변경:** ITssue의 TK-07은 문의자 권한·reason·허용 전환을 검사하지만, Jira 동기화는 직접 바뀐 FIN→WIP를 받아들이며 FIN→RDY에도 같은 제한을 적용하지 않는다. Jira 직접 변경의 허용 범위·권한은 운영 정책 확인 대상이다. 현재 동작을 문서 정리 과정에서 임의로 바꾸지 않았다.
3. **마크다운 영구 저장:** `document_file.stage_file`·`DocumentService.upload_version`은 원본을 저장한다. `ingest.upload.prepare_version`은 원본을 파싱해 청크를 만들고, `read_guide_md`·`DocumentService.content_of`는 조회 시 마크다운을 만들어 저장 없이 반환한다. 원본과 변환 MD를 함께 영구 저장하려면 별도 변경이며, 이번 점검으로 추가하지 않았다. 가이드화 초안을 새 MD 버전으로 등록하는 경로와 일반 업로드 변환 캐시도 구분한다.

- 이력: `models/ticket.py` TicketStatusHistory, `services/jira_transition.py`·`jira_webhook.py`의 FIN 이력 저장, API TK-08. 과거 이력 또는 FIN 상태의 결과만 편집한 중간값은 본문이 없을 수 있다.

## 추가 교차 점검 — 상태·권한·구현 범위

- **문의 중복·동시 처리:** API 02의 결과 재사용·소유권 설명을 미구현 후속 계약으로 명시했다. API 설계서 2.6.1·테이블 설계서의 api_requests 미구현 설명 및 현재 헤더 검증 코드와 일치시켰다.
- **종료 문의 이어가기:** API 02의 CLOSED_UNRESOLVED→IN_PROGRESS 화살표를 현재 상태도에서 제거했다. 종료 문의는 현재 재개 불가이며, AI 미해결 연결 선택 단계의 이어가기와 구분했다. 종료 문의 재개 확대는 이번 점검에서 확정하지 않았다.
- **일정 권한(11.08 추가 정정):** 프론트 담당자가 현재 팀 일정 표시를 확인해 R-43 추가 요청을 제외했다. 로컬 API의 권한 설명과 실제 확인 환경·데이터 경로를 구분하며, 코드 일부만 보고 조회 확대가 필수라고 판단한 이전 의견은 철회한다. 화면·서버 권한 변경은 하지 않는다.
- **항목별 전송:** API 06의 검색 적용 미구현 설명을 PR #347과 search/service.py의 coalesce(content_transfer_policy, transfer_policy)에 맞춰 정정했다. 허용 목록·차단 제목 전송의 미연결과 구분했다.
- **변경하지 않은 사항:** Slack·댓글 알림·P1 전원 알림, 보안 관리 API, 주간 가이드 자동 생성·승인 등록, 이탈 자동 삭제는 상위 문서의 미구현/요구 구분을 확인했다. 예전 날짜의 변경 이력에 나오는 5시간 삭제·일간 가이드화는 현재 요구가 아닌 당시 기록으로 남겼다.

이는 주요 정책·구현 경계의 교차 점검이며 모든 문장·API 응답 예시·배포 설정의 전수 일치나 운영 검증 완료를 보장하지 않는다. 추가 제품 결정 없이 정정한 사항과 구현이 남은 요구를 구분했다.
