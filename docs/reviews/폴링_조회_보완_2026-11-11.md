# 폴링·새로고침 보완

기준: `develop 65fa271` 이후 `fix/polling-refresh-control`. 이 문서의 폴링 보완은 프론트 변경이다. 같은 PR에는 별도로 승인받은 백엔드 비밀번호 변경 안내 문구 수정도 포함한다. 환경 변수·실제 환경 파일은 변경하지 않았다.

## 적용 범위

| 대상 | 변경 |
| --- | --- |
| 담당자 통계 | 15초 티켓 변경 구독 제거. 기존 구역별 새로고침·조회 조건 변경·다른 메뉴에서 재진입할 때 조회 |
| 운영 기록 | 불필요한 티켓 변경 구독 제거. 마지막 조회 시각·새로고침 버튼 추가. 현재 구분·이벤트·기간·페이지를 유지해 다시 읽고, 조회 중에는 중복 클릭 방지 |
| 보안 알림 목록 | 브라우저 탭이 숨겨지면 정기 조회 중단, 복귀하면 즉시 조회. 현재 목록 조회가 끝나기 전에는 정기 요청을 겹치지 않음 |
| 보안 알림 건수 | 같은 관리자의 사이드바·대시보드가 타이머와 값을 공유. 로그인 안내·목록과 동시에 요청하는 건수도 같은 인증 토큰의 진행 중 요청을 공유 |
| 안 읽은 알림 | 알림 종·사이드바 등의 구독자가 한 조회·타이머를 공유. 값이 같으면 화면 통지 생략, 읽음 처리 후에는 즉시 재조회 |

운영 기록의 기존 15초 구독은 목록 API의 Effect 조건에 포함되지 않아, 목록을 15초마다 재조회하지는 않았다. 이번에는 불필요한 구독과 상세 패널에 전달하던 틱을 없애고, 사용자가 직접 다시 읽을 수 있게 했다.

## 조회 중첩과 갱신 규칙

- 정기 조회가 왔는데 이전 요청이 진행 중이면 건너뛴다. 밀린 정기 요청을 쌓지 않는다.
- 조회 도중 탭 복귀·읽음 처리·보안 상태 변경이 생기면, 진행 중 요청이 끝난 뒤 한 번 더 읽는다. 여러 번 요청해도 후속 조회는 한 번으로 합친다.
- 일시 실패 시 조회 중 표시를 해제하고 다음 주기·복귀에서 다시 시도한다. 공유 건수는 마지막 성공 값을 유지한다.
- 마지막 구독자가 사라지면 타이머·저장된 값을 버린다. 이전 접속에서 늦게 도착한 응답은 새 구독에 전달하지 않는다.
- 화면 이동으로 구독자만 바뀌고 주기가 같으면 타이머를 다시 시작하지 않는다. 반복 이동으로 다음 조회가 계속 미뤄지는 것을 막는다.

공통 공유 조회는 `core/sharedPoll.ts`에서 처리한다. 모든 API에 캐시를 붙이거나 모든 티켓 조회를 통합한 변경은 아니다. 보안 목록 자체의 조회와 건수의 완료된 결과를 영구 공유하지도 않는다. 목록과 배지가 서로 다른 시점에 조회하면 별도 요청이 필요하다.

## 유지한 동작

새 답변 점·배정 및 처리 완료 알림·가이드 검색 준비 추적은 자동으로 동작한다. 보안 로그인 모달은 기존대로 관리자 로그인 때 신규 건이 있으면 한 번 표시하며, 접속 중 새 건마다 모달을 띄우는 기능을 추가하지 않았다.

티켓 목록·대화·가이드 검색 준비의 조회 간격과 API 계약은 변경하지 않았다. 다른 화면의 폴링 통합은 이번 범위가 아니다.
