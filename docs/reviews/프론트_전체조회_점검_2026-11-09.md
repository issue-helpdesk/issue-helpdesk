# 프론트 전체 조회 점검

기준: PR #397 작업 브랜치. 기존 API의 페이지 조회와 상태별 집계를 사용하며 백엔드 변경 요청은 추가하지 않는다.

| 역할 | 보완한 부분 |
| --- | --- |
| 문의자·공통 | 미확인 알림 전체 페이지를 읽어 최근 문의의 새 답변 표시 누락 방지. FAQ 목록의 500건 상한 제거 |
| 담당자 | 개인 대시보드의 상태별 건수·우선 처리·검색, 통계의 추이·긴급도 분포에 전체 페이지 반영. 사이드바 처리할 문의 건수는 서버 statusCounts 사용 |
| 관리자 | 대시보드의 연동·배정 확인 및 긴급도별 미해결 집계, 운영 현황 목록·배지에 전체 페이지 반영. 가이드·AI 제안의 임의 페이지 상한 제거 |
| 일정·팀 현황 | 캘린더의 500건 상한 제거. 팀 현황의 휴가 종류 조회도 전체 페이지 반영. 티켓 업무량 전체 조회는 PR #397 기존 변경에 포함 |

일반 목록(문의 내역·처리할 문의·전체 문의·계정·감사 로그)은 기존 페이지 이동을 유지한다. 최근 문의 5건과 대시보드 검색 10건은 의도한 미리보기이므로 유지한다. 관리자 통계와 담당자 상태별 현황은 기존 서버 집계를 유지한다.

전체 티켓 조회 중 한 페이지라도 실패하면 부분 집계를 정상 결과로 반환하지 않는다. 페이지 경계에서 같은 티켓이 다시 오면 ID로 중복을 제거한다. 조회 도중 데이터가 바뀌면 서버의 페이지 방식 특성상 누락 가능성까지 완전히 없애지는 못한다.

배포 확인: 역할별 건수와 해당 목록 비교, 100건 초과 조건에서 목록·우선 처리·통계 확인, 문의 새 답변 표시 확인. 데이터가 많을수록 전체 목록을 사용하는 화면의 요청 수가 늘 수 있으므로 응답시간도 함께 확인한다. 이번 변경은 화면 배치·색상·모드별 스타일을 변경하지 않는다.
